# 注释答案泄漏剥离（保行数）

把训练集 `user` 消息代码块里的**答案性注释**去掉，产出新版本数据集。核心约束是 **保行数**：
一行不删、代码字节不改——否则代码行号整体漂移，会引爆叙事里的全部行号引用（实测 1102 行）。

参考实现：`experiments/exp_06_finetune/audit/build_v2_20_candidate_20260914.py`
（v2_19 10069 行 → v2_20 10000 行；注释区答案词 2026→1、注释区行号锚点 3737→0）

---

## 0. 先决条件

- 用户**明确拍板**"新出 vN+1 / 覆盖"与"保行数 / 删行"。未拍板只出脚本，不写盘。
- 先产出逐行清单（`p0_2_answer_annotations.jsonl` 之类），别直接改。
- **删除类动作（去重、删样本）必须排在最后**，且用 user 内容指纹定位，不能用行号。

## 1. 六道安全门（任一不过即 abort，禁止写盘）

| 门 | 断言 |
|---|---|
| G1 | 每行**代码块行数**前后完全一致（保行数） |
| G2 | 每行**代码骨架**（剥掉全部注释后的文本）逐字节一致 → 只允许动注释 |
| G3 | JSON 全部可解析 + 7 键齐全（`has_vulnerability, vulnerability_type, risk_level, source, sink, explanation, fix_suggestion`） |
| G4 | 角色结构 system→user→assistant |
| G5a | **注释区内** `CWE-\d+` 残留 = 0 |
| G6 | 输出无重复 user 文本 |

**G2 是整套方法的支点**：只改注释 ⇒ 骨架必然不变；骨架变了说明注释识别错了（例如把 `#include` 当注释）。
G5b（标识符/字符串里的 `CWE-N`，如 docstring）**不要**强行归零——改字符串字面量需要放宽 G2，列人工队列。

## 2. 架构：触发口径窄、清理词表宽

```
触发(是否动这条注释) = ANN_TRIGGER      # 6 类答案性注释 + 行号锚点，与体检口径一致
清理(动到什么程度)   = LEAK_SEG + 行号锚点 + 针对但/却/然而 的转折段
```
**别混用**：用宽词表当触发条件，实测误改范围从 1788 处膨胀到 7595 行（4 倍）。

`ANN_TRIGGER` 六类：`CWE编号 / 防御迷惑 / 看似·表面上·假装 / 漏洞点·漏洞行 / 方向泄漏(存在漏洞·无漏洞·安全样本) / Vulnerable·insecure·unsafe`

## 3. 注释单元识别（引号感知）

- 逐字符扫描，跟踪 `"` `'` `` ` `` 状态；**只有引号外的标记才算注释**（否则 `'*/.git/*'`、`"*/15 * * * *"` 会被误判）。
- 行注释标记只认 `//` `#` `;`：
  **`#` 要排除 C 预处理器**（`include/define/ifdef/ifndef/endif/pragma/error/warning/undef/region`）——
  但**不要把 `line` 放进白名单**（实测 `# line 29: ...` 被当成 `#line` 整条漏掉）。
- 跨行 `/* */`、`<!-- -->`：整块当一个单元，并标记 `safe`；**`safe=False` 一律 skip 不动**。
  `safe` 条件 = 结束行的 `*/` 之后无残留代码 **且** 中间行全是纯注释行（以 `*` 或结束标记开头）。
  实测总有 2 处不满足（`/*` 被当模板分隔符包住 HTML / 块内夹代码），skip 是正确行为。
- 多行块开启符**必须按 marker 选 `/*` 还是 `<!--`**，硬编码 `/*` 会把 HTML 注释写成 `/* ... -->`。

## 4. 中性化规则（零捏造）

1. 剥 `/* */` `<!-- -->` 标记、`//` `#` 行首标记、块注释续行前缀 `*`。
2. **含泄漏内容的括号短语整段删**（连括号）；不含泄漏的括号保留——护住 `fmt.Sprintf()` / `Math.random()`。
3. 删行号锚点：`(?<![A-Za-z0-9_#/])(?:line|行|L)\s*\d{1,4}(?![0-9A-Za-z_])|第\s*\d{1,4}\s*行`
   ——`#` 和 `/` 的负向断言是**必须的**，否则 GitHub permalink `...web.py#L1455` 会被删掉。
4. 按分隔符切段，**丢掉命中泄漏词表的段**；**保留段逐字原样**（不要重排标点！
   `SEP` 里含 `.` `-` 会把 `fmt.Sprintf`、`html-escape` 打碎；只按 `：: ；; ，, 。、 【】「」[]` 与**两侧带空格的 ` - `** 切）。
5. 丢掉以转折词开头的段：`但|却|然而|不过|其实|只是`（"但这是不可靠的" 这类反述，是泄漏高发形态）。
6. **收尾回扫闸（关键）**：中性化后若 `kept` 仍命中 ANN_TRIGGER 或行号锚点 → **整条注释清空**。
   这一闸兜住"被分隔符切碎后逃过词表"的情形（`CWE-476` 被 `-` 切成 `CWE`+`476`）。
7. 括号配对清理：丢弃不成对的 `(` `)`，避免 `insecure URLs (…, no https)` 裁出悬空 `)`。
8. 保底：清洗后有效字符 < 4 → 清空；纯行号 → 清空。

**写回**：行注释 → `pre + (f"{marker} {kept}" if kept else "")`；
跨行块 → `pre + (f"{opener} {kept} {close}" if kept else "")`，并把中间行清空（**行数不变**）。

## 5. 行号锚点：清除，不要重编号

`// line N` 这类自指注释是蒸馏产物，真实代码没有。**清除**（同一行留空/留中性文字）比
"重编号为块内真实行号"更安全：重编号等于替一个本来就不该存在的注释背书，还会和叙事里的错号打架。
清除一次性消掉三套行号基准中的一套，且行数不变。

## 6. 落地后必须独立复核（不要信构建器的自检）

另写一个脚本、用**不同的**统计口径，对比新旧两版：

| 指标 | 期望 |
|---|---|
| 注释区答案词（关键词表全量匹配） | 降到 ~0 |
| 注释区行号锚点 | **0** |
| 保行数违例行 | **0** |
| JSON 契约异常行 | **0** |
| 重复 user | **0** |

⚠️ 独立复核的注释模型更弱时会出现"骨架差异 N 行"的假警报（跨行块被展平）。**先确认这些行都是含跨行块注释的行**，再判定为口径差异。

## 7. 交付物

新数据集 + `changelog.jsonl`（每条含 `kind/row/line/before/after`）+ 构建报告 md
（动作计数 / 6 门结果 / 改写抽检样例 / 方法取舍 / **本轮踩过的 bug 与根因** / 未处理项）。
未处理项要写全：SKIP_UNSAFE 的具体行、需放宽 G2 的字符串字面量队列、含真·正确性建议的 fix 行。

## 8. 已知局限

- 「合成标记」类注释（`模拟/场景/业务逻辑/demo`）**不泄漏答案**，本 skill 不动；
  是否清洗应由"合成腔调对泛化的影响"探针先量化（W10）。
- 「迷惑防御陷阱」（`看似/表面上`）**不能一刀切剥离**——它是刻意设计的对抗样本。
  正确做法：剥掉"作者元标注"（`防御迷惑：` 这类标记词），保留陷阱本身，
  并在 system prompt 增补"代码注释不可作为判定依据"（配 W9 探针）。

## 9. 配套：判定「负样本是否在教反防御」的分诊配方

用于回答"有多少负样本用『承认可绕过 + 样本外假设』洗白"。**必须两遍走**，一遍必翻车：

| 阶段 | 词表 | 实测命中（v2_20，10000 行） |
|---|---|---|
| 第 1 遍（宽） | `ADMIT = 会被执行/可被绕过/可被利用/成立…` + `WASH = 样本外/沙箱/上游/通常…` | 1126 —— **严重高估** |
| 第 2 遍（紧） | `ADMIT` 剔除元讨论（`是否成立/不成立/不可达/并非漏洞`）；再要求**句内无「行号锚点 + 机制词」** | **192 承认攻击可实施 → 其中 161 有样本内阻断理由（合格）→ 29 真高危** |

再逐条精读这 29 条 → 实际确认错标 **5 条（163/192 ≈ 85% 是合格负样本）**。

**结论要用这条写**：一个"承认可绕过"的负样本，只要叙事给出了**同文件、带行号的机制理由**
（白名单精确匹配 / 参数化 / 枚举映射 / 列表参数 / 上界校验），它就是合格负样本；
`样本外/沙箱/上游` 这类词在合格样本里也普遍出现，不能当判据。

**不要做的**：不要按行数批量改判/删除。本轮 5 条改判全部来自逐条精读，自动化只负责把 1126 压到 29。

## 10. 判定纪律：**实跑优先，禁止心算**

本轮的真实教训——心算两次出错，实跑两次纠正：

| 症状 | 心算结论 | 实跑结论 |
|---|---|---|
| `'....//....//etc/passwd'.replace('../', '')` | "残留不含 `../`，不会遍历" | **`'../../etc/passwd'`** —— 残留的 `.` 与 `/` 会重新拼出 `../` |
| `base_dir + '/../../etc/passwd'` 的 `startswith(base_dir)` | "应该拦得住" | **True** —— 字符串前缀比较不做 `normpath` |

**硬规则：任何关于路径规范化、字符串替换、哈希、编码、模板转义的结论，先跑一行代码再写。**
可复用的验证片段：

```python
import os
print(repr("....//....//etc/passwd".replace("../", "")))          # 路径过滤绕过
print(os.path.join("/base/dir", "../../etc/passwd").startswith("/base/dir"))  # 前缀比较
print(str(markupsafe.escape("{{7*7}}")))                          # 模板转义是否覆盖 { }
compile(f"with open('{{x}}','w') as f: f.write('{{y}}')", "<g>", "exec")      # 代码注入是否可编译
```
