## α0 评估记录（2026-08-12，A1 闭环）

**配置**：transformers 后端 + **no-merge**（PeftModel 运行时叠加 LoRA，保留 adapter FP16 最大精度）+ 4bit NF4 基座 + 训练 prompt（`combined`/V3_PROMPT）+ 贪心解码。结果文件：`experiments/exp_06_finetune/results/alpha0_87_full.json`。

### 87 合成集完整指标

| 指标 | 值 | 说明 |
|------|-----|------|
| recall | **91.8%**（56/61） | 有漏洞样本召回率 |
| accuracy | **97.6%**（80/82 有效） | 有效样本正确率 |
| FPR | **3.85%**（1/26） | 安全样本误报率 |
| strict_recall | **70.9%**（39/55） | 严格 CWE 编号+漏洞类型全对 |
| parse_fail | **5/87**（5.7%） | 4 个漏洞样本 + 1 个安全样本 |

### 失败样本明细

**parse_fail（5）**：
- `hard_cve_02_python_log_injection.py`（CWE-117 日志注入）
- `typical_17_md5_password.py`（CWE-327 弱加密）
- `typical_33_php_type_juggling.php`（CWE-843，271s 长耗时=输出超长打满 max_new_tokens）
- `typical_35_java_deser.java`（CWE-502 反序列化，271s）
- `noise_03_harden_string_concat.py`（安全样本）

**FN（1）**：`hard_longfile_01_hidden_sql.py`（CWE-89，181 行长文件隐藏 SQL 注入漏报）

**FP（1）**：`noise_06_shell_true_hardcoded.py`（shell=True 但命令为硬编码常量，被误判）

### 关键观察
1. **CWE 编号记忆是主要短板**：strict_recall 70.9% 明显低于 recall 91.8%，15 个 cwe_mismatch 中大量是"判对类型但编号记错"（如 CWE-78 写成 CWE-77、CWE-306 写成 XSS、CWE-639 写成 XSS）—— 这正体现 CWE Normalizer（查表工具）的价值。
2. **271s 长耗时样本 = parse_fail**：`typical_33`/`typical_35` 输出超长打满 2048 token 导致 JSON 解析失败，是 no-merge 模式下的边界问题。
3. **no-merge 下 batch 提速失效**：batch=4 时每批因 LoRA 运行时叠加反而更慢（实测逐档 OOM，且每批 7 分钟），故最终改回单条串行。此结论已记入 batch_probe 实验。
