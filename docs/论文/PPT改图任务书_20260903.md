## 任务卡 D（P13 备选，PPT 风格两阶段架构图）：只有当不想直接用现成图时才做
**原文件**：`ppt图片提取_20260903/P13_原图_两阶段架构图.png`



**现状问题**：现图 3 处事实错误——只画 3 个工具（实际 4 路并行）；"无候选→直接放行"与代码相反（实际默认全量复核）；"约80%/约20%"是禁止的未实测估计。

**规格**（自上而下流程图）：

1. 顶部：源代码文件输入
2. **Stage 1 工具召回层（4 路线程池并行，近零成本）**，四个并列盒子：
   - Semgrep taint（整文件污点模式）
   - TaintTracker（自研 AST 污点分析）
   - Prefilter（自研正则预筛）
   - ExternalScanner（secret / sca / sast / iac）
   - 汇合框：合并去重 + CWE 归一 → 候选漏洞清单（含 source→sink 证据链 + 行号锚点）
3. 菱形判断：有候选？
   - **无候选分支**（绿色）：生产/评估默认 full_recheck 全量 LLM 复核（全票判真才采信）——注意：不是"直接放行"
   - **有候选分支**（橙色）：进入 Stage 2
4. **Stage 2 LLM 裁决层**：triage 对齐训练分布 prompt · N=3 次采样 · 自一致率投票 · 代码切片上下文 + RAG 知识
5. 右侧竖框 **2.5 代信任层（由廉价到昂贵）**：① 确定性证据门（sink 已防御/无输入入口）② 共形预测三分类 {漏洞}/{安全}/{不确定} ③ 反事实验证（sink 注入防御看裁决是否翻转）④ 信任分级 A–E → 回填/抑制池/人工复核
6. 底部：聚合结论（确认漏洞 / 安全 / 存疑待复核）+ 兜底复核（全部候选被否决时强制全文件复核）

**红线**：不得出现 80%、20%、10-20% 等比例数字；不得画"无候选直接放行"分支。
来源行：架构与代码 two_stage_scanner.py 一致（fixed5 评估组态）。
