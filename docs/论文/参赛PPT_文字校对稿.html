第 1 页 · 封面

基于大语言模型的代码安全分析系统

  • 副标题：本地部署 · 两阶段架构 · 自训专用模型
  • 技术栈：Qwen3-8B + LoRA / 工具召回 + LLM 裁决 / 全栈多端
  • 申报人 / 学校 / 日期（占位）

第 2 页 · 项目定位与核心问题

传统工具 vs LLM 驱动的代码安全分析

  • 问题：传统静态分析工具（Semgrep / Bandit）靠固定规则模式匹配，面对复杂业务逻辑、绕过式过滤、跨函数污点时力不从心
  • 本系统定位：LLM 驱动，代码语义理解、上下文感知、可发现变体与非典型漏洞
  • 核心卖点：传统工具是"模式匹配"，本系统是"语义理解"

第 3 页 · 一句话亮点

三个核心亮点

  • "从开放生成到封闭判别"——LLM 任务从全文中发现漏洞，变为对具体 finding 判定真伪
  • "100 元训练出 95% 召回"——本地探索 + 云端放大，总成本约 100 元
  • "80% 文件不调用 LLM"——预筛短路 + 两阶段架构

第 4 页 · 系统架构

两阶段扫描架构

  • Stage 1 工具召回：Semgrep 污点流 / AST 轻量污点 / 正则预筛 / 外部工具（密钥、依赖、SAST、IaC）并行召回候选 finding
  • Stage 2 LLM 裁决：对候选做封闭二分类，N 次采样自一致率置信度，配 RAG 知识库、代码切片、行号纠正
  • 架构反转：LLM 从"发现漏洞"变为"判定真伪"，LLM 调用量从每文件 ≥1 次降为仅 10-20% 有候选文件

第 5 页 · 创新点 1

工具召回 + LLM 裁决的架构反转

  • 为什么不让 LLM 全文找洞：开放生成幻觉空间大、不可复现
  • 判别优于发现：每条判定有工具证据做锚点，幻觉空间被大幅压缩
  • 工具层漏报由"抽样复核保险丝"兜底（10% 无候选文件全量复核，监控召回漂移）

第 6 页 · 创新点 2

自一致率置信度替代 LLM 自报 confidence

  • 弃用 LLM 自报 confidence（校准差），改用 N=5 采样自一致率作为置信度代理
  • 证据锚定工具链：LineNormalizer 反行号幻觉 / TaintTracker 污点路径 / FixVerifier 修复校验 / CWE Normalizer 纠正
  • 修复建议"行号锚定"契约：从完整代码围栏改为单行局部建议，FixVerifier 主职抓幻觉行号

第 7 页 · 训练主线

本地探索 → 云端放大（100 元训练路线）

  • 本地 16GB 消费级 GPU：QLoRA + rsLoRA + AOTRITON，8B 模型 SFT 训练压缩到 16GB 内，v2~v9 快速迭代
  • 云端 A800：bf16 全精度 LoRA，双模型（DeepSeek / GLM）蒸馏 7692 条，4.1h 完成
  • 总成本约 100 元（DeepSeek 40 + GLM 40 + A800 20），对消费级硬件用户有直接参考价值

第 8 页 · 实验结果

合成集 vs 真实 CVE

  • 合成集（87 段）strict_recall：baseline 0.459 → v9max 0.607（+14.8pp），recall 1.000（0 FN）
  • 真实 CVE-fix recall：baseline 0.375 → v9max 0.950（+57.5pp，HF 管道）
  • 关键诚实：合成集虚高 59.2pp，真实集上被有效收敛
  • 说明：发布形态（Ollama Q4_K_M 量化）CVE-fix recall 实测 0.75~0.79，量化缺口已在产品内可视化

第 9 页 · 数据可信度方法论

数据可信度比指标绝对值更重要

  • 三次泄漏发现：样本注释泄露 → RAG 代码泄露 → 训练-测试 Jaccard 泄漏
  • Jaccard 行级重叠审计 + 合成集 vs CVE-fix 双测试集 + Bootstrap 显著性检验 + 严格口径指标（parse_fail 计入漏报）
  • "100% 准确率"是假象 → 诚实修正 → 反思架构 → 提出新方法 → 设计实验验证：完整的方法论自觉闭环
