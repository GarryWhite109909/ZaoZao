# Nivis 毕设答辩 PPT 框架

> 核心命题：这个项目的价值不在最终指标，而在**一次次的自我发现与推翻**——"做成项目的人"的价值 + "项目"的价值两条线。

---

## 第一幕：人的价值 —— 一条方法论发现链（约 5 页，主叙事）

> 我最初以为这是"训练一个漏洞检测模型"的工程题。做完才发现，最值钱的不是刷出来的指标，而是我在过程中建立的、每一次推翻自己后沉淀下来的方法论判断。下面是这条链上真正的关键发现。

---

### 发现 1｜数字会骗人：数据可信度是前提

**发现**：漂亮指标不一定是真的。遇到过样本答案注释泄露（100%准确率是假象）、训练-测试 Jaccard 重叠泄漏（v4 整版废弃）、测试集反向拟合规则（等于作弊）。任何"提升"都要先排除数据是否在骗我。

**我做了什么**
- 三次主动排查出泄漏，而非评委指出
- 建立 Jaccard 行级重叠审计：30% 相似即删/复核，之后所有数据版本必须通过
- 自查铁律：新增规则前先问"不看测试集结果我能推出来吗？否→删"

**沉淀的判断**：数据清洗和配比要关注**分布多种变体来教会模型一个方面的知识**，而不是用一个确定性的高质量样本妄图解决一整个方面的知识；评估集答案污染会系统性高估能力，任何提升先用"删除泄露后重跑"验证。

---

### 发现 2｜模型有盲区，但工具也有；"用工具不如不用"大多是工具没优化好

**发现**：单阶段里模型被锁死在"工具找什么就看什么"，模型天然会、但工具规则覆盖不到的盲区成了硬伤。而当"用了工具反而比不用更差"时，我最初怀疑两阶段架构本身——但归因后确认：**不是架构错了，是工具没有优化到位、提示不到位会误导模型**。工具不如不用的解药是把工具调到能帮上模型，而不是退回纯 LLM。

**我做了什么**
- 读工具层与模型层双层原始输出，逐样本定位是"工具漏召"还是"模型判错"
- 归因思维：`stage1_no_candidate`（工具没找到）与 `stage2_rejected`（模型否决）是两个不同的修复方向
- 否决"补规则"死路：规则何其多补不完，且对测试集反推=作弊；改为优化工具能力，让工具真正帮到模型

**沉淀的判断**：系统出问题时先归因"这一层的问题"还是"那一层的问题"，归因分流决定修哪儿；语义类漏洞（授权/溢出/IDOR/XXE）本就该交给 LLM，规则补不齐。

---

### 发现 3｜模型帮工具必须谨慎：模型自身能力得不到保障

**发现**：想让模型回填经验喂给工具时，发现**模型自己的判定都可能错**——把错的"经验"回填给工具，会把工具教坏，误导扩散。工具是确定性的、可审计的，模型输出有不确定性，"让模型教工具"风险不比收益小。

**我做了什么**
- 把模型输出按"判定质量"分级：只有判定正确且标号也对的才可回填，误报反向进抑制池
- 多重门控：全票门槛、跨样本聚合、双向可撤销、独立验证集门控——"谨慎"不是口头原则，是门槛参数写进代码
- 评估与自举隔离：`--no-signal-feedback`，防止历史裁决污染后续召回

**沉淀的判断**：让一个当前能力还不可靠的模型去"修正"一个确定性的工具，前提是给它的输出分层、设门槛；**宁可不改，也不要教坏**。

---

### 发现 4｜评估机制本身也会污染结果：评估必须先可信

**发现**：指标不仅会被数据污染，还会被**评估机制自己**污染——抑制池跨跑叠加历史裁决、共形校准用同一测试集样本，统计保证失效（exchangeability 破坏），换来的是假的好看。

**我做了什么**
- 定位 fixed3 带污染（10+ 核心规则被全局抑制池架空）→ 整轮 fixed4 弃用
- 评估强制隔离自举、未显式指定校准源时禁用自动加载
- 在干净环境下得到 fixed5 的数字

**沉淀的判断**：测量结果前先保证测量本身可信；统计方法的假设前提（exchangeability）要逐条核对，不能只看指标好看。

## 第二幕：项目的价值 —— 落到一个系统（约 3~4 页）

> 从发现链长出一个完整系统：数据 → 模型 → 工具 → 信任层，层层咬合。

---

### 系统 1｜数据：从手写 914 条到两阶段 7972 条（"本地探索→云端放大"）

- 本地 16GB 卡撞墙（DPO 三次失败、LoRA 增容无效、手写数据到顶）→ 换路线：本地验证方法论，云端释放算力
- DeepSeek+GLM 双模型 API 蒸馏 + 云端 A800 bf16：总成本约 100 元（API 40+40 + 算力 20）
- 两阶段训练：stage1 打底 + stage2 回收 dev 续训

> 一句话：不是暴力堆数据，而是在有限预算内把数据从"不可信、量不足"做到"可信、够用"。

---

### 系统 2｜架构：工具召回 + LLM 裁决（两阶段）

- Stage 1 静态工具做确定性候选召回 + 证据链（有 source 型漏洞）
- Stage 2 LLM 做封闭判别（无 source 型语义漏洞兜底）
- 用数据否决了"补规则"，用归因确认"工具没优化好"，最终让工具和模型互为补位

---

### 系统 3｜信任层：让模型判据可信（2.5 代）

- 把"模型输出不确定"落地成工程：信任分级回填、统计门控 + 因果门控、确定性证据门
- 让工具/模型协同时"宁误报于复核，不错杀真漏洞"——遗留 review 是保守设计而非判错

---

### 结果页：干净评估下系统数字

| 配置 | recall（不含 review） | FPR | accuracy |
|---|---|---|---|
| 纯 LLM（对照） | 0.967 | 0.154 | 0.931 |
| 工具链 fixed3（带污染） | 0.982 | 0.167 | 0.862 |
| **工具链 fixed5（干净环境）** | **1.000** | **0.043** | 0.862 |

- 明细：TP=53 FN=0 TN=22 FP=1，review 11（保守设计，非判错）
- 说明口径：acc 0.862 低于纯 LLM 0.931，主因是 11 个 review 计未决，非判错
- **诚实边界**：review 恰恰是下一代模型的精准优化点（数据支撑）

## 第三幕：工程实现全景（约 3 页）

### 工程 1｜自研工具链（零依赖，一行行写的）

| 工具 | 解决什么问题 | 关键设计 |
|---|---|---|
| TaintTracker | 污点分析 | 线性数据流、消毒识别、单文件过程间摘要 |
| Prefilter | 预筛候选 | 安全模式+漏洞特征双轨、硬编码凭证特殊处理 |
| CodeSlicer | 长文件切片 | ≥150 行按函数切分、chunk 间 OR 合并 |
| CWE Normalizer | CWE 编号纠正 | 零 token 开销查表、父子族匹配 |
| LineNormalizer | 行号幻觉纠正 | 内容锚定匹配、就近优先、重复行幂等 |
| FixVerifier | 修复建议验证 | 行号锚定、Java 包壳编译、JS 语法校验 |
| SARIF | 标准化导出 | SARIF 2.1.0、与 GitHub Code Scanning 互通 |

### 工程 2｜推理后端与硬件适配

- 一套代码 4 种后端 × 多平台：Ollama / Transformers / LlamaCPP / vLLM，覆盖 Win/Linux/macOS、NVIDIA/RTX50/AMD/Apple/CPU
- RTX50(Blackwell) Windows 强制源码编译（避开 cu130 预编译 wheel 的非法指令）；RTX50 GPU 需配 CUDA Toolkit 的提示
- 自适应回退：探测到 LoRA adapter 但本机跑不了 transformers 时自动回退 Ollama 并告警
- 显存分档自适应上下文、Ollama 低显存 GPU+CPU 混合卸载

### 工程 3｜启动器 / 依赖 / 部署（新机器开箱即用）

- 国内网络工程：大文件 HTTP Range 断点续传、国内镜像直连 + 断流回退、HF_ENDPOINT 前置、代理规范化（socks5://）
- 模型管理不落 C 盘：OLLAMA_MODELS / HF_HOME 锁到项目目录，自动迁移 + 清理，断点续传 + 完整性校验
- GGUF 防二次叠加：拒绝下载已合并 LoRA 的发布 GGUF，防止运行时再叠 LoRA 结果全错
- 自动安装合适依赖 + 安全工具，跨平台一键启动

### 工程 4｜前端与插件

> 举重若轻："这么优秀的前端，其实是整个项目最不起眼的地方——尽管它有这些细节……"

- 前端：双层设计令牌、手写 SVG 图表（三角函数逐帧计算规避 Chrome Bug）、主题切换、评分圆环动画、模型管理抽屉
- 通信：NDJSON 流式批量进度，比 WebSocket 简单且兼容性好
- 插件：VS Code（诊断波浪线 + Webview + 批量扫描）+ IntelliJ（气球通知 + ReadAction 线程安全读取）

## 第四幕：未来规划 —— Nivis-α1（1 页）

> 当前不是终点，下一步收敛方向已经清晰，且 review 机制精确指出了该修哪里。

- **修模型侧能力**：把 11 个 review（逻辑漏洞没有专用规则 / 归因偏置）作为定向优化点，配合防御机制教学 CoT、DSPairs/偏好优化
- **20 段 CVE-fix 测试集**：修 review 时同步补强真实 CVE 泛化——它暴露出的问题留到 α1 收口，本阶段不是核心
- **评估进一步可靠**：共形校准改用独立校准集重拟合（消除 in-sample 风险），评估隔离铁律保持
- **数据飞轮**：冻结集 + 回填信号 → 去重/泄漏审计/格式校验 → 版本化 → 回流（协议与管道已就绪，α1 跑通数据回流）
- **发布形态**：收敛量化缺口（HF/FP16 vs Ollama/Q4 两档精度），默认保精度形态
