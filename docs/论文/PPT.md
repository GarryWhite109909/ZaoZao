# Nivis 毕设答辩 PPT 框架

> 核心命题：这个项目的价值不在最终指标，而在**一次次的自我发现与推翻**——"我们"的价值 + "项目"的价值两条线。
> 每页遵循"结论先行 + 数据支撑"：口头讲结论，页面上放能经得起追问的数字。

***

## 第一幕：我们的价值 —— 一条方法论发现链（约 5 页，主叙事）

> 我们最初以为这是"训练一个漏洞检测模型"的工程题。做完才发现，最值钱的不是刷出来的指标，而是在过程中建立的、每一次推翻自己后沉淀下来的方法论判断。

***

### 发现 1｜数字会骗人：数据可信度是前提

**发现**：漂亮指标不一定是真的。三次主动排查出三类泄漏——v4 整版因训练-测试 Jaccard 重叠废弃；早期样本文件名含答案标签（100% 准确率是假象）；测试集反向拟合规则（新增规则前不问"不看测试集我能推出来吗"）。任何"提升"都要先排除不严谨性。

**做了什么**

- 三次主动排查出泄漏（答案注释泄露 / Jaccard 重叠 / 测试集拟合）
- 建立 Jaccard 行级重叠审计：30% 相似即删/复核，之后所有数据版本必须通过
- 自查铁律：新增规则前先问"不看测试集结果我能推出来吗？否→删"

**沉淀的判断**：数据清洗要关注**分布多种变体教会模型一个方面**，而非用单一样本妄图解决整个方面；评估集答案污染会系统性高估能力，任何提升先用"删除泄露后重跑"验证。

***

### 发现 2｜"用工具不如不用"大多是工具没优化好——归因分流是第一位的

**发现**：两阶段初期"工具链 recall 0.864 < 纯 LLM 0.967"，最想怀疑架构错了。逐样本归因后确认：**不是架构错了，是工具提示不到位在误导模型**——裁决式 prompt 丢上下文、无主告警锁死注意力、工具规则覆盖不到主漏洞（认证缺失/弱密码学/SSTI 深藏）。工具不如不用的解药是把工具调到能帮上模型，而不是退回纯 LLM。

**做了什么（关键：归因分流，两条修复线分开）**

- 读双层原始输出逐样本定位：`stage1_no_candidate`（工具漏召）与 `stage2_rejected`（模型否决）是两个方向——5 个 FP 里 3 个是裁决否决环节、2 个是工具提示含糊，3 个 FN 全是工具规则盲区
- 修工具能力而非补规则：TaintTracker 补 `request.files`/`file.save`/`extractall` sink，补 `request.get_data` source（示例：任意文件上传从"工具完全没提示"变成"污点路径直接召回"）
- 提示质量量化：工具层提示质量审计（A 召回覆盖率 59.0% / B 到点率 86.1% / D 误导率 14.3%），"到点没到点"用指标说话而非感觉

**沉淀的判断**：系统出问题时先归因"这一层"还是"那一层"，归因分流决定修哪儿；语义类漏洞（授权/溢出/IDOR/XXE）本就该交给 LLM，规则补不齐；**工具不会的不要瞎说**——无关告警送裁决只会锁死模型注意力，剔除后交 LLM 全文件复核兜底。

***

### 发现 3｜模型帮工具必须谨慎：把不可靠的输出回填给工具，会把工具教坏

**发现**：想让模型回填经验喂给工具时，发现**模型自己的判定都可能错**——把错的"经验"回填给确定性工具，误导扩散。工具是可审计的，模型输出有不确定性，"让模型教工具"风险不比收益小。

**做了什么**

- 输出按判定质量分 A-E 级：只有全票判真的可回填，高置信否定进抑制池（反向使用）
- 回填四重门控：全票门槛（votes==N）、跨样本聚合（≥2 独立文件）、双向可撤销（高置信否定清零已积累确认）、独立验证集门控——"谨慎"是门槛参数写进代码，不是口头原则
- 评估与自举隔离：`--no-signal-feedback`，防历史裁决污染后续召回

**沉淀的判断**：让能力不可靠的模型"修正"确定性工具，前提是输出分层、设门槛；**宁可不改，也不要教坏**。待学习池条目须经人工审核/独立验证集复验才转正——模型建议的工具规则，落地前必须过审核（当前已实现收集+门控，人工审核通道待接）。

***

### 发现 4｜评估机制本身也会污染结果：测量前先保证测量可信

**发现**：指标不仅会被数据污染，还会被**评估机制自己**污染——抑制池跨跑叠加历史裁决、共形校准用同一测试集样本（exchangeability 破坏），换来的是假的好看。

**做了什么（评估方法学四条铁律）**

1. **抑制池隔离**：fixed3 期间 10+ 核心规则被跨跑污染（B608 候选被裁决前吞掉，typical_01 候选 3→2）→ 整轮弃用，评估强制 `--no-signal-feedback`
2. **校准泄漏**：未显式指定校准源时禁用共形校准自动加载（in-sample 校准使 1-α 覆盖率保证不成立）
3. **答案泄漏**：文件名含标签、测试集反向拟合规则 → 全部审计（见发现 1）
4. **归因分流**：A 覆盖率缺口归工具侧、B 到点率缺口归模型侧，不混为一谈

**沉淀的判断**：测量结果前先保证测量本身可信；统计方法的假设前提（exchangeability）要逐条核对，不能只看指标好看。fixed5 的数字只在干净环境下给出。

## 第二幕：项目的价值 —— 落到一个系统（约 4 页）

> 从发现链长出一个完整系统：数据 → 模型 → 工具 → 信任层，层层咬合。

***

### 系统 1｜数据：914 条手写 → 蒸馏 10700 条 → 清洗 7972 条（"本地探索→云端放大"）

- 本地 16GB 卡撞墙（DPO 三次失败、LoRA 增容无效）→ 换路线：本地验证方法论，云端释放算力
- DeepSeek+GLM 双模型 API 蒸馏（长链推理压缩为 ≤5 步 ≤590 token 才能蒸馏到 8B）+ 云端 A800 bf16：总成本约 100 元（API 40+40 + 算力 20）
- 两阶段训练：stage1 打底 + stage2 回收 dev 续训（7972 条，正负比清洗后 ≈1:1.2）

> 一句话：不是暴力堆数据，而是在有限预算内把数据从"不可信、量不足"做到"可信、够用"。

***

### 系统 2｜架构：工具召回 + LLM 裁决（两阶段）——架构反转的两重收益

- Stage 1 静态工具并行召回候选 + 证据链（有 source 型漏洞：SQL/命令/XSS/路径穿越）
- Stage 2 LLM 对候选做封闭判别（无 source 型语义漏洞：认证缺失/IDOR/竞态，由 LLM 兜底）
- **效率收益（常被忽略的第二价值）**：LLM 任务从"全文件找洞"变为"对 finding 判真伪"，**约 80% 文件因三工具无候选不调用 LLM**——LLM 调用量从每文件 ≥1 次降为仅 10-20% 有候选的文件
- **精度收益**：每条判定有工具证据链做锚点，幻觉空间大幅压缩；LLM 语义兜底覆盖工具盲区（16 个盲区样本纯 LLM 判对 15/16 是架构依据）
- 用数据否决了"补规则"死路（规则补不完且对测试集反推=作弊），用归因确认"工具没优化好"

***

### 系统 3｜信任层：让模型判据可信（2.5 代，四层门控）

把"模型输出不确定"落地成工程，四层由廉价到昂贵：

| 层 | 机制 | 干什么 | 成本 |
|---|------|--------|------|
| L0 | 确定性证据门 | 零 LLM 成本的静态核验：sink 邻域防御签名 + 无输入入口拦截（如 subprocess 列表参数、参数化查询的误报在此拦截）| 0 |
| L1 | 共形预测 | 统计门控，N 采样投票 → {漏洞}/{安全}/{不确定} 三分类，带 1-α 覆盖率保证 | 低 |
| L2 | 反事实扰动验证 | 因果门控：sink 行内注入防御 → 裁决是否翻转，区分"真理解"vs"模式匹配" | 中 |
| 回填 | 信任分级信号注册表 | 模型判定质量分级回填（见发现 3），工具随使用收敛 | 0 |

- 效果：α0 上 FPR 0.154→0.105（-32%）；fixed5 上 FPR 0.043
- 设计取向：**宁误报于复核，不错杀真漏洞**——遗留 review 是保守设计而非判错

***

### 结果页：干净评估下系统数字（fixed5）

| 配置 | recall（不含 review） | FPR | strict_recall | strict_acc | accuracy |
| --- | --- | --- | --- | --- | --- |
| 纯 LLM（对照） | 0.967 | 0.154 | 0.770 | 0.793 | 0.931 |
| 工具链 fixed3（带污染，历史） | 0.982 | 0.167 | 0.800 | 0.808 | 0.862 |
| **工具链 fixed5（干净环境）** | **1.000** | **0.043** | **0.811** | **0.847** | 0.862 |

- 明细：TP=53 FN=0 TN=22 FP=1，review 11（rv=8 漏洞样本 / rs=3 安全样本，保守未决）
- **acc 0.862 为什么低于纯 LLM 0.931**：acc=(TP+TN)/87 全量分母，11 个 review 计"未决"占分母——**不是判错**；若只算有结论样本，未决率 12.6% 是保守设计的代价
- **strict 全维度反超纯 LLM**：strict_recall 0.770→0.811（+4.1pp）、strict_acc 0.793→0.847（+5.4pp）——工具链补正了模型归因编号记忆（CWE Normalizer evidence 守卫 + 父子族匹配），strict 收益不靠 FPR 交换
- **strict 口径（2026-08-18 统一）**：strict_tp/(tp+fn)，exp_07 剔除 review，全部文件经 `recompute_strict_metrics.py` 批量重算，与素材库/论文口径一致
- **工具层提示质量**（fixed5，`prompt_quality_audit.py`）：召回覆盖率 59.0% / 提示到点率 86.1% / 误导率 14.3%——"工具提示到点没到点"用五维指标量化，不再二元"过/不过"
- **诚实边界**：8 个 review 漏洞样本（SSRF/路径正则绕过/IDOR/竞态/跨文件×2 等）全是工具盲区 + 复核非全票——恰恰是下一代模型的精准优化点（数据支撑）

## 第三幕：工程实现全景（约 3 页）

### 工程 1｜自研工具链（零依赖，一行行写的）

| 工具 | 解决什么问题 | 关键设计 |
| --- | --- | --- |
| TaintTracker | 污点分析 | 线性数据流、消毒识别、单文件过程间摘要、多语言 sink/source 表 |
| Prefilter | 预筛候选 | 安全模式+漏洞特征双轨、硬编码凭证特殊处理 |
| CodeSlicer | 长文件切片 | ≥150 行按函数切分、chunk 间 OR 合并、调用点证据链 |
| CWE Normalizer | CWE 编号纠正 | 零 token 开销查表、evidence 守卫、父子族匹配（917⊂94） |
| LineNormalizer | 行号幻觉纠正 | 内容锚定匹配、就近优先、重复行幂等 |
| FixVerifier | 修复建议验证 | 行号锚定、Java 包壳编译、JS 语法校验 |
| **PromptQualityAudit** | **工具提示质量审计** | **五维量化：召回覆盖率/到点率/噪音率/误导率/判型一致性** |
| SARIF | 标准化导出 | SARIF 2.1.0、与 GitHub Code Scanning 互通 |

### 工程 2｜推理后端与硬件适配

- 一套代码 4 种后端 × 多平台：Ollama / Transformers / LlamaCPP / vLLM，覆盖 Win/Linux/macOS、NVIDIA/RTX50/AMD/Apple/CPU
- RTX50(Blackwell) Windows 强制源码编译（避开 cu130 预编译 wheel 的非法指令）；显存分档自适应上下文、Ollama 低显存 GPU+CPU 混合卸载
- 显存回收：推理后释放缓存归还驱动（CUDA/ROCm 品牌适配，CPU 安全跳过）——防长期采样碎片累积导致的 ROCm 崩溃
- 自适应回退：探测到 LoRA adapter 但本机跑不了 transformers 时自动回退 Ollama 并告警

### 工程 3｜启动器 / 依赖 / 部署（新机器开箱即用）

- 国内网络工程：大文件 HTTP Range 断点续传、国内镜像直连 + 断流回退、HF_ENDPOINT 前置、代理规范化（socks5://）
- 模型管理不落 C 盘：OLLAMA_MODELS / HF_HOME 锁到项目目录，自动迁移 + 清理，断点续传 + 完整性校验
- GGUF 防二次叠加：拒绝下载已合并 LoRA 的发布 GGUF，防止运行时再叠 LoRA 结果全错
- 自动安装合适依赖 + 安全工具，跨平台一键启动

### 工程 4｜前端与插件

> 举重若轻："这么优秀的前端，其实是整个项目最不起眼的地方——尽管它有这些细节……"

- 前端：双层设计令牌、手写 SVG 图表（三角函数逐帧计算规避 Chrome Bug）、主题切换、评分圆环动画、模型管理抽屉
- 通信：NDJSON 流式批量进度，比 WebSocket 简单且兼容性好；模型下载 queue+StreamingResponse 实时进度
- 插件：VS Code（诊断波浪线 + Webview + 批量扫描）+ IntelliJ（气球通知 + ReadAction 线程安全读取）

## 第四幕：未来规划 —— Nivis-α1（1 页）

> 当前不是终点，下一步收敛方向已经清晰，且 review 机制精确指出了该修哪里。

- **修模型侧能力**：把 review 的 8 个漏洞样本（逻辑漏洞无专用规则 / 归因偏置）作为定向优化点，配合防御机制教学 CoT、DSPairs/偏好优化；提示质量审计 B 到点率 86.1% 的缺口（CSRF/JWT/竞态/弱加密无专用规则）同样归模型侧
- **20 段 CVE-fix 测试集**：修 review 时同步补强真实 CVE 泛化——它暴露出的问题留到 α1 收口，本阶段不是核心
- **评估进一步可靠**：共形校准改用独立校准集重拟合（消除 in-sample 风险），评估隔离铁律保持
- DPO、GRPO 脚本已写好（GRPO 奖励函数防 reward hacking 三道闸已设计：FP 惩罚≥FN、格式门前置、证据接地校验）
- **数据飞轮**：冻结集 + 回填信号 → 去重/泄漏审计/格式校验 → 版本化 → 回流（协议与管道已就绪，α1 跑通数据回流）
- **模型→工具闭环**：learn_pool 待审核条目接入人工审核通道（独立验证集复验 + 人工批准）后转正为工具规则
- **发布形态**：收敛量化缺口（HF/FP16 vs Ollama/Q4 两档精度），默认保精度形态
