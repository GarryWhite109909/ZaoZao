## 二、术语与缩略语

| 缩略语 / 术语 | 全称 | 说明 |
|---|---|---|
| **CWE** | Common Weakness Enumeration，通用弱点枚举 | 软件安全弱点的标准分类体系，如 CWE-89 SQL 注入 |
| **CVE** | Common Vulnerabilities and Exposures，通用漏洞披露 | 针对具体软件产品的已公开漏洞编号 |
| **SAST** | Static Application Security Testing，静态应用安全测试 | 不运行程序、直接分析源码的安全检测 |
| **SCA** | Software Composition Analysis，软件成分分析 | 检测第三方依赖中的已知漏洞 |
| **IaC** | Infrastructure as Code，基础设施即代码 | 以配置/模板描述基础设施；其配置错误也是安全风险 |
| **污点分析** | Taint Analysis | 跟踪外部输入（source）流向危险操作（sink）的数据流分析技术 |
| **Source / Sink** | 污点来源 / 触发点 | 漏洞数据流的起点与终点 |
| **LLM** | Large Language Model，大语言模型 | 本系统的语义裁决引擎 |
| **SFT** | Supervised Fine-Tuning，监督微调 | 用标注数据对基座模型做指令微调 |
| **LoRA** | Low-Rank Adaptation，低秩适配 | 冻结基座、只训练低秩增量矩阵的参数高效微调方法 |
| **QLoRA** | Quantized LoRA | 4bit 量化基座 + LoRA 微调，显著降低显存需求 |
| **NF4** | 4-bit NormalFloat | 一种 4bit 量化数据格式 |
| **量化** | Quantization | 用更低精度表示模型权重以减小体积、加速推理 |
| **两阶段扫描** | Two-Stage Scanning | 本系统核心架构：Stage 1 工具召回 + Stage 2 LLM 裁决 |
| **自一致率** | Self-Consistency | 对同一判定采样多次，以判真票占比作为置信度代理 |
| **共形预测** | Conformal Prediction | 一种带覆盖率保证的统计预测框架，用于门控不确定样本 |
| **反事实验证** | Counterfactual Verification | 在 sink 行内注入防御后重判，以区分“真理解”与“模式匹配” |
| **证据门** | Evidence Gate | 基于静态特征（已知防御、输入入口）的零 LLM 成本确定性校验 |
| **信任分级回填** | Trust-Graded Feedback | 按判定质量分级，仅高质量判定允许回填工具记忆 |
| **SARIF** | Static Analysis Results Interchange Format | 静态分析结果的标准化交换格式（本系统导出 2.1.0） |
| **NDJSON** | Newline-Delimited JSON | 每行一个 JSON 对象的流式传输格式 |
| **RAG** | Retrieval-Augmented Generation，检索增强生成 | 检索知识库内容注入模型上下文 |
| **SSRF** | Server-Side Request Forgery，服务端请求伪造 | 本系统 URL 抓取功能需防御的攻击类型 |
| **FPR** | False Positive Rate，误报率 | 安全样本被误判为漏洞的比例 |
| **strict / loose 口径** | 严格 / 宽松评估口径 | strict 同时校验判断与 CWE 编号是否正确；loose 只看是否判出漏洞 |
| **未决率** | — | 转人工复核、不做自动结论的样本占比 |
| **Ollama** | — | 本地大模型运行与模型分发工具 |
| **GGUF** | GPT-Generated Unified Format | llama.cpp 生态的模型文件格式 |
| **vLLM** | — | 高吞吐大模型推理服务框架 |
| **v9max** | — | 本系统发布会话的模型版本（Ollama 形态） |
| **α0.5** | Nivis-alpha0.5 | 本系统高精度 LoRA 适配器版本（Transformers 形态） |
| **Nivis** | — | 本系统内核引擎与模型系列的代号（Nivis / Nivis-α0.5） |
| **固定组态 fixed5** | — | 评估基线组态（关闭信号回填），代表“静态管线”能力 |
| **wave8** | — | 第八波收口组态（盲区收口 + 归因链修正 + 回填开启 + 上下文 16384），当前最强 |
| **未复核 / not_covered** | — | 工具零召回且预算未覆盖，**模型从未被调用**；区别于“已判安全” |
| **复核覆盖度** | review coverage | 与判定正交：`llm_checked` / `not_covered` / `unknown`，表达“模型有没有看过” |
| **注意力预算** | Attention Budget | 按文件风险分与盲区命中排序，决定哪些文件值得消耗 LLM 预算 |
| **盲区提醒** | Blind Spot Hint | 以行级中性提示把“工具写不了规则”风险注入裁决 prompt；不产生候选、不进回填 |
| **工具-模型自适应闭环** | — | 模型裁决经门控校验后回填工具记忆，两者互相修正（§4.3.4） |
