# 第八篇  安装手册

> **本篇对应官方材料**：安装手册
> **改编说明**：本篇由项目《用户手册》§2、§13 与项目 README 的「快速开始 / 切换推理后端 / 故障排查」章节改编，已去除身份信息与文档间相对链接。

## 8.1  系统要求

| 条件 | 要求 | 说明 |
|---|---|---|
| 操作系统 | Windows 10+ / Linux / macOS | 三平台均支持 |
| Python | 3.10+ | 启动脚本会检测并自动安装依赖 |
| pip | 任意可用版本 | 首次运行自动安装依赖 |
| 磁盘空间 | ≥ 8 GB（建议 15 GB） | 模型权重约 4.7 GB + 依赖包约 2 GB + 向量库缓存 |
| 内存 | ≥ 8 GB（建议 16 GB） | 模型推理需要占用内存 |
| GPU（可选） | NVIDIA / AMD(ROCm) / Apple Silicon ≥ 4 GB | 无 GPU 时自动回退 CPU 推理（速度约为 GPU 的 1/10~1/20） |
| Ollama | 首次运行自动安装 | 若自动安装失败，请手动从官网安装 |
| git（可选） | 任意版本 | 仅 GitHub 仓库扫描功能需要 |
| 网络 | 首次需要联网 | 下载依赖包 + 模型；后续可离线运行 |

> **Windows 下 LlamaCPP 后端暂不支持 RTX 50 系列与 AMD 显卡**：受 Windows 上 `llama-cpp-python` 预编译二进制与编译工具链限制，这两类显卡易报 DLL / 编译类错误。推荐改走默认 Ollama 后端，或使用 Linux 系统运行 LlamaCPP / Transformers 后端。

## 8.2  一键启动（推荐）

一条命令搞定，启动脚本会自动完成其余所有事情：

```bash
# 解压软件包后进入项目根目录

# Windows：双击
app\launcher\start_windows.bat

# Linux / macOS
bash app/launcher/start_linux_macos.sh
```

### 8.2.1  启动脚本自动完成的步骤

1. **检测并安装 Python 核心依赖**——首次运行自动安装；
2. **选择推理后端**——启动器会提示选择 Ollama / Transformers / LlamaCPP；默认根据环境变量自动解析；
3. **自动安装后端专属依赖**——若选择进程内后端，启动器会按当前 OS 与 GPU 自动下载正确的 `torch` / `transformers` / `peft` / `bitsandbytes` / `llama-cpp-python`（支持 Windows/Linux/macOS × NVIDIA/AMD/Apple/CPU）；
4. **检测并安装 Ollama**——使用 Ollama 后端时自动安装/启动（其他后端跳过）；
5. **硬件检测与自适应配置**——自动检测 GPU/CPU/RAM，按显存分档选择推理参数（`num_ctx` / `num_gpu` / 量化等级）；
6. **拉取模型 / 定位 adapter**——Ollama 后端自动下载发布模型（约 4.7 GB，Q4 量化），拉取失败则回退官方基础模型；若软件目录下存在自研 LoRA adapter 且运行时兼容，则自动切换 **Transformers 进程内后端**（保 LoRA FP16 精度）；
7. **召回传统安全工具**——自动安装 Bandit / Semgrep / Gitleaks / Trivy / pip-audit / detect-secrets（两阶段 Stage 1 工具召回依赖；缺哪个静默跳过哪个）；
8. **启动后端**——FastAPI 服务监听 `http://127.0.0.1:8765`；
9. **打开浏览器**——自动跳转到 `http://localhost:8765`。

> 首次启动因需下载模型（约 4.7 GB）或后端依赖（torch 等约 2-4 GB），耗时取决于网速，请耐心等待。**后续启动通常 10 秒内完成。**
>
> 启动器会把模型存储锁定到项目目录，不会把系统盘 / 用户家目录塞满。

### 8.2.2  ⚠️ Linux 用户：Ollama 模型存储统一到项目目录（只需一次）

本软件把 Ollama 模型统一放在项目内目录（后端调用路径，避免模型落系统目录）。但 Linux 上用官方脚本自动安装的 Ollama 会被注册成 **systemd 服务**，它开机自启、始终用系统默认存储占用固定端口，与项目存储冲突。首次使用前请执行一次：

```bash
sudo systemctl disable --now ollama
```

之后启动器会自己用项目目录启动 Ollama，模型全部落在项目目录，前端状态一致。
**Windows / macOS 无需此步骤**（winget/brew 安装不注册系统服务，启动器直接接管）。

## 8.3  手动启动

如果不想用启动脚本（例如已在 IDE 中配置好环境），可以手动分步启动：

```bash
# 1. 确保 Ollama 运行
ollama serve &

# 2. 确保模型已拉取
ollama pull <发布模型名>

# 3. 启动后端
uvicorn app.backend.main:app --host 127.0.0.1 --port 8765

# 4. 浏览器访问
open http://localhost:8765        # macOS
xdg-open http://localhost:8765    # Linux
start http://localhost:8765       # Windows
```

## 8.4  确认安装成功

浏览器打开 `http://localhost:8765`，看到欢迎页 / 仪表盘即成功。也可在终端验证：

```bash
python -m app.launcher.vuln_scanner_cli health
```

## 8.5  切换推理后端

后端按以下优先级**自动解析**：

1. `VULN_SCANNER_BACKEND` 显式设置时优先（`ollama` / `transformers` / `llamacpp`）；
2. 配置了 `VULN_SCANNER_ADAPTER`，或软件目录下探测到合法 LoRA adapter（优先上线版 stage2）**且运行时兼容**时，自动选 **Transformers**——Q4 基座（NF4）+ FP16 LoRA 进程内推理，精度最高；
3. 否则回退 **Ollama**（Q4_K_M 合并量化的发布模型）——兼容性最好、依赖最少的一键启动形态；探测到 adapter 但本机跑不动 transformers 时也会自动回退并打印告警。

```bash
# Transformers 后端（NF4 基座 + FP16 LoRA，需 6GB+ 显存或足够内存）
export VULN_SCANNER_BACKEND=transformers
export VULN_SCANNER_ADAPTER=/path/to/alpha05_stage2_lora
bash app/launcher/start_linux_macos.sh

# LlamaCPP 后端（Q4 GGUF + 运行时 FP16 LoRA，实验性）
export VULN_SCANNER_BACKEND=llamacpp
export VULN_SCANNER_GGUF=/path/to/q4_k_m.gguf
export VULN_SCANNER_ADAPTER=/path/to/alpha05_stage2_lora
bash app/launcher/start_linux_macos.sh
```

> Windows 使用 `set` 代替 `export`。选择进程内后端后，启动器会自动按当前 OS/GPU 下载对应版本的依赖。

### 8.5.1  后端平台支持矩阵

各推理后端在不同平台 / 显卡上的支持情况，**完整矩阵见第三篇 §3.5.3**（含 vLLM 行），此处给出安装选型结论：

| 结论 | 说明 |
|---|---|
| **优先 Ollama** | 三平台全兼容（Windows / Linux / macOS × NVIDIA / RTX 50 系 / AMD / Apple / CPU），依赖最少，是设备兼容性优先时的首选 |
| **Transformers 限 Linux 体验最佳** | Windows 端不支持 AMD，RTX 50 系需额外 CUDA Toolkit |
| **LlamaCPP 的 Windows 端受限** | 暂不支持 RTX 50 系与 AMD 显卡（源码编译未成功） |
| **受限组合的处理** | 改用 Linux 运行，或回退 Ollama 后端 |

> 完整能力矩阵（含 Apple Silicon 与纯 CPU 列）以第三篇 §3.5.3 为准，两处如有出入以第三篇为唯一事实来源。

### 8.5.2  显存与平台说明

- Transformers 后端推荐 NVIDIA/AMD 显存 ≥ 6GB；4GB 显存会被强制走 CPU，速度显著下降；
- `bitsandbytes` 已支持 NVIDIA CUDA、AMD ROCm（预览）、CPU-only、Apple Silicon（慢速路径）；追求速度请改用 Ollama 后端；
- LlamaCPP 后端可纯 CPU 运行，也可按编译选项启用 CUDA/ROCm/Metal。

## 8.6  环境变量配置

启动器和后端通过以下环境变量控制行为，按需设置：

| 环境变量 | 默认值 | 说明 |
|---|---|---|
| `VULN_SCANNER_BACKEND` | 自动解析 | 推理后端：`ollama` / `transformers` / `llamacpp` |
| `VULN_SCANNER_ADAPTER` | 自动探测 | Transformers/LlamaCPP 后端：LoRA adapter 目录 |
| `VULN_SCANNER_GGUF` | 无 | LlamaCPP 后端必填：Q4 GGUF 基座文件路径 |
| `VULN_SCANNER_MODEL` | 发布模型 | Ollama 后端使用的模型名 |
| `VULN_SCANNER_FALLBACK_MODEL` | 基础模型 | 主模型拉取失败时的回退模型 |
| `VULN_SCANNER_AUTO_INSTALL_DEPS` | 未设置 | `1` 强制重新检查/升级依赖；`0` 禁用自动安装 |
| `VULN_SCANNER_PIP_INDEX` | 无 | 覆盖 pip 镜像源 |
| `VULN_SCANNER_RAG` | `0` | 设为 `1` 启用知识库增强 |
| `VULN_SCANNER_PREFILTER` | `1` | 设为 `0` 关闭传统工具预筛 |
| `OLLAMA_BASE_URL` | `http://localhost:11434` | Ollama 服务地址 |
| `VULN_SCANNER_NUM_CTX` | 自动检测 | 模型上下文窗口大小 |
| `VULN_SCANNER_NUM_GPU` | 自动检测 | GPU 层数（0 = 纯 CPU） |
| `VULN_SCANNER_NUM_THREAD` | 自动检测 | CPU 推理线程数 |

## 8.7  卸载

### 8.7.1  一键卸载

| 平台 | 入口 |
|---|---|
| Windows | 双击 `uninstall_windows.bat`，或运行 `python uninstall.py` |
| Linux / macOS | 运行 `bash uninstall.sh`，或运行 `python3 uninstall.py` |

常用参数：

- `--yes`：全自动，跳过所有确认；
- `--dry-run`：模拟，只列出将要删除的内容，不实际删除；
- `--keep-project`：保留项目文件夹（只清依赖和数据）；
- `--keep-ollama`：保留 Ollama 本体与模型；
- `--keep-accel`：保留 CUDA/ROCm 系统组件。

### 8.7.2  ⚠️ 必须用安装时的同一个 Python 环境卸载

依赖装进哪个 Python 环境，就必须用哪个环境卸载：

- **一键启动用户**：依赖是启动器用系统 Python 自动安装的，直接运行卸载脚本即可；
- **conda / venv 用户**：安装时先激活过环境，卸载前也必须先激活同一个环境再运行卸载脚本；
- 卸载脚本只清理"运行它的那个 Python 环境"，换环境运行会提示"未发现本项目相关包"并跳过，等于没有真正卸载。

### 8.7.3  卸载范围

脚本会按本机实际检测结果动态清理：

1. 后端进程（端口 8765）与 Ollama 服务进程；
2. 当前 Python 环境中的本项目相关包与 pip 下载缓存；
3. Ollama 拉取的模型；
4. Ollama 本体（按平台：winget / brew / apt / dnf / pacman / zypper / apk / 官方脚本）；
5. Linux 系统级 CUDA / ROCm 组件（需 sudo，仅 apt 系发行版）；
6. 本地运行数据：向量库、输出目录、日志、各类缓存；
7. 已安装的编辑器插件（尽力而为）；
8. 整个项目文件夹。

### 8.7.4  不会自动删除的内容

- **外部扫描工具**（bandit / semgrep / gitleaks / trivy）：这些是共享系统工具，可能被其他项目使用，卸载脚本不会动它们；
- **conda 环境本身**：卸载脚本只清当前环境里的包，不会删除任何 conda 环境；
- **npm 全局包**：如需删除请手动操作；
- **部分共享基础库**（网络/类型相关的基础库）：脚本保留这类通用库，避免影响同一环境里的其他程序。但注意：科学计算类包也在清理列表里，若同一环境还有其他项目用到它们，请留意确认提示，必要时先用 `--dry-run` 查看或将依赖装在独立虚拟环境。

### 8.7.5  注意事项

- Ollama 模型目录与 HuggingFace 缓存是全局目录，卸载会删除里面**所有**模型/缓存（包括其他项目用到的），`--yes` 模式下不会再次确认，请提前确认；
- 卸载脚本会逐项检查实际删除结果，失败项会明确报错，不会提示虚假成功；完成后请确认项目文件夹确实已删除。

## 8.8  故障排查

### 8.8.1  Semgrep 规则本地化（离线可用，随软件分发）

系统使用的 Semgrep 规则包已本地化并随软件入库（纯文本，MIT 开源，版本固定）。扫描完全离线运行，无需联网拉取规则。

- **更新规则**：`python tools/fetch_semgrep_rules.py`（幂等，已存在则跳过；需联网）
- **校验状态**：`python tools/fetch_semgrep_rules.py --check`
- 规则文件缺失时，工具层自动降级为在线拉取（并提示）。

### 8.8.2  启动相关

| 问题 | 原因 | 解决方案 |
|---|---|---|
| `ModuleNotFoundError: No module named 'app.launcher.bootstrap'` | 未在项目根目录下运行 | 确保 `cd` 到项目根目录后再执行启动脚本；Windows 启动脚本已内置自动切到根目录 |
| `pip install` 找不到依赖清单文件 | 当前目录不是项目根目录 | `cd` 到项目根目录后再安装 |
| `ModuleNotFoundError: No module named 'fastapi'`（或 chromadb / tree_sitter 等） | 依赖未安装 | 重新运行启动脚本（会自动安装），或手动安装依赖 |
| 启动器提示 Ollama 自动安装失败 | 包管理器不可用或网络问题 | 手动从 Ollama 官网下载安装，安装后重启终端再运行启动脚本 |
| 启动器提示 Ollama 已安装但不在 PATH 中 | 安装后 PATH 未刷新 | 重启终端；或手动将 Ollama 安装路径加入系统 PATH |
| 后端启动超时 | 端口 8765 被占用 | 检查端口占用并杀掉占用进程后重试 |
| Linux 上模型没统一到项目目录 | 系统级 ollama 服务仍用系统存储 | 执行一次 `sudo systemctl disable --now ollama`，再由启动器接管 |

### 8.8.3  模型相关

| 问题 | 原因 | 解决方案 |
|---|---|---|
| 模型下载超时或失败 | 网络不稳定或模型源不可达 | 手动重试拉取；若持续失败可改用回退模型 |
| 扫描结果全为"无法判定" | 模型未正确加载或输出格式不匹配 | 运行健康检查确认模型可用性；确认模型名与已安装的一致 |
| 推理速度极慢（> 60s/文件） | 无 GPU 回退到 CPU 推理 | 检查启动日志中的硬件检测行；CPU 模式约为 GPU 的 1/10 速度，属正常现象 |
| OOM（显存溢出） | 上下文窗口过大或显存不足 | 降低上下文窗口：设置环境变量 `VULN_SCANNER_NUM_CTX=4096` |
| 进程内后端报 DLL / 编译类错误 | 显卡架构缺少对应运行时 | 在 Linux 上运行，或改用默认 Ollama 后端 |

### 8.8.4  RAG / 向量库相关

| 问题 | 原因 | 解决方案 |
|---|---|---|
| `ModuleNotFoundError: No module named 'chromadb'` | 未安装 RAG 依赖 | 安装依赖清单中的 chromadb |
| RAG 扫描报错 `embedding model not found` | embedding 模型未缓存到本地 | 在有网络的环境执行一次模型下载（国内可用镜像） |
| RAG 检索结果明显不对 / 向量库为空 | 向量库未构建或由旧 embedding 模型构建 | 删除旧向量库目录后重建 |
| 自定义 embedding 缓存路径 | 默认缓存路径不可写 | 设置 `CHROMA_EMBEDDING_MODEL_PATH=/path/to/local/model` |

### 8.8.5  插件相关

| 问题 | 原因 | 解决方案 |
|---|---|---|
| VS Code 插件扫描无响应 | 后端未启动或地址不匹配 | 确认 `http://localhost:8765/api/health` 可访问；检查插件设置中的后端地址 |
| VS Code 插件请求超时 | 大文件推理耗时长 | 在设置中将请求超时调大（默认 300000ms = 5 分钟） |
| IntelliJ 插件编译失败 | JDK 版本低于 17 或构建同步失败 | 确认 JDK 17+；在 IDEA 中重新同步构建 |
| IntelliJ 插件通知不弹出 | 后端地址不匹配 | 修改插件源码中的后端地址常量后重新构建 |

### 8.8.6  IDE 报红（不影响运行）

| 问题 | 原因 | 解决方案 |
|---|---|---|
| IDE 中大量红色错误标记 | Python 解释器选错、依赖未安装、模块路径未配置 | 1. 选择正确的 Python 解释器；2. 在项目根目录安装项目包；3. 在 IDE 配置中把项目根目录加入分析路径 |
| 类型检查器报类型不匹配 | 严格模式误报 | 不影响运行，可调整类型检查严格度 |

## 8.9  目录结构

```
软件根目录/
├── app/                        # 软件本体
│   ├── backend/                #   FastAPI 后端（REST API + 两阶段扫描引擎）
│   ├── launcher/               #   跨平台启动器（一键启动 + 依赖自动安装）
│   ├── vscode-extension/       #   VS Code 插件源码
│   └── intellij-extension/     #   IntelliJ 插件源码
├── releases/                   # 插件安装包（vsix / zip）
├── models/
│   └── semgrep_rules/          # 本地化 Semgrep 规则（离线可用）
├── graduation_project/         # 核心 Python 包（扫描引擎 / schema / prompts）
├── data/                       # 本地运行数据（向量库等）
├── docs/                       # 用户手册等文档
├── requirements.txt
├── uninstall.py / uninstall_windows.bat / uninstall.sh
└── README.md
```
