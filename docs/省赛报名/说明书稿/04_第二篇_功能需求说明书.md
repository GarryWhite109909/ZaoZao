## 2.2  三大核心任务

> 素材：`docs/用户手册.md` §3

### 2.2.1  任务 A：扫描一段代码或一个文件

1. 打开 `http://localhost:8765` → 进入**扫描工作台**；
2. 「粘贴代码」标签 → 选语言 → 粘贴代码 → 点「开始分析」；或「上传文件」标签 → 拖入一个或多个代码文件；
3. 等待十几秒（单文件典型 5~15 秒，长文件更久），结果区给出：是否漏洞、CWE 类型、风险等级、漏洞原理说明、修复建议。

### 2.2.2  任务 B：批量扫描一个项目并导出报告

1. 扫描工作台 →「上传文件」→ 一次拖入整个模块的代码文件（最多 200 个）；
2. 点「开始分析」，页面实时显示进度（扫完一个出一个）；
3. 完成后点「**下载报告**」，得到一份 Markdown 报告：漏洞汇总表 + 每个文件的详细结果 + 修复建议。

### 2.2.3  任务 C：扫描 GitHub 仓库或网页

- 「GitHub」标签 → 粘贴仓库地址 → 设置最多扫描文件数（默认 20，大仓库建议自己限定）→ 开始。系统浅克隆仓库（只读、120 秒超时、扫完即删，不在用户机器上留下仓库副本）；
- 「URL」标签 → 输入网页地址 → 系统抓取页面里的脚本代码逐个分析。

## 2.3  扫描结果与判定语义

> 素材：`docs/用户手册.md` §4

### 2.3.1  三种判定

| 判定 | 含义 | 用户应当做什么 |
|---|---|---|
| **发现漏洞** | 系统确信存在漏洞（模型多次采样一致 + 通过证据校验） | 按修复建议处理 |
| **安全** | 未发现问题（工具没召回可疑点，且全文件复核也没发现） | 常规流程即可 |
| **需人工复核** | 系统有怀疑但证据不足，**故意不替用户下结论** | 花一分钟看一眼标注位置 |

> **「需人工复核」不是出错，是设计**：本系统的原则是"宁可多一道人工复核，也不漏报真漏洞、不错杀不确定的判定"。复核结果单列，不计入安全评分。

### 2.3.2  每条结果包含的字段

- **CWE 类型**：漏洞编号与名称（如 CWE-89 SQL 注入）；
- **风险等级**：Critical / High / Medium / Low；
- **Source & Sink**：污点数据的来源行与触发行（有数据流的漏洞才显示），配合编辑器插件可直达代码行；
- **漏洞说明**：自然语言解释"为什么这是漏洞"；
- **修复建议**：行号锚定的局部修复建议；
- **模型原始输出**：可折叠查看，用于核对。

### 2.3.3  安全评分

系统按 Critical 每项 -8 / High -8 / Medium -4 / Low -2 / Info -0.5 累计扣分给出安全评分；"需人工复核"的样本单列展示，不参与扣分。

### 2.3.4  与传统工具结果差异的说明

三个常见原因，均属正常：

1. **它把"安全写法"放行了**：参数化查询、`subprocess` 列表参数、`shlex.quote` 等有效防御会被识别，不再像规则工具那样照报误报；
2. **它报了规则工具不报的**：需要理解数据流 / 业务语义的漏洞（认证缺失、信任边界绕过等），规则工具天然覆盖不到；
3. **它给出"需人工复核"而不是硬判**：低置信判定会被送人工复核，而不是随机选边。

## 2.4  Web 界面功能需求

### 2.4.1  四种扫描输入方式

| 输入方式 | 交互 | 说明 |
|---|---|---|
| 粘贴代码 | 选语言下拉框 + 文本框 | Python / JavaScript / TypeScript / Java / PHP / Go / HTML |
| 上传文件 | 拖拽或点击选择，支持多文件 | 批量时显示实时进度条，完成后可下载 Markdown 报告 |
| URL 扫描 | 输入目标站点 URL | 自动抓取页面 `<script>` 内容逐个扫描 |
| GitHub 仓库 | 输入仓库地址 + 最大文件数 | 浅克隆 → 遍历 → 批量扫描 |

### 2.4.2  高级选项

| 选项 | 说明 |
|---|---|
| 多模型投票 | 勾选后选择 ≥2 个模型，系统顺序加载各模型并投票聚合结果（更准但更慢） |
| 两阶段扫描 | 系统**唯一**扫描路径（工具召回 + LLM 自一致率裁决），无需勾选即生效；该开关仅控制下方采样数设置是否可调 |
| 自一致率采样数 | 两阶段 LLM 裁决的采样次数（1~10，默认 3）。采样越多越准、越慢 |

> 外部工具（Bandit / Semgrep / Gitleaks / Trivy）已内置于两阶段 Stage 1 工具召回，无需单独勾选：密钥（secret）与依赖漏洞（SCA）类发现由确定性工具直接报告，SAST / IaC 类发现进入 LLM 裁决层判定真伪。

## 2.6  命令行功能需求

> 素材来源：用户手册 §9 与项目 README 的命令行章节（改编时已去除文档间链接）。

| 命令 | 功能 |
|---|---|
| `health` | 健康检查（模型/服务是否可用） |
| `scan <file>` | 扫描单个文件 |
| `batch <dir>` | 批量扫描目录下所有代码文件 |
| `url <url>` | 扫描 URL 抓取的脚本 |
| `github <repo>` | 扫描 GitHub 仓库（浅克隆） |

**全局参数**：`--model`（切换模型）、`--ollama-url`、`--rag`（知识库）、`--format text|json`、`--output`。

**特点**：直接复用扫描引擎，**无需启动后端服务**；扫描失败时退出码为 1，适合接入 CI 或脚本化批量检查。

## 2.7  模型管理与离线能力

> 素材：`docs/用户手册.md` §10

- **完全离线运行**：联网只是首次下载依赖和模型时需要。系统运行期不访问外网（HuggingFace 强制离线模式、Semgrep 规则已随软件本地化）；
- **换 / 加模型**：Web 界面右上角模型管理抽屉可拉取、删除、切换模型（带实时下载进度）；命令行方式：`--model <模型名>` 或环境变量 `VULN_SCANNER_MODEL`；
- **两档模型形态**（界面会显示当前形态）：
  - 发布模型 v9max（Ollama，约 4.7GB，兼容性最好）；
  - 高精度形态（Transformers + LoRA）——启动器检测到本机环境可运行时自动启用；跑不动会自动回退并打印说明；
- **国内网络**：依赖走国内镜像、模型走 HF 镜像，支持断点续传与断流自动换源，一般无需手动配置代理。

## 2.8  非功能需求

> 素材：`docs/用户手册.md` §6、§12

### 2.8.1  输入限制与支持范围

| 项目 | 限制 |
|---|---|
| 代码语言 | Python / JavaScript / TypeScript / Java / PHP / Go / HTML |
| 文件类型 | `.py` `.js` `.ts` `.jsx` `.tsx` `.java` `.php` `.go` `.html` `.htm` `.vue` `.svelte` |
| 单段代码 | 最多 200 万字符 |
| 单文件 | 最大 2 MB |
| 单次批量 | 最多 200 个文件、总计 10 MB |
| GitHub 扫描 | 浅克隆 + 120 秒超时 + 文件数上限（默认 20，可调，硬上限 50） |

超限会被前端直接拦截提示（后端再做一道同样的校验，返回 413），不会让用户白等。

### 2.8.2  性能预期

| 场景 | 预期 |
|---|---|
| 单文件扫描 | 典型 5~15 秒；长文件（自动切片后逐段分析）可能到分钟级 |
| 批量扫描 | 逐文件流式返回，页面实时显示进度 |
| 启动 | 首次需下载依赖与模型（取决于网速）；此后通常 10 秒内完成 |
| 无 GPU | 自动回退 CPU 推理，速度约为 GPU 的 1/10~1/20 |

### 2.8.3  兼容性需求

| 条件 | 要求 |
|---|---|
| 操作系统 | Windows 10+ / Linux / macOS |
| Python | 3.10+ |
| 磁盘空间 | ≥ 8 GB（建议 15 GB） |
| 内存 | ≥ 8 GB（建议 16 GB） |
| 显卡（可选） | NVIDIA / AMD(ROCm) / Apple Silicon ≥ 4 GB；可无 GPU |

### 2.8.4  隐私与安全需求

- **全离线**：代码、模型、知识库全部留在本机，运行期不联网；
- **无数据外传**：扫描内容不上传任何第三方服务；
- **URL 抓取的自我防护**：仅允许 http/https 协议，拦截内网/回环/链路本地/保留地址，缓解 DNS rebinding，逐跳校验重定向（最多 5 跳），响应体流式读取并限制大小。

### 2.8.5  已知能力边界（如实声明）

1. **速度**：语义分析的成本是时间——定位是"审计增强"，不是秒级 lint；
2. **"需人工复核"会占一定比例**：系统对没有确定性证据的判定选择保守（宁可交给人）。这是防漏报、防误判的设计代价，不是故障；
3. **两类漏洞是弱项**：① 跨文件的复杂攻击路径（只扫单文件时看不到全局数据流）；② "缺失型"漏洞（认证缺失、CSRF、竞态等"该有而没有"的问题）——此类没有确定性校验手段，置信不足时都会转人工复核；
4. **两档部署形态精度不同**：高精度形态（Transformers + LoRA）优于发布模型（Ollama 量化形态）。界面会如实显示当前用哪一档；
5. **结论是辅助，不是法律**：所有"安全"判定都建议结合业务上下文理解——系统能看懂代码语义，但看不懂未写出来的需求约束。
