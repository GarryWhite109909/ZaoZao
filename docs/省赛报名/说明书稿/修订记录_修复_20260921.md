## 七、补充轮:§8.2.2 模型存储表述核对（2026-09-21 深夜,响应"8.2.2 是否与实际不符"疑问）

对照 `app/launcher/start_windows.bat` / `start_linux_macos.sh` / `bootstrap.py` 逐条核实后的结论与修正:

**代码事实（用户的理解正确）**：四种后端 × 三平台的模型存储确实都锁定在项目目录——Ollama → `models/ollama`（启动脚本设 `OLLAMA_MODELS`）、Transformers 基座 → `models/transformers/.hf_home`（经 `HF_HOME`）、llama.cpp → `models/llamacpp`（自动探测/设置页下载）、vLLM → `models/vllm`；首次启动还会把 `~/.ollama/models` 等旧位置的模型**剪切迁移**进项目目录。

**为什么 §8.2.2 单提 Linux + Ollama**：Ollama 是唯一以独立系统服务形态运行的后端。Linux 官方安装注册 systemd 服务（自启、用 `/usr/share/ollama` 系统存储、占 11434），服务属系统用户——启动器无权限停止（`pkill` 后 systemd 自动重启），故需人工 `disable --now` 一次；其余后端/平台只靠启动器注入环境变量即可锁定，Windows 桌面版的"杀后自重启抢占端口"由启动器内置的结束托盘 + 重试接管。

**据此修正三处不实/不完整表述**：
1. §8.2.1 步骤 2：后端清单补上 Linux 菜单里实际存在的实验性 vLLM（Windows/macOS 隐藏）；
2. §8.2.1 步骤 6 拆成两条：原把「拉取失败回退 Qwen3-8B」与「探测到 adapter 自动采用 Transformers」写成一个时序，实际后者是默认后端解析规则（拉取前即生效）；并补上此前遗漏的**旧模型剪切迁移**行为；
3. §8.2.2 重写：补齐"为什么只有 Linux+Ollama 要手动"的结构性原因（其他后端无独立服务；systemd 属系统用户、自动重启）、`/usr/share/ollama` 具体路径、启动器先自动接管失败才需手动的次序、Windows 桌面版自重启的重试接管。

**连带一致性**：§8.3 手动启动补提示（绕过启动器时 `OLLAMA_MODELS` 未设置,模型会落到 `~/.ollama`,附与启动器一致的设置命令）；第五篇 §5.2.5 基座行精确到 `models/transformers/.hf_home`。

**构建脚本健壮性**：`build_typst_channel.py` 合并封面改为「先写临时名再替换」,v3.pdf 被阅读器占用时产物保留为 `说明书_最终_待编号_v3.tmp.pdf`,不再构建失败。
