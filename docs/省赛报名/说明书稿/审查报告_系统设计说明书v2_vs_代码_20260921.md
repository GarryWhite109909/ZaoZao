## 八、代码与注释问题（附修复建议）

> 均与本次审查交叉验证时发现，**未改动**。按严重度排序。

### C-1 `_CONF_MANUAL` 是死常量，且注释描述的三档阈值与实现不符 ★建议修

- 位置：`graduation_project/two_stage_scanner.py:240-242`
- 现状：

  ```
  240  # 置信度阈值：≥0.8 自动结论；0.5~0.8 结论但标记复核；<0.5 或平票→reviewer
  241  _CONF_AUTO = 0.8
  242  _CONF_MANUAL = 0.5
  ```

- 取证：全仓引用 `_CONF_AUTO` 的有 `:1492`（共形集接管）、`:2726/:2731`（reviewer 判定）、`:3213`（`strong_confirmed`）、`:3246`（注释）、`:3205`（注释）；**`_CONF_MANUAL` 除第 242 行定义外零引用**。
- 影响：注释读起来像「0.5 是显式路由阈值」，实际 0.5~0.8 档是由 `valid_votes` 与平票逻辑**隐式**产生的（`:2983-3002`）。任何人按注释去改 0.5 都会改到一个没人读的常量——这正是说明书 4.2「四档位」表述容易被追问的点。
- 建议（二选一）：
  1. 删掉 `_CONF_MANUAL`，注释改为「≥0.8 直接采信；其余（含 0.5~0.8 与平票）进人工复核清单」；
  2. 若要保留三档语义，把它真正接进路由，例如在 `_adjudicate_all` 里加 `elif verdict.confidence >= _CONF_MANUAL: reviewer(level="low_conf")`，并补一条单测锁住「0.5 边界进 reviewer」。

### C-2 直出档裁决的票数与 `n_samples` 不满足不变量 ★建议修

- 位置：`graduation_project/two_stage_scanner.py:2741-2757`（`_direct_adjudication`）
- 现状：`votes_true=1, votes_false=0, votes_invalid=0` 硬编码，docstring 自称「等价于高置信确认」；而生产 `n_samples=3`（`main.py:118`）。
- 影响：当前**不会**出错（直出档不进 `signal_registry.record()`，`valid_votes == self.n_samples` 的全票判定只对裁决档生效）。但 `AdjudicationVerdict` 隐含「票数之和 = N」这一不变量已被破坏；将来若把直出档纳入全票门槛或统计门（文档 4.3 已写「确定性工具直出档免疫模型意见」，容易被延续成「也走统计门」），会静默按 1/3 计算而判错。
- 建议：`votes_true=self.n_samples`，并给 `AdjudicationVerdict` 加 `deterministic: bool = False` 字段，在 `_aggregate` 与 `record()` 前置显式短路，把「直出档不参与统计门」从约定变成代码。

### C-3 生产组态注释只写了单文件路径，漏了批量的 targeted 覆盖 ★建议修

- 位置：`app/backend/main.py:106-111`
- 现状：注释断言「组态对齐论文 fixed5：`no_candidate_mode=full_recheck`」；但 `_scan_files_scheduled`（`:1213`）用 `BATCH_NO_CANDIDATE_MODE`（`:244-245`，默认 `"targeted"`）覆盖了 URL / GitHub / 工作区三条批量路径。
- 影响：同一份代码有**两种生产组态**，注释只承认一种；说明书 4.4 因此写成「无候选文件全量复核（生产默认组态）」，而仓库扫描实际走三档定向复核。
- 建议：注释补一行「批量/仓库/URL 路径由 `BATCH_NO_CANDIDATE_MODE` 覆盖为 `targeted`（三档定向复核，见 `:239-245`）；可用 `VULN_SCANNER_BATCH_RECHECK_MODE=full_recheck` 回退做 A/B。」说明书 4.4 同步把三个出口写成「全量复核（交互式默认）/ 10% 抽样（评估可选）/ 裁决全否决兜底」**之外**再加「三档定向复核（批量默认）」——目前文档完全没提 targeted，这是漏掉一个已上生产的设计。

### C-4 `COLLECT_HARD_CAP_FILES` 与 `max_files` 的上界是一句注释在维系 ★可选

- 位置：`main.py:233-237`（注释「上限须远大于 max_files（默认 50）」）与 `:278`（`max_files: Field(50, ge=1, le=500)`）
- 影响：这是一条**没有代码承载的不变量**——`COLLECT_HARD_CAP_FILES=3000` 与 `le=500` 之间没有任何断言。把 `le` 调到 3000 以上，遍历阶段的「按风险分排序取前 N」会退化成文档里明确批评过的「按 `os.walk` 顺序截断」，而且没有任何测试会红。
- 建议：声明一个模块级常量并在导入期断言，例如

  ```python
  MAX_SCAN_FILES_CEILING = 500          # 请求层上界
  assert COLLECT_HARD_CAP_FILES > MAX_SCAN_FILES_CEILING * 5, "收集上限须远大于扫描预算"
  ```

  并把 `Field(50, ge=1, le=MAX_SCAN_FILES_CEILING)` 与之绑定。

### C-5 证据门的语言白名单没有写进 docstring 的能力声明 ★可选

- 位置：`two_stage_scanner.py:1547`：`verifiable = language in {"python","py","javascript","js","typescript","ts"}`

### C-6 文档生成链路无版本留痕 ★建议补
