## 3. 当前最佳结果

### 3.1 系统级最新结果：两阶段架构 fixed5（2026-08-18，论文主数据）

**两阶段架构**（Stage 1 工具召回 + Stage 2 LLM 裁决 + 共形/反事实门控 + 信号回填），模型 Nivis-α0.5，裁决式 prompt，87 段测试集，干净评估环境（`--no-signal-feedback`）：

| 配置 | recall（不含 review） | FPR | accuracy |
|---|---|---|---|
| 纯 LLM（对照） | 0.967 | 0.154 | 0.931 |
| 工具链 fixed3（历史，带污染） | 0.982 | 0.167 | 0.862 |
| **工具链 fixed5（当前）** | **1.000** | **0.043** | **0.862** |

- 明细：TP=53 FN=0 TN=22 FP=1，review 11；唯一 FP 为 CWE-441 缺失型漏洞（无确定性校验手段，论文写局限）
- 工具层提示质量审计（A-E 五指标）：召回覆盖率 59.0% / 到点率 86.1% / 误导率 14.3%
- 详见 `docs/方法论_工具模型自适应闭环.md` §13.1b 与 `docs/过程.md` 2026-08-18 节

### 3.2 已发布模型：v9max（2026-08-07）

**v9max**（Qwen3-8B + 双模型蒸馏 7692 条 + 云端 A800 bf16 LoRA r=8 + rsLoRA，Q4_K_M 量化发布）。

**数据**：`train_chatml_v5_clean.jsonl`（749 条），已清洗 100 条训练-测试泄漏样本并新增 10 条弱密码学样本。

## 4. 核心发现

1. **数据可信度比指标绝对值更重要**：v4 因训练-测试泄漏产生漂亮但不可信的指标，已废弃；v5 清洗后才成为首个可信基线。
2. **CoT 清单化会损害真实 CVE 泛化**：v3 在合成集上表现更好，但 CVE-fix recall 回退，因为模型学会了逐项排除清单，对非标准模式迟钝。
3. **简单 hard-negative 得不偿失**：v6 为降 FPR 追加 FP 正确拒绝 CoT，反而牺牲 recall 与 CVE-fix 泛化，已归档。
4. **DPO 在 16GB 消费级 GPU 上不可行**：8bit 量化 OOM，4bit 量化梯度失效，需在 24GB+ GPU 或云实例上复用已准备的偏好对数据。
5. **"按漏洞类型补规则"是死路，工具与模型应互为喂养**（exp_07，2026-08-13）：16 个工具盲区（无 source 型漏洞）纯 LLM 判对 15/16——工具负责确定性召回与证据链，LLM 负责语义兜底，裁决置信回填形成自适应闭环（ISAM 类比）。
6. **工具链收益在 FPR 与 strict，recall 靠 LLM**：2.5 代架构（共形 + 反事实门控）在 α0 上 FPR 0.154→0.105（-32%）；fixed5 将 FPR 压到 0.043 且 recall 1.000。
7. **训练 prompt ≠ 推理最优 prompt**：v9max 与 α0.5 均验证 combined 变体推理最优（训练 prompt 直接用于推理会掉点），推理 prompt 必须独立消融。
8. **评估方法学陷阱本身就是论文素材**：抑制池跨跑污染、in-sample 共形校准泄漏、文件名泄漏、测试集反向拟合=答案泄漏——每项都有实证数据支撑。

## 5. 待决策事项

> v5 时代的三项决策（云 GPU DPO / FP micro-finetune / 停止微调）已被后续进展取代：v9max 发布、两阶段架构达标后，当前决策点如下。

| 选项 | 描述 | 风险/成本 |
|---|---|---|
| A. Nivis-α1 DPO（云端） | 用模型真实错误推理构造偏好对，收敛剩余 FPR 与"防御误判" | 需云实例；rejected 数据质量是关键 |
| B. 数据飞轮 + 防御机制教学 CoT | 补"为什么安全"的教学数据，根治"模式匹配 > 深度理解" | 数据工作量大 |
