## 1. 这是什么，适合谁

Nivis 是一套**在你自己电脑上运行**的 AI 代码漏洞扫描系统：传统安全工具（Semgrep、Bandit
等）负责快速找出可疑点，本地大语言模型再对每个可疑点做语义判断——它是不是真漏洞、
属于哪类 CWE、怎么修。

**适合的场景**：

| 场景 | 怎么用 |
|---|---|
| 交代码前自查一段"拿不准安全不安全"的逻辑 | Web 界面粘贴代码（任务 A） |
| 提交 / 发布前把整个项目过一遍 | 批量扫描 + 导出 Markdown 报告（任务 B） |
| 评估一个开源仓库能不能引入 | GitHub 仓库扫描（任务 C） |
| 写代码时随手查当前文件 | VS Code / IntelliJ 插件 |

**一句话定位**：它比规则工具"懂语义"（能看懂数据流、识别有效防御、解释漏洞原理），
比云端服务"更私密"（代码、模型、知识库全部留在本机，运行可完全离线）。

## 2. 安装与首次启动

### 2.1 硬件与系统要求

| 项目 | 最低 | 建议 |
|---|---|---|
| 操作系统 | Windows 10+ / Linux / macOS | — |
| Python | 3.10+（启动脚本自动检测） | — |
| 磁盘 | 8 GB（模型约 5 GB + 依赖约 2 GB） | 15 GB |
| 内存 | 8 GB | 16 GB |
| 显卡 | 可无（自动回退 CPU，慢 10~20 倍） | NVIDIA/AMD/Apple ≥ 4 GB 显存 |

### 2.2 一键启动

```bash
git clone <repo-url> && cd Graduation-Project

# Windows：双击
app\launcher\start_windows.bat

# Linux / macOS
bash app/launcher/start_linux_macos.sh
```

### 2.3 首次启动会发生什么（全自动，你只需要等）

1. 安装 Python 依赖（国内自动走清华镜像）；
2. 自动选择推理后端：检测到本项目自带的 LoRA 模型且显卡支持 → 用高精度形态；否则用
   Ollama 兼容形态（首次自动安装 Ollama）；
3. 下载扫描模型（约 5 GB）；
4. 安装传统安全工具（Bandit / Semgrep / Gitleaks / Trivy / pip-audit / detect-secrets，
   缺哪个跳过哪个，不影响运行）；
5. 启动服务并自动打开浏览器 `http://localhost:8765`。

> 首次启动耗时取决于网速（主要是下载模型）。**之后每次启动通常 10 秒内完成。**
> 启动器会锁定模型存储到项目目录 `models/`，不会把你的 C 盘 / 家目录塞满。

### 2.4 确认装好了

浏览器打开 `http://localhost:8765`，看到欢迎页 / 仪表盘即成功。也可在终端验证：

```bash
python -m app.launcher.vuln_scanner_cli health
```

## 3. 三个最常用的任务（5 分钟上手）

### 任务 A：扫一段代码 / 一个文件

1. 打开 `http://localhost:8765` → 进入**扫描工作台**；
2. 「粘贴代码」标签 → 选语言 → 粘贴代码 → 点「开始分析」；
   或者「上传文件」标签 → 拖入一个或多个代码文件；
3. 等待十几秒（单文件典型 5~15 秒，长文件更久），结果区给出：是否漏洞、CWE 类型、
   风险等级、漏洞原理说明、修复建议。

### 任务 B：批量扫描一个项目并导出报告

1. 扫描工作台 →「上传文件」→ 一次拖入整个模块的代码文件（最多 200 个）；
2. 点「开始分析」，页面实时显示进度（扫完一个出一个）；
3. 完成后点「**下载报告**」，得到一份 Markdown 报告：漏洞汇总表 + 每个文件的
   详细结果 + 修复建议。

### 任务 C：扫描 GitHub 仓库 / 网页

- 「GitHub」标签 → 粘贴仓库地址 → 设置最多扫描文件数（默认 20，大仓库建议自己限定）
  → 开始。系统浅克隆仓库（只读、120 秒超时、扫完即删，不会在你机器上留下仓库副本）；
- 「URL」标签 → 输入网页地址 → 系统抓取页面里的脚本代码逐个分析。

## 4. 读懂扫描结果

### 4.1 三种判定，各有含义

| 判定 | 含义 | 你该做什么 |
|---|---|---|
| **发现漏洞** | 系统确信存在漏洞（模型多次采样一致 + 通过证据校验） | 按修复建议处理 |
| **安全** | 未发现问题（工具没召回可疑点，且全文件复核也没发现） | 常规流程即可 |
| **需人工复核** | 系统有怀疑但证据不足，**故意不替你下结论** | 花一分钟看一眼标注位置 |

> **"需人工复核"不是出错，是设计**：本系统的原则是"宁可多一道人工复核，也不漏报
> 真漏洞、不错杀不确定的判定"。复核结果会单列，不计入安全评分。

### 4.2 每条结果包含什么

- **CWE 类型**：漏洞编号与名称（如 CWE-89 SQL 注入）；
- **风险等级**：Critical / High / Medium / Low（影响安全评分扣分）；
- **Source & Sink**：污点数据的来源行与触发行（有数据流的漏洞才显示），配合编辑器
  插件可直达代码行；
- **漏洞说明**：自然语言解释"为什么这是漏洞"；
- **修复建议**：行号锚定的局部修复建议；
- **模型原始输出**：可折叠查看，用于核对。

### 4.3 安全评分

系统按 Critical 每项 -8 / High -8 / Medium -4 / Low -2 / Info -0.5 累计扣分给出安全评分；
"需人工复核"的样本单列展示，不参与扣分。

### 4.4 为什么结果可能和 Bandit / Semgrep 不一样

三个常见原因，都属正常：

1. **它把"安全写法"放行了**：参数化查询、`subprocess` 列表参数、`shlex.quote` 等有效防御
   会被识别，不再像规则工具那样照报误报；
2. **它报了规则工具不报的**：需要理解数据流 / 业务语义的漏洞（认证缺失、信任边界绕过等），
   规则工具天然覆盖不到；
3. **它给出"需人工复核"而不是硬判**：低置信判定会被送人工复核，而不是随机选边。

## 6. 输入限制与支持范围

| 项目 | 限制 |
|---|---|
| 代码语言 | Python / JavaScript / TypeScript / Java / PHP / Go / HTML |

| 单文件 | 最大 2 MB |
| 单次批量 | 最多 200 个文件、总计 10 MB |

超限会被前端直接拦截提示（后端再做一道同样的校验，返回 413），不会白等一场。

## 7. 高级功能

扫描工作台「高级选项」里：

| 功能 | 说明 | 建议 |
|---|---|---|
| **自一致率采样数** | 对每个可疑点让模型独立判 N 次（默认 3），票数一致才高置信出结论 | 追求速度降到 1~2；追求准确保持 3 |
| **多模型投票** | 选 ≥2 个模型分别扫描再投票聚合（更准、更慢） | 重要代码抽查时用 |
| **RAG 知识库** | 检索内置的漏洞知识注入判定过程，增强可解释性 | 默认关；开启后推理时间增加 <2% |

> 两阶段扫描（工具召回 + LLM 裁决）是系统的**唯一**扫描路径，无需也无法关闭——
> 你看到的每个"发现漏洞"结论背后，都有工具证据链 + 多次采样 + 证据校验三道关。
> 外部工具（Bandit / Semgrep / Gitleaks / Trivy）已内置在第一道关里，无需单独勾选。

## 8. 在编辑器里用（VS Code / IntelliJ 插件）

**前置**：后端服务已启动并保持运行（插件只是"遥控"后端，后端关了插件就不能用）。

### VS Code

1. 安装：VS Code → 扩展面板 → `⋯` → **从 VSIX 安装** → 选仓库里的
   `releases/vuln-scanner-1.2.1.vsix`；
2. 用法：打开代码文件 → 右键 →「AI 漏洞扫描: 分析当前文件」；结果在侧边面板展示，
   漏洞行会标**红色波浪线**（可配置关闭）；
3. 批量：命令面板（`Ctrl+Shift+P`）→「批量扫描工作区」；
4. 常用设置（搜 `vulnScanner`）：后端地址 `backendUrl`、保存时自动扫描
   `autoScanOnSave`、批量文件上限 `workspaceMaxFiles`。

### IntelliJ IDEA

1. 安装：`File → Settings → Plugins → ⚙ → Install Plugin from Disk...` → 选
   `releases/vuln-scanner-0.1.0.zip` → 重启；
2. 用法：编辑器中选中代码（不选则扫整个文件）→ 右键 → **AI 漏洞扫描**
   （或 `Ctrl+Shift+V`），结果以气球通知弹出。

> IntelliJ 版定位为演示版：无波浪线标记与批量扫描。完整差异见
> `app/intellij-extension/README.md`。

## 9. 命令行速查

无需打开网页，直接复用扫描引擎（**不需要**先启动后端服务）：

```bash
python -m app.launcher.vuln_scanner_cli <命令>

health                                    # 健康检查（模型/服务是否可用）
scan app/main.py                          # 扫单个文件
scan app/main.py --format json            # 输出 JSON（方便脚本处理）
batch ./src --output report.md            # 批量扫目录 + 导出报告
batch ./src --limit 20 --no-recursive     # 限量、不递归
url https://example.com                   # 扫网页脚本
github https://github.com/user/repo       # 扫 GitHub 仓库（浅克隆）
```

通用参数：`--model <模型名>` 切模型、`--rag` 开知识库、`--format text|json`。
适合接进 CI 或脚本里做提交前检查（扫描失败时退出码为 1）。

## 10. 离线使用与模型管理

- **完全离线运行**：联网只是首次下载依赖和模型时需要。系统运行期不访问外网
  （HuggingFace 强制离线模式、Semgrep 规则已随仓库本地化）；
- **换 / 加模型**：Web 界面右上角模型管理抽屉可拉取、删除、切换模型（带实时下载进度）；
  命令行方式见 [README「模型部署与版本管理」](../README.md#模型部署与版本管理)；
- **模型有两档精度**（界面会显示当前形态）：
  - 发布模型 v9max（Ollama，约 4.7GB，兼容性最好）；
  - 高精度形态（Transformers + LoRA，检出质量对应论文指标）——启动器检测到本项目
    自带模型且本机环境可运行时自动启用；跑不动会自动回退并打印说明；
- **国内网络**：依赖走清华镜像、模型走 HF 镜像，支持断点续传与断流自动换源，
  一般无需手动配置代理。

## 11. 常见问题 FAQ

| 问题 | 处理 |
|---|---|
| 扫描很慢（>60 秒/文件） | 大概率在用 CPU 推理。看启动日志 `[硬件检测]`；有独卡却走 CPU 时重启启动脚本，或显式设 `VULN_SCANNER_BACKEND=ollama` |
| 结果全是"需人工复核" | 模型可能没正确加载：`python -m app.launcher.vuln_scanner_cli health` 检查；确认模型名一致 |
| 报显存不足（OOM） | 降低上下文窗口：按 [README](../README.md#8gb-显存适配说明) 创建 4K 上下文版模型 |
| 启动报端口被占用 | `netstat -ano | findstr 8765`（Windows）/ `lsof -i :8765`（Linux/macOS）找到进程杀掉 |
| VS Code 插件没反应 | 确认后端已启动且 `http://localhost:8765/api/health` 能访问；核对插件设置 `vulnScanner.backendUrl` |
| 波浪线没显示 | 设置里 `vulnScanner.markDiagnostics` 需为 `true`；个别无法定位到行的情况只展示面板结果 |
| Linux 上模型没进项目目录 | 系统自带 ollama 服务抢占：执行一次 `sudo systemctl disable --now ollama` 再重启脚本 |
| RAG 相关报错 | 见 [README 故障排查 RAG 小节](../README.md#rag--向量库相关)（多为知识库未初始化或旧向量库需重建） |

更多排错条目见 [README「故障排查」](../README.md#故障排查)。

## 12. 已知边界（使用前请读一遍）

我们对能力边界持如实态度，以下是你应该知道的：

1. **速度**：语义分析的成本是时间——单文件典型 5~15 秒，长文件（自动切片后逐段分析）
   可能到分钟级。它定位是"审计增强"，不是秒级 lint；
2. **"需人工复核"会占一定比例**：系统对没有确定性证据的判定选择保守（宁可交给人）。
   这是防漏报、防误判的设计代价，不是故障；
3. **两类漏洞是弱项**：① 跨文件的复杂攻击路径（只扫单文件时看不到全局数据流）；
   ② "缺失型"漏洞（认证缺失、CSRF、竞态等"该有而没有"的问题）——此类没有确定性
   校验手段，置信不足时都会转人工复核；
4. **两档部署形态精度不同**：高精度形态（Transformers + LoRA）优于发布模型
   （Ollama Q4 量化）。界面会如实显示当前用哪一档；
5. **结论是辅助，不是法律**：所有"安全"判定都建议结合你的业务上下文理解——
   它能看懂代码语义，但看不懂你没写出来的需求约束。

## 13. 卸载

| 平台 | 操作 |
|---|---|
| Windows | 双击 `uninstall_windows.bat`（或 `python uninstall.py`） |
| Linux / macOS | `bash uninstall.sh`（或 `python3 uninstall.py`） |

常用参数：`--dry-run` 只列出将删内容不动手；`--keep-ollama` 保留 Ollama 与模型；
`--keep-project` 只清依赖不删项目文件夹。

⚠️ **必须用安装时的同一个 Python 环境运行卸载**（conda / venv 用户先激活原环境）。
外部安全工具（bandit / semgrep 等系统级安装）不会被自动删除，需要时手动卸载。
详见 [README「卸载」](../README.md#卸载)。
