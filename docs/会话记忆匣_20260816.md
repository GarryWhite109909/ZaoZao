## 十、工具提示质量审计结论（2026-08-16 21:40 追加）

**方法**：`/tmp/tool_hit_audit2.py` 遍历 87 段纯工具召回，按候选语义 vs expected CWE 比对。

**结论：工具层提示基本到点，无系统性误导。**
1. 61 个有候选样本中，约 25 个"不命中"是我的分组脚本误判（B608=SQL 被归 Command、django/flask.security 规则没识别为 XSS、SSTI 匹配 1336）——实际提示到点。
2. 真实的"提示不到点"仅 typical_10（CodeInj vs Command 近似）、typical_20（WeakCrypto vs 证书校验部分接近）——性质温和。
3. **关键**：大部分"不命中"是多漏洞单标注——工具提示 XSS/B105（真实次要漏洞），预期是认证缺失/IDOR/CSRF。模型确认次要漏洞 → loose recall 判对、strict 扣分。**这不是工具误导，是测试集只标一个漏洞**（与第五节发现呼应）。
4. 安全样本误报候选（safe_01/02/05/06/07/08、noise_*）靠模型裁决否决（P0 已修）——模型纠错工具，非误导。

## 十一、α0 vs α0.5 工具链差异根因（2026-08-17 关键结论）

**核心发现：α0 工具链的"全正提升"是配置巧合，不是普适规律。**

| 维度 | α0 | α0.5 |
|------|-----|------|
| 工具链裁决 system prompt | **combined_nosource（开放式，5056字，has_vulnerability）**——与训练 combined 同源同格式 | 之前 triage_*（is_confirmed 裁决式）→ 格式错位 0.676；triage_train_aligned 对齐后 10样本 6TP |
| 纯 LLM recall | 0.934（低基线，盲区多） | 0.967~0.984（高基线） |
| 工具链 recall | 0.966（**靠 trust_llm_recheck 兜底 8 个盲区**） | 裁决环节掉点（6/10） |
| 工具链 FPR | 0.154→0.105（共形+反事实） | 待测 |

**机理**：α0 的正提升 = trust_llm_recheck 捞盲区（recall +）+ 共形压 FPR，不是裁决质量好。α0.5 基线高、盲区被训练覆盖 → 兜底没东西捞 → 工具链只剩"裁决确认"环节 → N 采样投票+切片反而把模型确定判断搞漂移。

**推论**：工具链对"强模型" recall 是零和或负贡献；真正价值在 FPR 压制 + strict 类型校正 + 证据链。α0.5 的正确打开方式可能是**复用 α0 配置 `--variant combined`（开放式）**，先复现再优化，而非发明裁决式 prompt。
