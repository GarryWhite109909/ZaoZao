# 方法论：两级注意力预算 与 工具层盲区提醒

日期：2026-08-31　状态：已实现（待真实模型 A/B 验证）

---

## 一、要解决的问题

仓库/URL 批量扫描有两个独立但叠加的缺陷：

### 1.1 文件选择是"盲目截断"

`app/backend/main.py::_clone_and_collect` 原实现按 `os.walk` 顺序取前
`max_files`（默认 50）即 `break`。`os.walk` 顺序是目录名排序，大仓库里
`utils/`、`models/`、`dto/` 常常排在 `auth/`、`api/` 之前——**50 个名额被
低危文件吃光，高危文件压根没进扫描**。

实测（模拟仓库：50 utils + 20 dto + 1 auth，auth 排在遍历顺序最后）：

| 策略 | 前 10 个是否含 auth/session.py |
|---|---|
| 旧（顺序截断） | **否** |
| 新（风险分预算） | **是** |

此时讨论"每个文件复核多快"没有意义——复核再快也救不了没被选中的文件。
**这是本次改动中收益最大的一项，且是纯确定性的、零 LLM 成本。**

### 1.2 无候选复核的成本随仓库规模线性爆炸

`full_recheck` 对每个工具层零召回的文件都做 **全文件 × min(3,n) 票**。
大仓库里绝大多数文件是零召回的，预算几乎全花在零风险文件上。

---

## 二、方案：两级注意力预算

核心命题：**在固定算力预算下最大化召回，而不是均匀分配注意力。**

### 第一级：文件级——风险分排序 + 预算调度

`graduation_project/risk_budget.py`（纯确定性，无 LLM）：

- **打分维度**：路径语义（auth/api/payment/crypto/upload… 高危；tests/docs/
  examples 低危；config/models/dto 中低危）+ 内容形态（sink / 外部源 /
  入口点）+ 体量修正（极tiny/极大降权）。
- **知识来源**：语言习语级公开漏洞知识（OWASP 载体分布），**不从测试样本
  挖掘**——样本挖掘属于 `SignalRegistry.learn_pool` 通道（须经独立验证集
  审批转正），两者严格分离以防过拟合。
- **分配**：预算内按分降序选取；**未覆盖文件显式回报**（`BudgetPlan.uncovered`），
  绝不静默丢弃——与 `suppressed_by_registry` / `dropped_unowned` 的留痕原则
  同构：预算外文件也是"没扫到"的一种，必须可审计。
- **同构折叠**：结构指纹（剥离注释/空白/字符串/数字）相同的文件折叠为
  一个代表。

### 第二级：文件内——盲区定位 + 三档定向复核

`graduation_project/blind_spots.py` + `no_candidate_mode="targeted"`：

| 档 | 判据 | 送什么 | 票数 |
|---|---|---|---|
| **A** | 有盲区 且（风险分 ≥12 或高优先级盲区 ≥2） | 盲区片段 | `min(3, n)` |
| **B** | 有盲区但低危；**或零盲区但高风险分** | 片段/预筛块 | 1 |
| **C** | 零盲区 且 低风险分 | 不送 LLM | 0（按 `sampling_rate` 抽样） |

省时的两个来源：
1. C 档省掉整次调用（大仓库的主要收益）；
2. A/B 档把"整文件"换成"盲区片段"——自检实测 5575 → 285 字符（**5.1%**），
   模型从"读 1000 行找漏洞"变成"看几个带行号的 13 行片段判漏洞"。

### 实测（71 文件模拟仓库，fake client 计数）

```
[full_recheck] LLM 调用 = 216 次
[targeted]     LLM 调用 =  65 次      → -69.9%
召回侧：两种模式在越权（IDOR）样本上判真结果一致
```

## 三、三条硬约束（盲区提醒不可违反）

盲区提醒的语用地位是**提示**而非**判定**，三条约束缺一不可，否则就是
换皮的告警：

1. **不产生 finding**：不进 `findings`、不进裁决、不影响 `has_vulnerability`。
2. **永不进 SignalRegistry**：盲区被模型否定是**正常且高频**的（它本就是
   低置信提示），一旦允许回填抑制池，这套机制会在几轮扫描后自我清空——
   这是 §五之四（规则级抑制压没 `python-xss-taint` 全族）教训的直接推论。
3. **中性措辞**：统一"工具无法判定 X，请确认 X"，**绝不写"此处存在 XX 漏洞"**。
   `prompts._TRUST_NOTE_CHAIN` 已实证 prompt 里的信任标注会实质影响模型判断。

自检里有对应的守卫用例（措辞禁用词表、"请确认"覆盖率、抑制池零写入）。

## 四、实现过程中实证的五个坑（均已有回归用例）

1. **正则 `$` 绑定整个交替组**：`(A|B|C)$` 的 `$` 作用于整组而非最后一项，
   导致 `app/__init__.py` 在 `__init__\.` 分支匹配后仍剩 "py" 而整体失败。
   路径段边界由 `(^|/)` 已锚定，无需 `$`。
2. **测试目录的高危词是噪声**：`tests/test_auth.py` 因文件名含 "auth" 加分。
   现在命中低危路径时不再累加高危词。
3. **短文件密度分虚高**：8 行文件的"每百行 sink 密度"是 500 行文件的 12 倍。
   改为**绝对量 + 密度双通道**各封顶相加。
4. **越权代码几乎都是跨语句的**：`oid = request.args.get(...)` →
   `Order.query.get(oid)`，任何单行正则都无法关联两行（自检实测纯行级规则
   0 命中）。补了极轻量的单文件变量名流追踪（不识别消毒、不跨函数——那是
   TaintTracker 的职责）。
5. **"零盲区 = 不送 LLM" 会静默放行真实漏洞**（最重要）：

   | 漏洞形态 | 盲区命中 | 风险分 | 原设计档位 |
   |---|---|---|---|
   | SQL 注入（拼接） | 0 | 34.0 | C（不送 LLM）|
   | 命令注入 | 0 | 36.0 | C |
   | 路径穿越 | 0 | 34.0 | C |
   | XSS | 0 | 28.0 | C |
   | 越权（IDOR）| 1 | 28.0 | A |

   盲区表覆盖的是"工具**写不了**规则"的形态，而注入类是工具**本该召回**的
   形态——工具因规则不覆盖/语言不支持/新框架而零召回时，C 档会把它们静默
   放行。故加两道保险：
   - 风险分高（有外部源+sink+入口点 = 有实际攻击面）却零召回，是**工具失效
     的信号**，比"文件没内容"更值得复核 → 降 B 档；
   - C 档按 `sampling_rate`（默认 10%）抽样复核，在线估计"零盲区文件的漏报
     率"（复用 `sampled` 模式原有语义，非新增机制）。

   代价：省幅从 -74.4% 降到 -69.9%，换来的是不再有静默放行。

6. **折叠的保守性边界**：放宽数字归一化后（不加 `\b`，否则 `Dto19` 里的
   `19` 因前面是字母而不匹配，折叠失效），"仅字段名不同"的高分文件也会被
   折叠。故加 `FOLD_MAX_RISK_SCORE=0.0` 闸门：**有攻击面的文件永不折叠**。
   折叠的收益是算力、代价是潜在漏扫，这个交换只对零风险文件划算。

## 五、消融开关

| 开关 | 取值 | 用途 |
|---|---|---|
| `VULN_SCANNER_BATCH_RECHECK_MODE` | `targeted`（默认）/ `full_recheck` | 批量复核策略 A/B |
| `VULN_SCANNER_BLIND_SPOTS` | `1`（默认）/ `0` | 盲区提醒开/关（测 FP 影响）|
| `VULN_SCANNER_RECHECK_RATE` | `0.1`（默认） | C 档抽样率；设 0 完全关闭 |
| `use_blind_spots` 构造参数 | True/False | 同上（进程内）|
| `fold_duplicates` 请求字段 | True（默认） | 同构折叠（GitHub 扫描）|
| `max_scripts` 请求字段 | None（默认全扫） | URL 扫描的脚本预算 |

## 六、待验证（诚实列出边界）

1. **盲区提醒对 FP 率的影响未测**。它大概率会抬高判真率（这是 prompt 注入
   的固有风险）。必须用真实模型做开/关 A/B，测 FP 率与召回率变化。
2. **未覆盖文件未做兜底**：预算外的文件只是"显式回报"，没有第二次机会。
   真实仓库上应评估 `uncovered` 的实际占比是否合理。
3. **实测 71 文件的 110 秒几乎全来自 Stage 1 工具调用**（fake client 不计
   LLM 时间）。若目标部署的 LLM 延迟不高，省调用次数的收益比例会低于
   省时间比例——论文里应报告"LLM 调用次数"而非"端到端耗时"。
4. **盲区规则的覆盖度未做定量评估**：目前只有 8 类 20 条先验规则，未在大
   规模真实 CVE 上测过"零盲区文件里有多少真漏洞"（C 档抽样的监控数据正是
   为回答这个问题而保留的）。

## 七、论文可用的表述

- 两级注意力预算（文件级 + 文件内）可以作为一个独立贡献点：**在固定算力
  预算下最大化召回，而非均匀分配注意力**。
- 盲区提醒的语用定位（提示 ≠ 判定）是它与"再加一层规则"方案的本质区别，
  也是它不增加误报的原因。
- 可给出「每千行 token 成本 × 召回率」的帕累托曲线（三档 + 抽样率构成
  一组可调的工作点），比"我们加了个提示"更有说服力。
