# 差分对出题流水线 v2（2026-09-11）

> 目的：把"出题"从人工判断变成带门的机械流程。**人只拍板方向，机械正确性由流水线保证。**
> 所有结论均来自本项目实测文件，锚点逐条标注。

---

## 0. 一页结论

1. **wave1 的毒源不在蒸馏，在"取材 + 标注"两个自动环节**。抽检 3/3 是"标签错、蒸馏对"
   （`corpus/diffpair_wave1/results/_audit_result_vs_manifest_20260911.md` §五）。
2. **损耗不是"你出的烂题"**。v2_15→v2_17 净损耗 −136 行（1.34%），构成里 84% 是蒸馏管道
   缺陷与自动取材错配，只有约 1/4 勉强算"题面质量问题"，且那部分也是批处理产物而非判断题
   （`audit/build_v2_17_governance_20260909.py` 头注）。
3. **最大的结构性缺口：v2_17 至今一次都没训练过**。所有评测数字都来自 alpha05 / v9max
   （`audit/审查报告_弱点探测方法审计_20260830.md` L100 G1："alpha06 未开训，训后复测整环不存在"）。
   → **治理收益目前 0 验证**，这是先于一切的问题。
4. **方向是对的，但训练目标要改**：差分对不是教"有洞/无洞"，是教"判别边界"
   （pre-fix vs post-fix）。用 LLM 区分差分对 = 把最弱能力用在最难结构（LLM 最弱项
   pairwise discrimination，见 `.workbuddy/memory/MEMORY.md` 实测门方法论）。

## 2. 六道门（机械可执行定义）

### 门 A · 语义对齐（修复"取材"）
- **规则**：CVE 描述里的机制关键词，必须在被选中的 hunk 的**改动行**里命中。
- **反例（实测）**：00180 标签 CWE-77 / CVE-2026-30625（MCP server RCE），
  实际取材文件是 `upsonic/chat/cost_calculator.py`（纯数值计算，无命令执行面）。
  → CVE 根因文件 ≠ 取材文件。
- **实现**：一个 patch 常改多个文件 → 按"CVE 描述动词/对象 ↔ hunk 新增行"匹配度打分，
  取 top-1；匹配度低于阈值则**弃题不硬凑**。

### 门 B · 差分有效（已实现，需扩到全量）
- **规则**：patch 新增行中必须含**至少一条非注释有效行**。
- **已落地**：`_patch_audit_20260911.json`；8 包纯注释已隔离。
- **待做**：对 wave2 及后续所有批次默认执行。

### 门 C · 标签可证（修复"标注"）
- **规则**：`expected_cwe` 必须能在代码内数出**构成要件数 > 0**；
  要件 = 0 的标签降级为 `pending_lead`，**不许进训练标签**。
- **反例（实测）**：00006 标签 CWE-89，全文 `SELECT` 0 次、`FROM` 0 次、`db.` 0 次
  → 该标签在文件内不可能成立；蒸馏报的 CWE-476（补 `e.Parameter != nil` 检查）才对。
- **注意**：「因缺失而致的洞」（A 版缺的正是修复新增的那段代码）**不能**用要件计数反证，
  这类走门 D。

### 门 D · 独立真值（非循环）
- **三个可接受来源**：① patch 语义（修复点自证）② 运行实测（可判定子集，覆盖上限 59.5%）
  ③ NVD / GHSA / MITRE 官方口径。
- **禁止**：用 LLM 裁 LLM 生成的数据（同源循环，测的是一致性不是正确性）。

### 门 E · 防御证据（补 W2，FP 第一根因 44%）
- **规则**：负样本（判无洞）的监督目标必须包含**防御所在行号 + 为什么该防御有效**。
- **理由**：rolling_dev 25 条 FP 里 11 条（44%）是"防御未识别"，
  与"修复识别失败 16/20、翻转一致性 0.20"同源（`results/mining_stats_alpha05_20260825.md`）。
  只教"无洞"学不到为什么安全。

### 门 F · 闭环回流
- 出题 → 入库 → 训练 → `rolling_dev 50` 复测 → 错题回流成下一批题面。
- **当前断裂**：v2_17 从未训练，环路未闭。

## 5. 闭环与实验设计

- **v2_17（治理版，10022 行）先训一次**，拿 rolling_dev 50 的 strict / micro / FPR 作基线。

- 两段训练构成"先基础后真实 CVE"的**可测对照实验（论文 ablation）**。
- 防作弊纪律：wave1 与三套评测集 CVE 交集 = 0、seed 文件名交集 = 0
  （`_weakness_driven_plan_20260911.md` §六），改标不构成"对着测试集调参"。
