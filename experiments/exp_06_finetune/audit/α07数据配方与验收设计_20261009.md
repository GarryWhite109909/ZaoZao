## 4. §3.2 近邻对构建规则（修污染风险版）

1. **三集 FN 清单（附录 A ~30 例）只做形态规格，本身不进训据**——cvefix 源 CVE 即
   考卷、87 是招牌指标集、rolling_dev 是 held-out 纪律集，混入即不可比 + 一次性报废。
2. 按规格另挖**实例不相交**的其他 CVE（取对应修复 commit 的修复前代码），同一蒸馏
   管道，过防御反证门（§2-③）。
3. **入册门**：对 87/cvefix/rolling_dev 三集做词集 Jaccard/n-gram 查重，
   **≥0.3 一律进人工复核，零确认才入册**（判定 B 的 10010/10011/10023 就是这个门
   该拦而未拦的案例——门从本批起前移到组装时）。
4. 补样过程中三集样本只读不训；每次入库批次跑一次筛查脚本存档。

## 5. §3.3 裁决扩量批次（对型候选确认率 ≥0.85 的训据侧供给）

1. **存量种子**：判定 B 审计结论——可作模板 4/20，修复截断后 8/20，同源排除后上限
   11/20；**只认 7568-7593 波段 8 字段生产形态**。存量不合格行重写（不计入基数）。
2. **规模**：800~1500 行。其中单候选验证形态 ≥800（承接现有 96 行的形态，规模化）；
   **原生多候选 schema ≥200**：user = 切片 + 候选列表（rule_id/类型/锚点，对型错型
   混合），assistant = 逐候选 `is_confirmed` + 理由 + 文件级 verdict——与生产
   `adjudications[].confirmed/votes` 同构（prompts.py:224/:844 的 schema 脱节欠账在此
   补回）。
3. **正反例双方向**：应确认与应否决都按 0824 报告 ②b 设计；反例必须显式教排除理由
   （毒数据教训，不是只标 false）。
4. **反哺通道**：§1.2 的 `recheck_ticket`（adjudication_ticket_v1）人工裁决结果直接
   进本批次——运维工单即训据原料。
5. 来源与 §3/§4 共用管道；每批过封闭式论证率门禁与簇审计门。
