### 二补记：「13.8% 编译失败」是假象，已撤回（2026-09-09 复核）

上一轮把 47 条编译失败当作「训练集里有编译不过的代码，是毒源」。重编验证后**该结论不成立**：

| 真实原因 | 条数 | 性质 |
|---|---:|---|
| 补 `stdlib/string/stdint/time/stdio` 后即通过（**样本省略 include**）| 16 | 轻微不完整，非错误 |
| POSIX/第三方头在 Windows 不存在：`sys/socket.h` `syslog.h` `sys/mman.h` `openssl/evp.h` | 12 | **平台差异，代码本身没错** |
| POSIX-only 函数：`ntohs` `getuid` `lstat` `fchmod` `O_NOFOLLOW`；`mkdir` 双参数 | ~18 | **平台差异** |
| **真·代码缺陷** | **1**（line 5613）| 见下 |

**语法错误 = 0 条。** 真实缺陷率 ≈ **1/340 = 0.3%**，不是 13.8%。

唯一真缺陷 line 5613（标签 safe）里有一行 `memset(env_key_copy, 0, buf_size);`，
且自带注释 `/* 注意：此处为示意，实际应操作 buf */` —— **模型蒸馏出了「自认占位的示意代码」**：
既不真实、也不编译、还带着自我免责注释。这才是蒸馏产物的真风险，值得单独做一类检测（搜「示意/示例/省略」类注释）。

> 教训：**跑不动 ≠ 代码错。跨平台 harness 的假阳性必须先剥离，否则会把平台差异当成数据缺陷写进论文。**
按此外推，把 Python/JS/Go 全量 L0 跑完（约 4200 条），预期翻案量在 30~40 条量级——而成本是三套 harness + shim。

## 四、必须记录的一次自我证伪

初算「簇内 has_vuln 冲突」= **573 组 / 1439 行**，看着像发现了 14% 的错标率。
**抽查 4 组后，这个假设被推翻**——它们几乎全是刻意设计的差分对：

| 簇 | 成员 | 真相 |
|---|---|---|
| java 8 行 | 2275 `csrf().disable()` → true/CWE-352；6159 `csrf(CookieCsrfTokenRepository)` → false | **标准 vuln/safe 正负对**，正是方法论 §2.1 要的主力数据 |
| python 26 行 | 1792 / 1858 / 1932 同为 `/search` 路由 SQL 拼接，写法分别为 `+` / `%` / 加 before_request | 同一漏洞的**等价写法变体**，都是 true |
| python 11 行 | 1817 不重生成 session（CWE-384）；1898 `permanent=True`（CWE-613）| 同骨架、两种不同漏洞，都是 true |
| dockerfile 19 行 | 1223 含硬编码凭证 → true；2995 同骨架无凭证 → false | 差分对 |

**教训：近重复 ≠ 错标。Jaccard 0.5 会把差分对和变体簇全兜进来，用它当错标挖掘机是方向性错误。**

我又用 token 级危险/防御正则做了自动分诊，同样失败——
`http.csrf().disable()` 被"防御"正则命中（含 `csrf(`），参数化 `cursor.execute("%s", (x,))` 被"注入"正则命中。
**token 级启发式的误报率高到不可行动**，这条和项目里 g26 verify 过严误报是同一个坑。

## 五、方案重排（建议的优先级）

### P0 — 把实测门改成「测量工具」（最高 ROI，建议立刻做）

不再追求翻案条数，改为**估计总体错标率**：

1. 已生成分层抽样清单 **`实测门_分层抽样清单_20260909.csv`（459 条 / 30 层 / 4.52%）**，
   按 语言×has_vuln 分层，主流语言的 vuln 侧加密 1.6×。
2. 这 459 条跑 L0 + L1（敌意输入 harness，人工精读），逐条给出 verdict + basis。
3. 按层权重回推全库 → **得到带置信区间的标签噪声估计**。

**为什么这比多修 50 条值钱**：论文里能写「用独立于模型论证的运行实测估计数据集标签噪声 = X%±Y」，
是可辩护的方法论贡献；而修 50 条样本对 10151 条的总量只是 0.5%，且不改变任何结论。

### P1 — 静态 oracle 全量交叉（覆盖 95%，但必须先校准）

semgrep（项目已有 5 套 taint 规则 + owasp-top-ten）+ hadolint + shellcheck + checkov 全量扫一遍，
产出「机器判定 vs 人工标签」分歧表。**但不要直接按分歧删样本**——
先在 P0 的 459 条上测出每个 oracle 的 precision/recall，才能把全量分歧数换算成错标率。
这是「弱监督 + 校准」的标准做法，也是唯一能把成本压到全量的路。

### P2 — 冗余/多样性治理（22.38% 那条线的正解）

2272 行落在 917 个近重复簇里，**这不是错标，是独立性不足**：
- 风险：评测集若混入同簇样本 → 指标虚高；训练侧 → 对少数骨架过拟合
- 处置：**簇内配额上限**（方法论 §2.3 的 G6 已有，但只在入库门，没回溯清存量）
- 顺带产出论文指标：**有效独立样本数 = 10151 − 簇内冗余**

### P3 — 实测门保留精确打击，只打高价值少数

不扩层，只用于：仲裁僵局（1665 / 1542 这类）、safe 硬崩（3575 / 3807 / 5119）、
wave2 补弱样本（441/95）的 oracle 断言。这是它单位投入产出比最高的位置。
