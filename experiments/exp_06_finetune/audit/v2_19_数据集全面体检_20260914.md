### 2.2 契约违约（system prompt 白纸黑字要求，但数据没做到）

system prompt 原文：*fix_suggestion 只给应修改的具体行+改法即可（**单行**、行号须真实存在、**禁止输出完整代码/补丁/代码块**）*。

| 违约 | 行数 | 占比 |
|---|---|---|
| fix_suggestion 多行改写 | **2982** | 29.6% |
| fix_suggestion 含代码 | **2315** | 23.0% |
| fix_suggestion 过长（>220 字） | **1822** | 18.1% |
| 无洞行 fix 非 `no fix needed` | 617 | 6.1% |
| `vulnerability_type` 非 `none` 也非 `CWE-xxx`（如"无"、"N/A"、"无适用 CWE（…）"） | 29 | 0.3% |
| 无洞但 `risk_level ≠ None`（如 Low） | 30 | 0.3% |

→ 模型会学到"fix 就贴一段补丁"和"无洞也能给 Low"，与推理时的单行契约错位。

### 2.3 行号锚定：三种基准并存 + 内嵌注释 72.8% 是错的

全库同时存在**三套行号基准**：

1. 单文件族 = **块内 1-based**（system prompt 要求的口径）
2. 代码里内嵌的 `// line N` 注释 = **另一个（多半是原文件的）编号**
3. 工具裁决族 = `NNN|` **原文件行号前缀**

| 检查 | 结果 |
|---|---|
| 内嵌 `// line N` 注释总数 | **1683 处** |
| 其中**与实际所在行不符** | **1225 处（72.8%）**（偏移以 −1~−13 为主，1192 负 / 33 正） |
| 含此类注释的行 | 527 行 |
| 这些行里**叙事照抄了错号** | **512 / 527（97.2%）** |
| 叙事引用行号越界（> 代码行数） | 194 行（1.9%） |
| JSON 引用行号越界 | 42 行（0.4%） |
| 同一回答混用 `Lxx` 与 `line N` 两套 | 464 行（4.6%） |

**实例（row 0，C 语言）**：代码 `free(pkt->payload)` 实际在第 37 行，内嵌注释写 `// line 34`，叙事照抄"第 34/35 行"，而 JSON 写的是正确的 `line 37/38`——**同一个答案里两套行号打架**。

→ 副作用：模型学到"锚点可以随便写"，而 `source`/`sink` 是 verdict JSON 的硬字段。

### 2.4 叙事与 JSON 结论互斥（最伤训练的一致性缺陷）

| 类型 | 行数 | 占比 |
|---|---|---|
| 叙事**立场**与 JSON 相反（叙事说有洞 / JSON 说无洞，或反之） | **246** | 2.4% |
| 叙事提到的 CWE 与 JSON 的 CWE **完全不相交** | **321** | 3.2% |

**实例**：
- **row 1013（Java XXE）**：叙事第 3–4 点写"攻击者可构造 … 导致任意文件内容被读取，构成完整的数据流"，JSON 却写 `has_vulnerability:false`，理由是"小写 doctype 触发文法级 Fatal Error"。

### 4.2 难度：对抗样本在位，但被"答案注释"泄掉

正向证据：
- 带"**防御迷惑**"标记 334 行、"**看似**"386 行、"**绕过**"406 行——存在真正的"迷惑防御"对抗设计。

**反向证据（关键缺陷）**：**36.4%（3666 行）的代码里写有答案性注释**：

| 注释词 | 行数 | 性质 |
|---|---|---|
| 模拟 / Simulate / 场景 / 业务逻辑 | 1414 / 243 / 189 / 202 | 合成标记（提示"这是造的"） |
| **防御迷惑** | **334** | 直接说"这个防御是假的" |
| **CWE-\d+（把编号写在代码里）** | **313** | **答案编号泄漏** |
| **漏洞点** | **197** | 直接指出漏洞位置 |
| **漏洞行 / Vulnerable / insecure / 安全样本** | **37 / 66 / 22 / 14** | 答案方向泄漏 |

→ 模型可以**不分析、直接读注释**就拿到正确标签。这解释了"合成集 recall 0.93–1.0"而"rolling_dev 只有 0.645"的一部分：**合成集的难度被注释泄掉了**，真实代码里没有这些注释。
更麻烦的是 row 239 那类：代码注释写 `// CWE-749: Exposed Dangerous Method`，教师照抄给出 CWE-749——**注释本身就是错的**，于是错误标签被固化。

### 4.3 难度结构缺口

- **工具告警裁决族（T）仅 33 行（0.3%）**，其中 27 条判无洞。而项目自评"即使工具给出完整污点链，模型 4/5 概率推翻"——**这个已知最大裁决弱点几乎没补数据**。
- **多漏洞样本 0 条**（rolling_dev 全为单一 expected_cwe）。
- **跨文件**：多文件族 426 行（CWE-22×42 / 918×31 / 502×30 / 611×28…）——这是相对 8-30 的优秀补强 ✅。
