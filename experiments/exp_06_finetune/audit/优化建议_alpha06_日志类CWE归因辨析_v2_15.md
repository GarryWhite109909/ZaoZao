#### 主次选择三例实拍（2026-08-29 晚间补充：本日最稳定的失败模式）

同一现象在不同样本上重复出现三次——**模型总选中"真实的伴生/次类型"，而非主类型**。
这不是漂移（不是随机错），是系统性主次判断缺失：

| 样本 | 模型选（top1） | 主类型 | 二者关系 | 后果 |
|---|---|---|---|---|
| hard_longfile_03 | CWE-79（XSS，真实成立）| **CWE-1336**（SSTI 可 RCE）| XSS 是 SSTI 的伴生 | strict miss（79 未标注）|
| hard_bypass_06 | CWE-798 / CWE-312（硬编码凭证，真实成立）| **CWE-208**（时序攻击）| 798 是次标注、208 是主标注（manifest: `CWE-208; CWE-798`）| strict hit（侥幸，798 在标注内）|
| typical_28 | CWE-89（SQLi，真实成立）| **CWE-209**（信息泄露，主标注）| 89 是治理补标、209 是主 | strict hit（侥幸）|

**定性：模型侧主次排序能力缺失**（记为 F7），与 F1（编号方差）、F2（叙事漂移）并列。
工程侧无解——不能在聚合层硬编码"哪个 CWE 更重要"，那是答案泄漏。

**扩容规格（+12 条，三例各 4 条）**：

| 例 | 形态 | 标注要求 | must-have 锚句 |
|---|---|---|---|
| SSTI+XSS 伴生 | `from_string(f"..{user}..")` + `Environment()` 默认 autoescape=False | 主 1336，伴生 79 进 vulnerability_types | "存在模板源码注入时主类型 1336（模板语法执行可 RCE），XSS（输出未转义）为伴生漏洞同时成立"；autoescape 锚："autoescape 只影响变量值输出的转义，不影响模板语法是否被执行" |
| 时序攻击+硬编码凭证 | `token == SECRET_API_TOKEN`（常量硬编码）| 主 208，伴生 798 | "`==` 对字符串是**非常数时间**比较（逐字节短路，可测量爆破）→ 主类型 208；硬编码凭证 798 同时成立但不遮挡主类型" |

**通用主次规则（写入教师 prompt，非样本特判）**：
> 多漏洞共现时按**危害可达性**排序取主类型：
> 可 RCE / 可绕过认证 > 可读取任意数据 > 信息泄露 > 输出未转义。
> 伴生漏洞必须同时写入 vulnerability_types，不得因选了主类型而省略。

**F7 专项验收**：上述三样本各 3 次采样，top1 稳定命中 1336 / 208 / 209。

### F8：幻觉类型与投票机制（2026-08-29 新增，工程侧已评估不动）

**现象**：`hard_cve_07_tarfile_symlink.py`（tar 解压，**全文件无任何日志代码**）
三条候选全部判真 3/0：

| 候选 | 模型输出类型 | 性质 |
|---|---|---|
| B202（tarfile 规则）| CWE-117 日志注入 | **幻觉** |
| request-data-write | CWE-117 日志注入 | **幻觉** |
| path_traversal_open_join（prefilter）| CWE-22 路径穿越 | 正确 |

顶层 `vulnerability_type` = **CWE-117** —— 2 票幻觉压过 1 票正确。

**机制**：`_aggregate` 的类型投票键 = （总票数, 独立票数, 最高严重度），
"独立票"= 模型输出类型 ≠ 工具标注归一化结果——设计意图是**奖励独立思考**
（避免模型复读工具标注）。但模型独立思考出幻觉类型时同样加分，幻觉票因此胜出。

**工程侧为何不动（已实测论证）**：
1. 扩展 `_RECHECK_CWE_TO_TYPE` 加 `CWE-117 → Log Injection` + sink 特征
   （`logger.`/`logging.`/`print(`）——该样本确实无这些特征 ✓
2. **但** `_recheck_type_plausible` 在 sink 搜索失败时 fallback 到
   `_has_cross_file_call(code)`，本样本 import 了 `tarfile`/`os` 并调用 →
   fallback 返回 True → **CWE-117 仍被判为形态匹配**
3. 要让校验生效须改跨文件 fallback 语义（判断"导入符号是否与类型相关"），
   而该 fallback 服务于 hard_crossfile 全族（sink 在外部文件），
   改动波及所有跨文件样本 → **风险远高于收益，实测确认后放弃**

**数据侧修法（推荐）**：
- 教师口径：vulnerability_type 必须是**代码中真实存在的漏洞类型**，
  禁止输出与代码形态无关的类型（本例：无日志代码不得判 117）
- 机检断言：蒸馏时校验 vulnerability_type 的 sink 特征是否出现在该样本代码中
  （复用 `_RECHECK_SINK_RE` 思路）——**入库前离线检查**，不受跨文件 fallback
  影响，无回归风险
- 与 P0-C「硬性知识错误清洗」同批处理

### P0-C 硬性知识错误清洗（F3，专项）

**动作**：全库扫描 explanation/裁决文本中的可判定技术论断，重点清单：

- "from_string…按字面量（执行/处理）"类（Jinja2/Flask 上下文必错）
- **时序比较类（2026-08-29 采样原文实锤）**："token == SECRET_API_TOKEN 是恒定时间比较，
  不存在 Timing Attack" —— `==` 对字符串恰恰是**非常数时间**的（逐字节短路比较，
  可测量爆破），与事实完全相反。该错误论据直接导致 hard_bypass_06 的 1/3 采样判假。
  同类需清洗："== 比较不会泄露信息"、"Python 字符串比较是常数时间"
- **tarfile 解压语义类（2026-08-29 采样原文实锤，hard_cve_07）**：
  ① "extractall 的 path 是常量 UPLOAD_DIR，攻击者无法通过 tar 内容控制 path 参数，
     因此不存在路径穿越" —— **错误**：路径穿越的载体是 **tar 成员名**（可含 `../`、
     符号链接），目标目录是否为常量与之无关（CVE-2007-4559 即此形态）；
  ② "该操作等效于 `os.system` 级别风险" —— **错误**：`tar.extractall` 无 shell 语义，
     其 sink 类型是路径穿越（CWE-22）/ 任意文件写入，**不是**命令注入。
     该错误论据直接导致采样 3 判出 CWE-732（权限配置），采样 1 判出 CWE-441（代理）。
- **autoescape 语义类**："未调用 render_template() 因此不涉及 Jinja2 模板渲染"
  （`env.from_string` 同样是模板渲染）；"autoescape 开启即可防 SSTI"
  （autoescape 只管变量值输出转义，不管模板语法执行）
- 同族变体（typical_23 第 6 次实拍，0/3 全票采纳错误论据）："没有调用
  render_template() 因此不涉及 Jinja2 模板渲染"（render_template 是 Flask 封装，
  直接用 `env.from_string()` 同样是模板渲染）；"template_str 硬编码、name 仅字面量
  拼接"（f-string 已将 name 插值进模板源码）
- 框架语义类错误高发词：`render_template` vs `render`、autoescape 默认值、
  `subprocess` shell 语义等——逐词建立"论断→真值"核对清单

**产出**：错误正文 → 重蒸馏清单（正文行号校准一并做）；无法机械判定的进人工批次。

- **机检断言**：清零已知错误论据词表（词表按上列核对清单维护，非测试集拟合——每条
  对应可执行的 API 语义事实）

### P1-A 捏造 API 禁令（F4）

教师生成 fix_suggestion 后自检："推荐的方法在标准库/已 import 库中真实存在吗"。

- **机检断言**：抽 fix 中 `\w+\.\w+\(` 调用列表，`escape|sanitize|neutralize|secure` 高发词
  人工核存在性；标准库 API 建立白名单对照（仅日志类先做：logging 只有 `%s` 惰性插值 +
  输出侧过滤两种有效修复）
- 日志类修复唯一标准形态：`logger.info("...%s", x)` 或输出侧剥离 `\r\n` 控制字符；
  `isalnum()` 置空属过度防御（静默清空合法用户名），禁止作为唯一修复入库

### P1-B 伪修复禁令（F5）

原型污染修复形态白名单（node 实证）：

1. 键名过滤：`if (key === '__proto__' || key === 'constructor' || key === 'prototype') continue;`
2. null-prototype 目标：`{ __proto__: null }`（注明仅保护该对象路径）
3. 无原型结构化替代（structuredClone / Map）

**禁止**：对 `src[key]`/`target[key]` **值**的比较（`!== Object.prototype`、`instanceof`）——
值比较挡不住键名注入。教师口径：1321 组样本的 fix 仅允许白名单形态。

**第三类：修复-判定严重性不匹配（2026-08-29 typical_28 实拍补充）**：模型 3/0 确认
SQLi（f-string 拼接），三条 fix 全是 `execute("... WHERE id = ?", (user_id,))`——
直接参数化**等效消除该漏洞点**，与"确认高危漏洞"的判定自相矛盾（与 F2 同源：
教师对"正确写法"的模板化输出与判定上下文脱节）。教师口径：fix 必须与
has_vulnerability=true 的判定语义一致——SQLi 场景 fix = 保持查询逻辑不变的安全
重构（预校验/白名单/最小权限），不得以"直接消除漏洞点"为 fix（那是 false 的语义）。

- **机检断言**：1321 组 fix_suggestion 含 `Object.prototype`**值比较**形态 → 退回；
  含键名过滤或 null-prototype → 通过
- **机检断言（第三类）**：样本 vulnerability_type 含 SQLi 且 fix 含"参数化查询/参数化"
  → 标记人工复核（该形态大概率是混淆样本，90% 命中）

## 四、教师判定锚速查表（直接嵌入教师 prompt）

```
【日志族】用户输入到达 logger/log/logging/写日志文件
  1. 输入在格式串参数位？ logger.info(user_input) → 134；logger.info(f"..{x}")/("%s",x) → 非 134
  2. 输入是敏感字面值（密码/token）？ 落日志 → 532；落非日志存储（文件/DB明文）→ 312
  3. 输入是任意可控内容（可含 \n 控制符）？ → 117（必须写"注入换行/控制符伪造日志条目"，
     不得写"敏感信息泄露"——那是 532/312 的叙事）
  312 vs 311：存储未加密 = 312；传输未加密 = 311

【原型污染族】
  递归合并/深赋值 + 攻击者控制键名（__proto__/constructor/prototype）→ 1321（JS）
  其它语言对象属性动态修改 → 915；912 是"代理/中间人"语义，与原型污染无关
  修复只允许：键名过滤 / null-prototype 目标；值比较（!== Object.prototype）无效禁止

【模板族】
  用户输入拼入模板源码（from_string(f"..{u}") / Template(u_str)）→ 1336：
    from_string 将字符串编译为模板并渲染，{{}}/{%%} 模板语法会被执行
    —— "按字面量执行"是错误认知
  用户输入仅作模板变量值 render(name=u) 且输出未转义 → 79（此时才谈转义）
  1336 vs 134：模板串执行语义由模板引擎定义（{{}} 语法）→ 1336；
    printf 格式串的 %n/%s 由 C 库解析 → 134。仅表层形似，不是同族

【CSRF vs XSS 边界（2026-08-31 新增，typical_22 实锤 352→79）】
  场景有 CSRF token 的生成/回显、但服务端**不校验** → 352（Cross-Site Request
  Forgery——攻击面是"借用已认证会话发请求"，不是"脚本注入"）。
  仅当用户可控数据**未转义进入 HTML 响应体**才是 79。
  修复叙事：352 的修复是服务端 token 校验/ SameSite cookie；"转义输出"是 79
  的修复——确认 352 时禁止输出转义类修复（语义错位）。

【PHP 弱比较族（2026-08-31 新增，typical_33 实锤 843→200/204）】
  用户输入与秘密值做 == 比较（"0e..." md5 碰撞 / "1"=="1.0" 类型混淆）→ 843
  （Incompatible Type / type juggling）。
  修复只允许：hash('sha256', x) 后 === 严格比较 / === 强比较。
  200/204（信息暴露/时序）至多是伴生视角，不得作为该场景主类型。

【类型输出纪律（2026-08-31 新增，F9：确认对象与输出类型脱钩）】
  is_confirmed=true 的 finding，其 vulnerability_type 必须与**该候选指向的
  漏洞语义**一致，禁止输出其他类型的编号：
  - 文件上传无类型校验 = 434（全文无 SQL sink 时禁止输出 89）
  - 原型污染 = 1321（JS 专有，__proto__/递归 merge）；77 是命令注入
    不是"认证"，287 是认证缺失——都禁止用于 __proto__ 场景
  - 多缺陷共现时：主类型 = 危害可达性最高者；伴生类型只能进 notes
```
