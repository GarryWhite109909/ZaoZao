## 二、「有效行 < 8」不是删除理由（抽样 12 条读码）

抽 12 条逐条读码，**单条看全部合格**：形态正确、explanation 正确、行号锚定齐、无捏造：

```
@app.route('/ping')
def ping():
    host = request.args.get('host', '')
    result = subprocess.run(f'ping -c 1 {host}', shell=True, capture_output=True, text=True)
    return result.stdout
→ true/CWE-78，explanation：用户输入 host 直接拼入 shell 命令 → 注入分号/管道 → 任意命令执行
```

它们的问题**不是"行数少"，而是同一 trick 反复出现**（`ping`/`gzip`/`nslookup`/`convert` + `shell=True`/`shell_exec`/反引号/`system(cmd)`，只换语言与函数名）。
所以正确的归档是**「重复啰嗦 / 懒变体」**，而不是「无营养」。

反例（不该连坐删）：idx 1828 的 `os.environ['PATH'] = env` + `subprocess.run(['ls','-la'])` —— 是 **PATH 劫持**这一独立 trick，不在重复套路里。

**62 条里落在唯一 trick 簇的 6 条（明确不可删）**：`6799 / 6803 / 6805 / 6806 / 1963 / 2756`。

## 三、换个视角量「冗余」：同 trick 簇

按 4 元签名聚类（sink 家族 × source 家族 × 防御形态 × 拼接方式）：

| 项 | 值 |
|---|---|
| 512 条 → 簇数 | **152** |
| **单条簇（唯一 trick，形态多样性，不可删）** | **76 条** |
| 最大簇 | 45 条（`sh_c` × source 未识别 × 无防御 × 拼接） |

**「每簇保留 N 条」下的冗余量**（这个 N 由人定，不由脚本定）：

| 每簇保留 | 冗余条数 | 占 78 | 删后剩余 |
|---|---|---|---|
| 1 | 360 | 70.3% | 152 |
| 2 | 284 | 55.5% | 228 |
| **3** | **228** | **44.5%** | **284** ← 我原规划的目标「≤300」≈ 这一行 |
| 5 | 150 | 29.3% | 362 |
| 8 | 92 | 18.0% | 420 |

**读法**：我原写的"78 → ≤300"**恰好等于"每 trick 只留 3 条"** —— 这是**配额决策**，不是质量决策。按你的口径，它只能作为「如果决定治重复啰嗦，代价是多少」的信息，**不能作为删除依据直接执行**。

## 四、配比怎么治：抬冷门侧，不砍热门侧

### 4.1 「双重 buff」的定量论证（你的假设，我把它量化了）

| 面 | 实测 | 后果 |
|---|---|---|
| **质量面** | 77 侧的 9 条里，7 条是 g26 合成（sed/SNMP/IMAP/MVG/ffmpeg 滤镜）、2 条 alpha05 遗留（其中 `#7780 degit` 疑为 78）。**没有任何一个 kit 是真 77**（134 个未投喂包里标称的 5 个"77"实测全是 OS shell）。 | 即使配比拉到 1:1，模型看到的 77 与 78 在 sink 形态上**不可分** → 学出 77≈78 → 仍答 78 |
| **配比面** | 77:78 = 9:512 = **1:56.9**；即 77 的先验 = 9/521 = **1.7%** | 即使 77 侧样本形态完美，先验 1.7% 下模型输出 78 的期望概率仍极高 |

⇒ **两个都是必要条件**，缺一不可。这与你的判断一致：**坍缩 = 数据质量不够 + 配比过于极端**。
⇒ 但**治配比的手段是抬冷门侧**（S3 新造真 77），**不是砍热门侧**。

### 4.2 正确的配比目标：不是 1:1:1，是**下限约束**

配比合理性不该表述为"某类占比上限"。可执行的表述是**下限**：**每个 CWE 至少有 N 条 + 冷门类型有形态覆盖**。
当前长尾分布（v2_24，正样本 4813）：

| 条数区间 | 类数 | 条数 | 占正样本 |
|---|---|---|---|
| 1–3 | **18** | 27 | **0.6%** |
| 4–10 | 16 | 127 | 2.6% |
| 11–30 | 32 | 651 | 13.5% |
| 31–100 | 26 | 1268 | 26.3% |
| 101–1000 | 12 | 2740 | 56.9% |

**≤5 条的 20 类**：`61 / 908 / 1236 / 776 / 640 / 150 / 565 / 203 / 354 / 129 / 284 / 494` 各 1 条，`269 / 184 / 250` 各 2，`916 / 119 / 74` 各 3，`20 / 1427` 各 5 —— **合计 37 条 = 正样本的 0.77%**。

其中 **`184 / 250` 是 system prompt 明文口径却没有样本**（"作为安全防线的不完整禁用列表 = CWE-184"、"服务以 root 运行 = CWE-250"），属**口径与数据不一致**，优先级高于配额讨论。

**建议的下限目标**（待你拍板）：每个 CWE ≥ 5 条（当前 20 类不达标，缺口 ≈ 37 条）；口径明文的类（184/250/327/338/295）≥ 20 条。

### 4.3 若 77 补到 60 条

- 77:78 = 60/512 = **0.117**（比现在 0.0176 好 6.6 倍）
- 77 占正样本 1.2%（仍是冷门，符合真实分布——这也说明**不需要追求 1:1**）
