### 二、source→sink 数据流逐条验证

**流 A：请求路径 → 正则替换 → 内部转发路径（第 77→89→128–131 行）**
- source：第 78 行 `currentPath := req.URL.RawPath`（未解码原始路径，攻击者可控）。
- 处理：第 89 行 `newTarget = rt.regexp.ReplaceAllString(currentPath, rt.replacement)`；无正则时走第 91 行分支，剥离 `$N` 引用。
- sink：第 128–131 行写入 `req.URL.RawPath` 并 `url.PathUnescape` 后赋给 `req.URL.Path`，交给后端。
- 防御评估：这是中间件的**设计功能**（rewrite 本身就是允许改写路径），且注释明确说明不处理多重编码。若运维配置了宽松正则（如 ingress-nginx 迁移场景常见的 `/(.*)`），攻击者可通过编码字符（如 `%2e%2e%2f`）在替换结果中注入穿越序列，绕过后端路由前缀隔离。但该行为与 ingress-nginx 兼容语义一致，属于配置层面的固有风险，非本代码引入的逻辑缺陷。**记为低危备注**。

**流 C：请求路径 + 查询串 → 302 重定向 Location（核心漏洞，第 84→89→112→121 行）**

## 三、`ServeHTTP` 数据流逐一验证

**流 A：用户路径 → 正则替换 → 绝对 URL 302 跳转（开放重定向风险面）**
- Source：第 89–92 行 `currentPath`（攻击者完全可控）。
- Sink：第 131 行 `http.Redirect(rw, req, newTargetURL.String(), ...)`。
- 防御链：
  1. 第 100–103 行：只有 replacement 模板本身带 scheme 才走此分支；若模板无 scheme（如 `//$1`），`absoluteURLRedirect=false`，不会产生外部跳转，落入流 B 的内部改写分支——无法借“scheme 相对 URL”绕过进入跳转分支。
  2. 第 110–118 行：替换结果整体重新 `url.Parse`，host 由模板固定部分决定。即使捕获组内容形如 `evil.com` 或 `%2F%2Fevil.com`，它只会落在 path/query 部分，无法覆盖已解析出的 authority（Go 的 `url.Parse` 中 host 先于 path 解析，path 中的 `//` 不改变 host）。解析失败则 500（第 111–113 行）。
  3. 第 120–125 行：query 透传仅在 `newTargetURL.RawQuery == ""` 时进行，且 `req.URL.RawQuery` 本身已被 Go 标准库解析校验过，不含裸 CR/LF。
  4. `http.Redirect` 内部还会对 Location 值做 HTML/控制字符净化，CRLF 注入到响应头不可行。
- 结论：该流的开放重定向与头注入均被有效阻断。

**流 B：用户路径 → 正则替换 → 内部转发路径（路径穿越/规范化混淆风险面）**
- Sink：第 141 行 `req.URL.RawPath = newTarget`，第 143 行 `url.PathUnescape`。
- 防御链：
  1. 第 149–153 行：`JoinPath()` 触发 `path.Clean` 规范化；
  2. 第 155–159 行：**关键防御**——若清洗后的路径与原路径不一致（如出现 `..`、多余斜杠导致的语义变化），直接 400 拒绝。这封死了经典的“RawPath 与 Path 不一致导致后端路由混淆”攻击（如 `/safe/../admin`、编码斜杠 `%2F..%2F` 变体）。
  3. 第 145–148 行：unescape 失败即 500 拒绝，不降级放行。
  4. 第 161 行同步修正 `RequestURI`，避免下游读到旧值造成不一致。
- 结论：路径混淆有显式校验兜底，非黑名单式过滤。

**流 C：用户路径 → X-Forwarded-Prefix 头（头注入风险面）**
- 第 134–139 行：prefix 来自静态配置或经同一正则替换生成；即便含特殊字符，`req.Header.Set` 在写入时会剥离非法头字符，且 `currentPath` 取自 `EscapedPath()`，原始 CRLF 已被转义。无可利用注入。

**流 D：错误信息回显**
- 第 146 行 `http.Error(rw, err.Error(), ...)` 回显的是 `url.PathUnescape` 的标准库错误（如 `invalid URL escape`），可能包含攻击者输入的片段，但属低危信息泄露且 Traefik 上游接受此行为；第 105、112、150 行均为固定文本，无注入。
