# 逐点分析

**入口点枚举（全文）：**

1. **构造函数 `TableChatAgent.__init__`（第 96-120 行）**：接收 `config.data`（文件路径/URL/DataFrame，第 84 行），经 `read_tabular_data` 加载数据。数据来源若为用户可控 URL/文件，属于外部输入 source；但仅用于构建 DataFrame，无直接危险 sink。

2. **系统消息格式化（第 106 行）**：`config.system_message.format(summary=summary)` —— summary 来自 `dataframe_summary(df)`（第 42-90 行），其中分类列的唯一值直接拼入字符串。若数据内容含 `{...}` 格式化占位符可引发 format 异常或注入提示词，但影响限于 LLM 提示，非代码执行 sink。

3. **核心 sink：`pandas_eval` 方法（第 137-176 行）**：
   - **source**：第 143 行 `exprn = msg.expression` —— 表达式由 LLM 通过 `PandasEvalTool` 工具调用生成，而 LLM 输出可被用户查询间接操控（prompt injection），也可被恶意数据集内容（如单元格文本诱导 LLM）操控。
   - **sink**：第 155 行 `pd.eval(exprn, local_dict=local_vars)`。
