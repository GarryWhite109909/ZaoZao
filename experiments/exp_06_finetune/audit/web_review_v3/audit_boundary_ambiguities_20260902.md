# web_review 审计模型边界歧义案例库（2026-09-02）

> 用途：web_review 审计模型（glm5.3 / glm5.3-flash）在**缺少官方 CWE 判别依据**时，
> 对边界样本的定性不稳定——同一样本会得出互相冲突的归属（79 vs 798、1336 vs 79、
> 611 vs 79 等）。本文档记录这类歧义案例，作为 prompt 优化（嵌入官方判别标准与原理）
> 的反例输入与验收基准。
>
> 数据来源：`audit/web_review/result.txt`(glm5.3) + `audit/web_review_v3/result_batch_20_30.txt`(glm5.3-flash)。
> 二次精审依据：MITRE CWE v4.20 官方定义（`audit/cwe_offline/cwe_defs.json`）。

## 一、歧义模式总览（审计模型结构性不确定点）

| 模式 | 说明 | 涉及样本 |
|---|---|---|
| **硬编码凭证 798 vs 未使用常量** | 代码定义了 secret_key/db_password 但**从未流向 sink**——算"硬编码即洞"还是"未使用常量不算可利用漏洞"？ | 6257 |
| **防御/净化代码当漏洞** | 审查把 sanitizer/校验函数/过滤组件本身误当漏洞点 | 7524, 7543, 7536 |
| **模板源码注入 vs 反射 XSS** | `render_template_string(整段含拼接)` 判 1336(SSTI) 还是 79(XSS)——取决于输入是否真进模板语法位 | 8210 |
| **XXE 611 vs SVG 净化 XSS** | XML 解析器外部实体 vs SVG 上传净化不完整 | 7536 |
| **缺授权 862 vs 已有 authorize()** | 路由有授权检查时仍判"缺授权" | 7793 |
| **纯库代码误标** | 无任何输入校验缺陷的库代码被判 CWE-20 等 | 7810 |
| **逃逸/转义函数误标命令注入** | 防御性参数转义组合函数被判 78 | 7524 |

## 三、对 prompt 优化的要求（从歧义反推）

审计 prompt 目前缺的**三条判断纪律**（导致上述歧义）：

1. **防御代码识别**：先判断该代码是不是"防御/净化/校验函数本身"，若是，它**不构成漏洞点**——真正的漏洞在防御缺失的可达路径，而不是防御函数的存在。
2. **硬编码凭证须被使用**：CWE-798 要求硬编码凭证**流向敏感操作**(登录校验/加密/签名等)。未使用的常量仅"定义"不算可利用漏洞，最多是代码异味，不得据此 DELETE 一个含真实 XSS 的样本。
3. **模板源码注入判定**：判 1336(SSTI) 必须确认**外部输入进入了模板源码字符串位**(`render_template_string(f"...{u}...")` 中 u 拼进模板)，再被模板引擎渲染；仅整段字符串拼接不经模板求值、或输入只作变量值 → 不构成 SSTI(按输出层判 79)。

## 四、验收基准（prompt 优化后，这 8 条应得到有官方依据的稳定判定）

- 6257：明确 798 不成立(未使用常量) → 聚焦真实 XSS(79)，verdict 从 DELETE 复核
- 8210：按"输入是否进模板语法位"定 1336 或 79，不再凭直觉
- 7536/7524/7543/7810/7793/7312：按"防御代码识别"纪律给出"非漏洞点/确证漏洞"的清晰定性
