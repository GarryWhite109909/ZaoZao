# 易混淆 CWE 判别附录（供 web_review / 审查 AI 嵌入，CWE 归属权威标尺）

> 依据：MITRE CWE v4.20 官方定义/扩展描述/Observed Examples（本地 `audit/cwe_offline/cwe_defs.json`）。
> 用法：当你要给某样本下 CWE 归属结论时，先对照本附录对应组；附录未覆盖的组按代码 sink 语义判断；仍拿不准 → 写入 verify 数组，禁止凭先验硬判。

## 组 1：74 / 77 / 78 / 88 —— 注入主族（最易错）

| CWE | 官方核心 | 一句话判别 |
|---|---|---|
| 74 | 通用注入父类（下游组件解析输出） | 下游解释器说不清才用；能用子类绝不停留 |
| **77** | **非 OS shell 的命令语言**注入 | 注入目标是"某个解释器自己的命令语言"，但不是 OS shell：sed 脚本、SNMP 命令、Fluentd/应用配置语言、IMAP/SMTP 命令、MVG 图形语言 |
| **78** | OS 命令注入，官方含两亚型：①输入拼命令串经 shell；②**无 shell 但选择执行哪个程序可控**（`exec([COMMAND])`/`subprocess.run([user_cmd])`） | sink 是 OS 命令执行，**无论有无 shell 层**。无 shell 列表形式**仍是 78**（只是不能组合多命令） |
| 88 | 参数分隔符注入（程序固定、只注参数） | 什么时候用：命令名硬编码、用户输入落参数位（`git rebase --exec <x>`） |

**判定口诀**：先问注入目标是不是 OS 命令执行 → 是就 78（不看 shell）；注入目标是 sed/IMAP/SNMP 等命令语言 → 77；命令名固定只注参数 → 88。
**注意**：不要因"没有 shell=True"把 OS 命令场景改成 77（官方警告 77 常被误用）。

## 组 2：94 / 95 / 917 / 1336 / 150 / 134 —— 代码执行细分区（次易错）

| CWE | 官方核心 | 一句话判别 |
|---|---|---|
| **94** | 代码段由外部输入**拼接/生成**再执行 | 代码是"拼出来的"：字符串拼进源码/生成文件再 compile+exec |
| **95** | 输入直接进 **eval()/exec()** 一跳求值 | sink 就是 eval/exec 本身收字符串；`new Function`、`vm.runInNewContext`、PHP `preg_replace /e`、`create_function` 都算此列 |
| 917 | **表达式语言**语句（SpEL/OGNL/log4j `${}`） | 框架表达式求值器在 sink |
| **1336** | **模板引擎**把输入当模板语言渲染 | 模板引擎把输入当模板源码：Jinja2 `render_template_string(f"..{u}..")`、Pug/EJS/Twig/Freemarker/Thymeleaf 视图名注入、Go template `Parse(user)`。**输入拼进模板源码字符串**是 1336；仅作变量值 `render(x=input)` 不是 |
| 150 | 终端 ANSI/OSC 控制序列（TUI 渲染） | 终端输出未净化控制字节 |
| **134** | printf/格式化字符串（`%n`/`%s` 由 C 库或格式引擎解析） | sink 是格式化函数且输入占据**格式串位** |

**最易混淆的两个**：
- **1336 vs 134**：模板引擎把输入当模板语言执行 → 1336；格式串 `%` 语义 → 134。**二者仅表层形似**。典型反例：`render_template_string(f'<h1>Hello {name}</h1>')` 是**1336 不是 134**（模板语法 `{{}}` 会被执行）。
- **94 vs 95**：`eval()`/`exec()` 直接收用户字符串 → **95**；输入拼成代码文本再执行 → **94**。两者都含 eval 形态时按"NVD 惯例直接求值=95"。

---

嵌入提示词位置建议：放在「# 输出格式」之前；并在「# 纪律」处追加一句：
「CWE 归属判定前必须对照【易混淆 CWE 判别附录】组1/组2；对 render_template_string/SSTI、eval 类、命令注入类拿不准时，把断言写入 verify 数组待查证，禁止凭记忆硬判 1336/134/77/78 等编号。」
