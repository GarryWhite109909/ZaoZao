2. **source→sink 数据流**：唯一 source 是 URL 路径（`rctx.RoutePath` 或 `r.URL.Path`），sink 是 `s.f.NewObject`、`RcatSize`、`o.Remove`、`walk.ListR`、`Mkdir` 等后端操作。防御在 `WithRemote`：先 `strings.Trim(urlpath, "/")`，再拒绝空串外的 `.` 及所有非 `iofs.ValidPath` 的路径——即拒绝任何含 `.`/`..` 元素、绝对路径、反斜杠等形态。黑名单式绕过不适用：这是白名单校验（canonical relative path），且注释明确说明后端用 Fs root 拼接，故穿越被阻断。

3. **append-only DELETE 检查**：`deleteObject` 用 `strings.Split(r.URL.Path, "/")` 判断倒数第二段是否为 `locks`。由于 `WithRemote` 已保证路径 canonical（无 `..`），无法借 `/locks/../data/xx` 绕过；URL 编码 `%2e%2e` 会被 net/http 解码进 `URL.Path` 后同样被 `ValidPath` 拒绝。允许删 `locks/` 下对象是 restic 协议预期行为。

4. **私有仓库检查**：`checkPrivate` 要求 URL 段 `userID` 等于认证用户；未认证时 `ok=false` 直接 403；NotFound 兜底也返回 403，避免枚举。

5. **次要问题**：`listObjects` 缓存清理、`createRepo` 的 `path.Join(remote, name)` 均基于已验证的 remote，无注入面。`postObject` append-only 的 TOCTOU（先查存在再写）在单后端语义下属竞态但影响有限，且为已知设计权衡。
