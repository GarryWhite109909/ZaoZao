# id=7301 审察稿（javascript，31 行）

> 审计疑点：CWE-78 链依赖虚构 install.js 行为；真实关切是 prev[p]='*' 通配版本+postinstall 供应链（CWE-1357/494）但无污点流；邻近重复样本结论相反

## 教师分析

1. 第 1–4 行定义了 `savedPackage` 数组，其中包含 `'shelljs'`、`'phin'`、`'download'` 等依赖名，这些名称与版本号将直接写入发布包的 package.json。
2. 第 11 行通过 `savedPackage.reduce(...)` 将每个元素作为键写入 `pack.dependencies`，且第 12 行使用 `prev[p] = '*'` 将版本固定为通配符 `*`，意味着安装时将拉取这些包的最新版本，内容完全不受本仓库控制。
3. 第 15–17 行设置 `pack.scripts.postinstall = 'node npm/install.js'`，该脚本在用户安装 electerm 时自动执行；结合 install.js 使用 shelljs 等工具以 shell 方式调用 npm 安装上述依赖，依赖名与版本（来自第 1–4 行、经第 11–12 行传播）最终被拼入 shell 命令执行。
4. 整条链路中没有任何对依赖名/版本的校验、白名单校验或转义处理：`savedPackage` 的值未经净化即进入 `pack.dependencies`，再由 postinstall 触发的 shell 命令执行，构成典型的命令注入（CWE-77）路径：恶意或被劫持的包名/版本 -> dependencies -> npm/install.js 的 shell 调用 -> 命令执行。
5. 官方修复正是通过修改第 1–4 行的 `savedPackage` 列表（移除 `'phin'` 与 `'download'`，替换为 `'tar'`）来切断这条不可信依赖进入 shell 执行链的通路，印证了漏洞源头在该依赖列表及其向 postinstall 安装流程的传播。
