## 一、现有脏数据怎么洗（v2_15 → v2_16）

### 1.1 洗数据的分层法（按证据强度从硬到软）

| 层 | 证据源 | 工具/资产 | 处置 |
|---|---|---|---|
| L1 官方标签 | NVD API / GHSA / MITRE v4.20 本地目录 | `audit/cwe_offline/nvd_check.py`（已留作入库门禁） | CVE 绑定样本与官方冲突 → 改标（记录 label_basis）或降级 desc 为"模式参考" |
| L2 代码形态 | 标签声称的 CWE 与 sink 形态不符 | agent 逐条精审（9/2 已确认 1336/94/943/643 组 52+ 条） | 改标签（叙事同步改）或删除；无真实 sink 的假阳性 → 删 |
| L3 同源簇泄漏 | 隔离种子的衍生样本跨池 | `result_id_map.json` 反查 + 簇表 | 无条件 purge（当前 2 条：行 7645/7663）；build 加 `--purge-quarantined-seeds` 幂等步 |
| L4 审计 verdict | web_review DELETE/FIX/UNSURE | `apply_web_review_delete.py`（已执行 10 条）+ FIX 通道 | DELETE 删；FIX 按错误类型修；UNSURE 进人工裁决 |
| L5 口径一致性 | 近邻辨析（798 抢占/327 吞族/77↔78） | teacher_prompt 追加层锚句 + 人工抽验 | 不改旧标签（历史样本保留当时口径），靠**新数据稀释** + 评测基线版本化（2026-09-02 修正版） |

### 1.2 洗的纪律（每一步都必须）

1. **备份先行**：`.bak_日期_操作`，冻结集内备份须移出目录再重打锁（cve_fix 教训）。
2. **manifest 留痕**：`_changelog`（改了什么/为什么/依据）+ `label_basis`（code|nvd|ghsa）。
3. **自检三件**：JSON 全库解析零失败、正负比符合预期变化、溯源包（source_pack）不丢。
4. **双通道裁决**：不信单一审查者（agent 精审在边界样本上同样会错，6257 教训）——
   有争议样本走 2v1 仲裁或人工，不做静默改标。
5. **改标/删除/降级三分**：标签错→改（含叙事）；无洞误标→删；CVE 归属故事存疑→降级不删。

## 二、后续蒸馏的方法论（从"配额填充"转向"约束派生"）

### 2.1 源头三源制（行业对照后的定位）

| 源 | 用途 | 占比目标 | 项目资产 |
|---|---|---|---|
| **patch 派生差分对**（主力） | 教判别边界 | ~60% | corpus/patches 291 条 + wave1 的 286 对修复对雏形 |
| 真实 CVE 定向补弱类 | 补长尾形态 | ~25% | rolling_dev 441/95 反复漏报的族；2026 形态 |
| 合成辨析对 | 教近邻边界 | ~15% | g 系列管线（kits→蒸馏→verify→merge） |

**差分对的生成契约**（区别于历史单侧样本）：
- pre-fix 判真 + post-fix 判安 + **行级归因**（explanation 必须点名"第 X 行的修改关闭了哪个攻击面"）
- 一对 = 一个判别边界教学单元，不是两个独立样本
- CVE-fix anchor strict=1.000 但 rolling_dev strict=0.450 的差距证明：差分对教的是
  "真实代码里漏洞与正常的分界"，这正是 6% 典型性下唯一还缺的能力

### 2.2 每条样本的生成契约（g25/g26 全部教训的沉淀）

1. **oracle 先行**：vuln 侧必须有可断言的污点路径；safe 侧必须有可断言的防御链。
   手写样本一律先过独立 agent 审查（g25 第一版 7/16 带隐蔽漏洞的教训）。
2. **hint 给判别标准不给结论**：cmdlang-08 教训——hint 判 77，实际经 /bin/sh -c 是 78，
   教师纠正了 hint。hint 只给"按什么判"，答案由教师独立得出。
3. **一致性门**：G1 dual 双采样 + 仲裁（2v1），保证标签不是采样波动的产物。
4. **行号锚定在生成时**：explanation 引行号必须带代码片段（P1-C 口径），
   蒸馏产出跑 normalize_line_numbers——校准留给入库门，不做事后修补。
5. **辨析叙事**：近邻样本 explanation 必须含互斥锚句（"非 78 因为…"/"非 327 因为…"），
   机检断言区分"辨析语境讨论"vs"叙事错位"（g26 verify 过严误报的教训）。

### 2.3 管道硬门（freeze 前必跑的检查序列）

```
生成 → [G1 一致性] → [G2 sink特征] → [G4 契约] → [G5 oracle断言] →
入库 → [G6 簇/泄漏门: purge-quarantined-seeds + 全库簇查重] →
冻结 → [verify: 锚句+叙事互斥+契约] → [score_batch 口径抽验] → lock
```

- G5（新增）：变体/合成样本的 oracle 断言——污点路径存在性（vuln）/防御可达性（safe）
- G6（新增）：同源簇只许一侧 + 簇内配额上限（防同文件多化身过拟合，DiverseVul 惯例）
- 头部配额在 build 层执行（78 封顶），不在数据层删

### 2.4 教师口径管理

- 唯一权威源：MITRE v4.20 本地目录（cwe_offline/）+ NVD/GHSA 机检——**拿不准查官方，不凭记忆**（77/78 锚句修正的教训）
- teacher_prompt 追加层持续进化，但每次修改评估对已入库样本的口径漂移（改锚句 → 重蒸馏受影响族 or 接受版本差）
- 评测基线变更（如 P0 的 9 处）必须版本化：素材库口径"基准答案 = 2026-09-02 修正版"

### 2.5 评测-数据闭环（防作弊红线内）

- 错例驱动：每个 strict miss → 用**官方语义**造同形态对照对（不是对着测试集加映射——
  "不看测试结果能推出来吗"自检）
- rolling_dev 只测不调、发布前一次（D8 纪律）
- 复盘三分法：数据缺口（造数据）/ 管线缺陷（改门）/ 口径漂移（改基准并版本化）——
  9/7 综合测评的时差教训：先确认"模型吃没吃过这批数据"再归因

## 三、一句话总纲

**清洗 = 分层证据 + 留痕 + 双通道；生成 = 差分对为主 + oracle 先行 + 簇不变量；
行号和类型的事后修补只在入库门兜底，不进数据本体。**
