## ⚠️ 2026-09-14 更正：P1 档「CWE-77 ×5」的口径不成立，改按 CWE-78 投喂

`diffpair-corpus_00181 ~ 00185` 的 `manifest_PRIVATE.json` 写着 `expected_cwe = CWE-77`，
但这 5 个 77 来自 **NVD 的伞类绑定**，与 **MITRE 语义**冲突（77 是 78 的父类，精确子类优先）。
逐条实测 sink 形态：

| kit | CVE | 语言 | sink 实测（pre-fix） | MITRE 语义应判 | manifest 写 |
|---|---|---|---|---|---|
| 00181 | CVE-2026-32241 | Go | `runCmd([]string{}, "", "sh", "-c", n.preStartupCommand)` — **显式 sh -c** | **CWE-78** | CWE-77 |
| 00182 | CVE-2026-22688 | Go | 上游补丁自带注释 `prevent command injection (CWE-78)`，校验 MCP stdio `Command/Args` | **CWE-78** | CWE-77 |
| 00183 | CVE-2025-69256 | JS | `execAsync("find \"${rootDir}\" ...")` — exec 走 shell 字符串 | **CWE-78** | CWE-77 |
| 00184 | CVE-2025-67511 | Py | `sshpass -p '...' ssh ... '{escaped_command}'` 经 `run_command`（shell 字符串） | **CWE-78** | CWE-77 |
| 00185 | CVE-2025-61141 | Go | `exec.Command("sh", "-c", command)` / `exec.Command("cmd", "/c", command)` | **CWE-78** | CWE-77 |

旁证：`audit/cwe_offline/nvd_cwe_check_full_20260908.jsonl` 里 CVE-2025-67511 的
`nvd_cwes = ["CWE-77"]`，而同一记录的 `assistant_labels = ["CWE-77", "CWE-78"]` —— **教师本人早已分歧过**。

**处置**：这 5 包**照投**（它们本身是合格的真实 CVE 差分对），但**预期标签改为 CWE-78**，
解析时按 78 归档。它们补的是 **78 的形态多样性**，不是 77。

⇒ **修正后：全项目没有任何现成的「真 CWE-77（非 OS 命令语言）」kit。**
77 的真实存量 = `data/final_train_chatml_alpha06_v2_24_candidate_20260914.jsonl` 里的 **9 条**
（7 条来自 `corpus/repair_wave/g26_command_language.jsonl`：sed / SNMP / IMAP / MVG / ffmpeg 滤镜；
2 条 alpha05 遗留）。**77 只能靠新造补**（见 `audit/alpha06优化规划_20260914.md` S4）。

**同源结论**：这与 §2.1（alpha05 的 174 条 77 实为 78、构建脚本改判 78 做对了）是**同一根因的两个方向**——
项目对「NVD 伞类 77 vs MITRE 78」的口径**只在训练数据主体上执行了，没执行到 diffpair kit 的 oracle 层**。
