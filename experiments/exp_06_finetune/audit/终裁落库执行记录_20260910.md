## 二、7901 的 CWE 口径留痕（用户提问后修正推荐理由）

用户问「为什么推荐库内口径，库内和官方谁接近真理」。查证 NVD 官方 API 后结论：

- NVD 对 CVE-2023-33201 的 `weaknesses[0]` = **CWE-295**
  （source=`nvd@nist.gov`, type=Primary），**但同一记录的描述原文**为
  *"inserts the certificate's Subject Name into an LDAP search filter without any escaping,
  which leads to an **LDAP injection** vulnerability"* —— **NVD 自身描述与 CWE 字段不自洽**。
- 该分歧的实质是「机制类」vs「上下文/后果类」：CWE-90 描述缺陷本身
  （不可信输入未中立化进 LDAP 查询），CWE-295 描述为什么它要紧（发生在证书校验路径）。
- 本项目一贯判据是「MITRE 精确子类 > NVD 绑定」——`L1_conflict_待人工清单_20260908` §A
  已按此 KEEP 了 11 条（POODLE 的 NVD 310 弃用伞类、Struts2 的 NVD 74 旧映射噪声、
  CVE-2017-18349 NVD 20 伞类而 502 为正解等）。

**最终处置**：top-1 取 **CWE-90**（MITRE 机制类定义字面命中 + 与库内 3446 同源 + 在 22 类清单内），
并在 `explanation` 中**显式记录 CWE-295 分歧**，供「与 NVD 一致率」指标另算。
决策卡 C4-1 的措辞「库内口径」已订正为「MITRE 机制类语义」。
