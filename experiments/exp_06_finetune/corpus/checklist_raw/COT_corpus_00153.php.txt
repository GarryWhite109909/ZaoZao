分析：

1. **输入点枚举**：`fromString(string $xml)`（line 22）与 `fromFile(string $file)`（line 71）接收外部 XML 字符串/文件路径，SAMLResponse 等不可信 XML 会流入 `$xml`。危险 sink 为 line 37 的 `$domDocument->loadXML($xml, $options)`。

2. **数据流验证**：source（调用方传入的不可信 XML）-> fromString -> loadXML。防御检查：
   - line 27-29 / 43-45：PHP < 8.0 时使用 `libxml_disable_entity_loader(true)`，但 PHP >= 8.0 时该函数已废弃且不执行；
   - line 34：options 含 `LIBXML_NONET`（禁网络），但仍包含 `LIBXML_DTDLOAD | LIBXML_DTDATTR | LIBXML_PARSEHUGE`，允许加载 DTD 与实体定义；
   - line 51-57：加载**之后**才遍历 childNodes 拒绝 DOCTYPE 节点——这是事后检测而非事前阻止，且 XXE 实体在 loadXML 解析阶段即被展开，检测发生在危害发生之后；同时该黑名单式检查可被绕过（如 XInclude、编码混淆等场景下 DOCTYPE 检测不完整）。因此该流未被有效防御覆盖。

3. **第二入口**：`fromFile`（line 71-93）读取文件内容后同样调用 `fromString` -> loadXML，走同一未防护路径，构成替代通道。

4. **结论**：存在 XXE（CWE-611）。修复应移除 `LIBXML_DTDLOAD`/`LIBXML_DTDATTR`，或改用不解析外部实体的安全配置。
