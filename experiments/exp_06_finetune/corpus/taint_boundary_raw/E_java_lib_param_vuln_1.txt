```java
package com.example.archive;

import java.io.File;
import java.io.FileInputStream;
import java.io.FileOutputStream;
import java.io.IOException;
import java.nio.file.Files;
import java.nio.file.Path;
import java.nio.file.Paths;

/**
 * 归档解包工具模块，被上层服务调用（如消息队列消费者传入归档名）。
 */
public final class ArchiveExtractor {

    /** 弱防御：仅拒绝包含 ".." 的路径 */
    private static boolean looksSafe(String name) {
        return !name.contains("..");
    }

    public static void extractEntry(String archivePath, String entryName, byte[] data) throws IOException {
        if (!looksSafe(entryName)) {
            throw new IOException("unsafe entry: " + entryName);
        }
        Path target = Paths.get("/var/archive/extracted", entryName);
        Files.createDirectories(target.getParent());
        try (FileOutputStream out = new FileOutputStream(target.toFile())) {
            out.write(data);
        }
    }

    public static void deleteArchive(String archiveName) {
        File f = new File("/var/archive/incoming/" + archiveName);
        f.delete();
    }
}
```

1. 第 15 行 `looksSafe` 与第 19 行 `extractEntry(String archivePath, String entryName, byte[] data)`：本文件无 request/argv 等显式 web 入口，但公开静态方法参数承载上层调用者（队列消费者）提交的外部数据，`entryName` 为等效污点源，必须按不可信处理。
2. 第 16 行黑名单仅检查 `contains("..")`，可被 URL 编码 `%2e%2e%2f`、Unicode 变体、绝对路径 `/etc/cron.d/x`（不含 `..` 直接逃逸目录）、Windows 反斜杠 `..\..\x` 等方式绕过，属可绕过弱防御，非有效防护。
3. 第 21 行 `Paths.get("/var/archive/extracted", entryName)`：当 `entryName` 为绝对路径时，Java 的 `resolve` 语义使子路径直接覆盖基路径；第 23 行 `new FileOutputStream(target)` 将外部数据写入任意文件路径——source(第 19 行) → sink(第 23 行) 全程无有效防御，构成 CWE-22 任意文件写入。
4. 第 28-30 行 `deleteArchive(String archiveName)` 是第二污点链：`archiveName` 同样来自函数参数，经字符串拼接后进入第 30 行 `f.delete()`，攻击者传 `../../etc/target` 可删除任意文件，为同一漏洞的替代通道。
5. 第二入口检查：除上述两个公开方法外，文件内无路由注册、无其他 IO 入口；两条链均以函数参数为唯一 source，均可达 sink 且无有效校验，确认存在漏洞。
