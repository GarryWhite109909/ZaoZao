```php
<?php
// config_loader.php — 配置/清单文件解析模块
// 被上层服务调用：上层将外部提交的配置文件内容传入 parseConfig()

namespace App\Config;

class ConfigLoader
{
    /**
     * 解析 XML 格式的配置清单。
     * $rawXml 由调用方提供（外部提交的配置文件内容），按不可信数据处理。
     */
    public static function parseConfig(string $rawXml): array
    {
        // 弱防御：仅做字符串替换，试图去掉 DOCTYPE 声明（可绕过）
        $cleaned = str_ireplace(['<!DOCTYPE', '<!doctype'], '', $rawXml);

        libxml_use_internal_errors(true);
        $dom = new \DOMDocument();
        // 第 24 行：污点数据直接进入 XML 解析器，未禁用外部实体加载
        $dom->loadXML($cleaned, LIBXML_NOENT | LIBXML_DTDLOAD);

        $result = [];
        foreach ($dom->getElementsByTagName('entry') as $node) {
            $key = $node->getAttribute('name');
            $result[$key] = $node->nodeValue;
        }
        return $result;
    }
}
```

1. 污点边界：本文件没有任何 request/input/environ 等显式 web 入口；第 15 行公开静态方法 `parseConfig(string $rawXml)` 的参数承载上层服务传入的外部提交配置内容，是等效污点源，必须按不可信处理。
2. 数据流：`$rawXml`（第 15 行）→ `$cleaned`（第 20 行）→ `loadXML($cleaned, ...)`（第 24 行），污点直达 sink。
3. 防御分析：第 20 行 `str_ireplace` 移除 `<!DOCTYPE` 属于黑名单式弱防御——攻击者可用 `<!DOCTYPE` 大小写混合变体、XML 注释包裹、或使用 `<?xml ... [<!ENTITY xxe SYSTEM "file:///etc/passwd">]>` 内部子集且不写 DOCTYPE 关键字的其他编码/换行拆分方式绕过；且第 24 行显式启用 `LIBXML_NOENT | LIBXML_DTDLOAD`，主动允许实体展开与 DTD 加载，构成 CWE-611 XXE 的完整条件。
4. Sink 可达性：`DOMDocument::loadXML` 在上述 flag 下会解析并展开 `<!ENTITY>` 外部实体，可读取本地文件（file://）、发起 SSRF（http://），返回值经第 27-29 行进入 `$result` 回传给调用方，泄露路径完整可达。
5. 第二入口检查：文件内无路由注册、无其他公开方法、无间接回调入口；唯一通道即 `parseConfig` 参数，但该参数即为污点源，故结论成立。
6. 结论：存在 CWE-611 XXE 漏洞，风险 High。
