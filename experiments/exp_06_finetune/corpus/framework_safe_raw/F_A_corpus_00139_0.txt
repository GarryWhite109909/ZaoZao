```python
from fastapi import FastAPI, HTTPException
from lxml import etree

app = FastAPI()

@app.post("/xml/pretty")
def pretty_format(payload: dict):
    xml_string = payload.get("xml")
    if not xml_string:
        raise HTTPException(status_code=400, detail="missing xml field")

    parser = etree.XMLParser(resolve_entities=False, no_network=True)  # 禁用实体解析与网络访问，防御 XXE
    try:
        doc = etree.fromstring(xml_string, parser)
    except etree.XMLSyntaxError as e:
        raise HTTPException(status_code=400, detail=f"invalid xml: {e}")

    # 格式化输出（等价于原 LSSerializer 的 format-pretty-print）
    return {"formatted": etree.tostring(doc, pretty_print=True).decode()}
```

1. 第 6 行 `payload: dict` 与第 7 行 `payload.get("xml")` 是唯一用户可控输入点：请求体 JSON 中的 `xml` 字段直接进入 XML 解析流程。
2. 第 15 行 `etree.fromstring(xml_string, parser)` 是 sink——不可信 XML 字符串在此被解析。原代码第 14 行使用默认配置的 `XMLParser()`，外部实体（DOCTYPE 内 SYSTEM 实体）会被解析并展开，构成 CWE-611 XXE 注入链。
3. 修复位于第 14 行：将解析器改为 `etree.XMLParser(resolve_entities=False, no_network=True)`。类型正确性：`resolve_entities=False` 使实体引用保持为未展开的节点而非替换为文件内容；`no_network=True` 阻止 libxml2 通过 HTTP/FTP 拉取远程 DTD/实体，二者均为 lxml/libxml2 原生安全 API。
4. 位置正确性：防御施加在解析器构造处，即数据流进入 sink 的唯一必经通道，覆盖所有经该 parser 的解析调用；攻击面完整覆盖本地文件读取（file://）、内网 SSRF 探测与 Billion Laughs 实体膨胀等 XXE 变体。
5. 第 17-19 行的异常处理与第 22 行的 `etree.tostring` 输出路径不涉及实体展开，无需改动，保持 minimal diff。
6. 第二入口检查：本模块仅注册 `/xml/pretty` 一个路由，无其他解析入口或中间件引入的替代 XML 处理通道；结论为无残留 XXE 攻击面。
