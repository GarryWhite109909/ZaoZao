```java
package com.example.comment;

import org.springframework.stereotype.Controller;
import org.springframework.ui.Model;
import org.springframework.web.bind.annotation.*;
import org.springframework.beans.factory.annotation.Autowired;
import org.thymeleaf.TemplateEngine;
import org.thymeleaf.context.Context;
import java.util.Map;
import java.util.Set;

@Controller
@RequestMapping("/admin/comments")
public class AdminCommentController {

    // 服务端维护的模板白名单：只允许渲染预置的模板名，绝不接受用户提交的模板内容
    private static final Set<String> ALLOWED_TEMPLATES = Set.of(
        "comment-notification-default",
        "comment-notification-plain"
    );

    @Autowired
    private CommentRepository commentRepository;

    @Autowired
    private TemplateEngine templateEngine;

    // 渲染评论通知模板，模板内容来自服务端预置模板，用户只能选择模板名
    @PostMapping("/save")
    @ResponseBody
    public String saveComment(@RequestParam Map<String, String> params) {
        String commentBody = params.getOrDefault("comment_body", "");
        String format = params.get("format");

        if ("template".equals(format)) {
            String templateName = params.getOrDefault("template_name", "comment-notification-default");
            // 白名单精确匹配：用户可控字符串仅作为模板名查找，不作为模板内容解析
            if (!ALLOWED_TEMPLATES.contains(templateName)) {
                return "invalid template";
            }
            Context ctx = new Context();
            ctx.setVariable("user", params.get("comment_name"));
            return templateEngine.process(templateName, ctx);
        }

        commentRepository.save(new Comment(commentBody, params.get("rel_type"), params.get("rel_id")));
        return "saved";
    }
}
```

1. 第 24 行 `@RequestParam Map<String,String> params` 绑定了全部请求参数，均为用户可控输入点：`comment_body`、`format`、`comment_name`、`rel_type`、`rel_id`，以及新增的 `template_name`。
2. 原漏洞数据流：第 30 行 `params.get("format")` 判断后，第 34 行把用户可控的 `commentBody` 直接作为第一个参数传给第 35 行 `templateEngine.process(commentBody, ctx)`——Thymeleaf 会将字符串当作模板内容解析执行表达式（如 `${T(java.lang.Runtime)...}`），构成 SSTI sink。修复后第 33~38 行改为取 `template_name` 并在第 36 行用 `ALLOWED_TEMPLATES.contains(templateName)` 做白名单精确允许集校验，未命中直接拒绝；只有白名单内的服务端预置模板名才会进入第 40 行 `templateEngine.process(templateName, ctx)`，用户输入永远不再作为模板内容被解析，类型上 String 模板名仅用于资源查找、位置上校验位于 process 调用之前、覆盖了该数据流唯一入口。
3. 防御方式为框架原生安全实践之一（模板名白名单 + 预置模板），非黑名单/正则/替换过滤，符合有效防御要求。
4. 其余数据流保持原样：第 42 行 `commentRepository.save(...)` 的 ORM 保存路径与原代码完全一致，未做改动，保证 minimal pair 局部对照性。
5. 第二入口检查：本控制器仅 `/admin/comments/save` 一个端点，无其他调用 `templateEngine.process` 的通道；`ctx.setVariable("user", ...)` 属于向模板传递数据的正常变量绑定，不是模板内容注入面。
6. 结论：SSTI 数据流已被白名单彻底切断，无残留风险。
