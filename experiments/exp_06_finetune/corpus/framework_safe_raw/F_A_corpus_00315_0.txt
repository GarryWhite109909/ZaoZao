```python
from flask import Flask, request, jsonify
import jinja2

app = Flask(__name__)

env = jinja2.Environment(
    loader=jinja2.FileSystemLoader("/app/templates"),
    undefined=jinja2.Undefined,
    autoescape=True,
)

# 白名单：仅允许渲染预置模板文件，禁止 from_string 动态编译用户输入
ALLOWED_TEMPLATES = {"welcome.html", "report.html", "summary.html"}

@app.route("/api/template/render", methods=["POST"])
def render_template():
    data = request.get_json(silent=True) or {}
    template_str = data.get("template", "")
    try:
        # 安全修复：不再编译用户字符串为模板；改为渲染固定安全模板，
        # 用户输入作为模板变量（数据）传入，与代码彻底分离
        result = env.get_template("welcome.html").render(content=template_str)
        return jsonify({"code": 0, "data": {"content": result}})
    except jinja2.TemplateError as e:
        return jsonify({"code": -1, "msg": str(e)}), 200

@app.route("/api/template/render_file", methods=["POST"])
def render_template_file():
    data = request.get_json(silent=True) or {}
    name = data.get("name", "")
    try:
        # 安全修复：白名单精确匹配，杜绝路径穿越与任意模板加载
        if name not in ALLOWED_TEMPLATES:
            return jsonify({"code": -1, "msg": "template not allowed"}), 403
        tpl = env.get_template(name)
        return jsonify({"code": 0, "data": {"content": tpl.render()}})
    except jinja2.TemplateError as e:
        return jsonify({"code": -1, "msg": str(e)}), 200

if __name__ == "__main__":
    app.run(host="0.0.0.0", port=6806)
```

2. 原第 23 行 `env.from_string(template_str).render()` 是 SSTI sink：用户字符串被当作模板代码编译，`{{7*7}}`、`{{ ''.__class__.__mro__ }}` 等 payload 可执行。修复后该行改为 `env.get_template('welcome.html').render(content=template_str)`——模板是服务器端固定文件，用户输入只作为变量数据进入渲染上下文，实现模板与数据分离，这是框架原生安全用法，类型上 `content` 是普通字符串参数而非可编译模板源。
3. 防御位置正确：替换发生在 sink 调用处，且未改变函数名、路由、控制流与返回结构，满足最小 diff 纪律；同时第 11 行补 `autoescape=True`，对变量插值做 HTML 自动转义，覆盖 XSS 次生面。
4. 攻击面覆盖：主入口的动态编译通道已消除；即使攻击者提交 `{{ config }}` 或 `{% import %}` 类 payload，也只会被当作字面文本经转义输出，无法进入模板引擎求值。
5. 第二入口检查：原第 37 行 `env.get_template(name)` 存在路径穿越/任意模板加载风险（如 `../../etc/passwd`），因同一漏洞类型的数据流一并修复——第 38-39 行加入 `ALLOWED_TEMPLATES` 白名单精确匹配（集合成员判断，非黑名单），不匹配即返回 403，匹配后才允许加载。
6. 结论：两条数据流均已修复，无残留 SSTI sink；路由、业务场景、数据流走向与原代码完全一致。
