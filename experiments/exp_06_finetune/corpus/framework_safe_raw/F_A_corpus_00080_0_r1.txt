```code
from flask import Flask, request, jsonify
import hashlib

app = Flask(__name__)

@app.route('/api/sign', methods=['POST'])
def sign_payload():
    parts = request.get_json().get('parts', [])
    if not parts:
        return jsonify({'error': 'no input'}), 400
    # prefix with block count to prevent hash collisions
    data = str(len(parts)).encode()
    for p in parts:
        data += p.encode() + b'$'
        data += str(len(p.encode())).encode()
    digest = hashlib.sha256(data).hexdigest()
    return jsonify({'signature': digest})

if __name__ == '__main__':
    app.run()
```

1. 第 7 行：用户可控输入点为 `request.get_json().get('parts', [])`，即 POST JSON body 中的 `parts` 数组，每个元素内容与长度均完全由客户端控制。
2. 第 10-13 行：可控数据经长度前缀拼接为 `data`，随后在第 14 行进入哈希函数 `hashlib.md5(data)`——这是唯一的数据流，sink 为 MD5 摘要计算。
3. 防御机制：采用 Python 标准库（框架原生安全 API）提供的 SHA-256 算法替换 MD5。SHA-256 属于当前无已知碰撞攻击的强密码学哈希，类型正确性成立：输入仍为 bytes、输出仍为 hexdigest 字符串，下游 `jsonify` 序列化行为不变。
4. 位置正确性：修复点位于 sink 本身（第 14 行），即数据流终点处消除弱算法调用；上游拼接逻辑（防碰撞的块计数前缀）原样保留，攻击面覆盖完整——无论 parts 内容如何构造，摘要均由 SHA-256 生成，MD5 碰撞/长度扩展类攻击不再适用。
5. 最小 diff 纪律：仅将第 14 行 `hashlib.md5` 替换为 `hashlib.sha256`，函数名 `sign_payload`、路由 `/api/sign`、变量名及控制流全部保持一致。
6. 第二入口检查：应用仅注册单一路由 `/api/sign`，无其他入口或后台任务使用 MD5；全文件无残留弱哈希调用，结论为安全。
