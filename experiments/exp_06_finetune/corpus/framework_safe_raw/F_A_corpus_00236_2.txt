```php
<?php
// auth.php - JWT 签发与校验（原生 PHP，firebase/php-jwt 风格）
require_once __DIR__ . '/vendor/autoload.php';

use Firebase\JWT\JWT;
use Firebase\JWT\Key;

function load_jwt_secret(): string { // 新增：从环境加载密钥，禁止硬编码
    $secret = getenv('JWT_SECRET');
    if ($secret === false || strlen($secret) < 32) {
        throw new RuntimeException('JWT secret not configured');
    }
    return $secret;
}

function create_user_jwt(string $username, array $networks, bool $isAdmin): string {
    $issuedAt = time();
    $payload = [
        'iss' => 'netmaker-api',
        'sub' => $username,
        'networks' => $networks,
        'is_admin' => $isAdmin,
        'exp' => $issuedAt + 7200,
    ];
    return JWT::encode($payload, load_jwt_secret(), 'HS256'); // 第 24 行：改用环境变量密钥签名
}

function verify_user_jwt(string $token): ?array {
    try {
        $decoded = JWT::decode($token, new Key(load_jwt_secret(), 'HS256')); // 第 31 行：同一环境密钥验签，移除主密钥后门比较
        $user = db_find_user($decoded->sub);
        if ($user === null) {
            return null;
        }
        return (array) $decoded;
    } catch (\Exception $e) {
        return null;
    }
}

// 路由入口：POST /api/login 与 GET /api/verify?token=...
$uri = parse_url($_SERVER['REQUEST_URI'], PHP_URL_PATH); // 第 46 行：外部输入 source
if ($uri === '/api/login') {
    $body = json_decode(file_get_contents('php://input'), true);
    header('Content-Type: application/json');
    echo json_encode(['token' => create_user_jwt($body['username'], $body['networks'] ?? [], false)]);
} elseif ($uri === '/api/verify') {
    $claims = verify_user_jwt($_GET['token'] ?? ''); // 第 52 行：token 直达 verify sink
    header('Content-Type: application/json');
    echo json_encode(['admin' => $claims['is_admin'] ?? false]);
}
```

2. 原漏洞核心是第 8 行 `const JWT_SECRET = 'BytesOverTheWire'` 硬编码凭据（CWE-798），签名与验签共用该常量；修复在第 11-17 行新增 `load_jwt_secret()` 辅助函数，从 `getenv('JWT_SECRET')` 读取并强制长度 ≥32，属于框架外置配置/环境变量的标准安全做法。
3. 第 24 行 encode 与第 31 行 decode 均改为调用 `load_jwt_secret()`，替换而非删除原语句，控制流、函数名、路由路径全部不变，满足最小 diff 纪律。
4. 防御位置正确性：在密钥进入 JWT 库之前完成校验，覆盖签发与验证两条使用路径，攻击者无法再利用公开泄露的源码常量伪造任意 admin token。
5. 同时移除第 22 行 `getenv('MASTER_KEY')` 后门比较——它本身也是硬编码/后门凭据数据流的一部分，删除后 masteradministrator 提权通道不复存在。
6. 第二入口检查：`/api/login` 数据流不涉及密钥比较，仅签发普通用户 token 且 `is_admin` 恒为 false，无需改动；`db_find_user` 内部查询不在本次 CWE-798 目标范围内保持原样。
