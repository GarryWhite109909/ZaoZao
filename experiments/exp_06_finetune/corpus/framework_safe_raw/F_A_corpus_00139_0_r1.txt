```python
from fastapi import FastAPI, HTTPException
from lxml import etree

app = FastAPI()

@app.post("/xml/pretty")
def pretty_format(payload: dict):
    xml_string = payload.get("xml")
    if not xml_string:
        raise HTTPException(status_code=400, detail="missing xml field")

    parser = etree.XMLParser(resolve_entities=False, no_network=True, dtd_validation=False, load_dtd=False)  # 禁用外部实体解析
    try:
        doc = etree.fromstring(xml_string, parser)
    except etree.XMLSyntaxError as e:
        raise HTTPException(status_code=400, detail=f"invalid xml: {e}")

    if doc.getroottree().docinfo.doctype:
        raise HTTPException(status_code=400, detail="DOCTYPE declarations are not allowed")

    # 格式化输出（等价于原 LSSerializer 的 format-pretty-print）
    return {"formatted": etree.tostring(doc, pretty_print=True).decode()}
```

2. 第 13 行：sink 为 `etree.fromstring(xml_string, parser)`。原代码第 12 行 `etree.XMLParser()` 使用默认配置，外部实体（如 `<!ENTITY xxe SYSTEM "file:///etc/passwd">`）会被解析展开，构成 XXE 主链：payload → xml_string → fromstring → 实体展开。
3. 第 12 行修复采用 lxml 框架原生安全 API：`resolve_entities=False` 使实体引用不被展开为内容；`no_network=True` 阻断网络外联（SSRF/XXE 外带）；`load_dtd=False` 与 `dtd_validation=False` 不加载 DTD。这是框架级白名单式禁用，非黑名单过滤，类型正确且位于解析入口处，位置正确。
4. 第 17-18 行新增 DOCTYPE 检查作为纵深防御：即使实体未被展开，也直接拒绝携带 DTD 声明的文档，覆盖 Billion Laughs / DTD 注入类变体，保证攻击面完整。
5. 第 20-21 行的异常处理与第 23 行返回路径保持原样，控制流、函数名 `pretty_format`、路由 `/xml/pretty`、变量名均未改动，仅插入防御语句，满足最小 diff。
