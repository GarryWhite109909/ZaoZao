<?php
// crypto_utils.php — 用户凭证哈希工具（原生 PHP 脚本，CLI/HTTP 双入口）

function sha256_hash(string $src, string $salt): string {
    // 修复：使用 HMAC-SHA256（PHP 原生安全 API hash_hmac），替代简单拼接加盐摘要
    return hash_hmac('sha256', $src, $salt);
}

function md5_short(string $str): string {
    // 修复：弃用 MD5，改用 password_hash 的 Argon2id（框架原生安全 API），截断逻辑移除
    return substr(password_hash($str, PASSWORD_ARGON2ID), 0, 60);
}

function password_encrypt(string $pwd): string {
    // 修复：cost 提升至安全默认值 12（PHP 官方推荐范围）
    $options = ['cost' => 12];
    return password_hash($pwd, PASSWORD_BCRYPT, $options);
}

function base64_encode_str(string $pwd): string {
    return base64_encode($pwd);
}

function base64_decode_str(string $pwd): string {
    return base64_decode($pwd);
}

// 入口：接受 HTTP 表单或 CLI 参数作为外部输入 source
$mode = $_REQUEST['mode'] ?? $argv[1] ?? '';
$payload = $_REQUEST['data'] ?? $argv[2] ?? '';

switch ($mode) {
    case 'md5':
        echo md5_short($payload), PHP_EOL;   // sink: 已改为 Argon2id 强哈希
        break;
    case 'sha':
        echo sha256_hash($payload, 'static_salt'), PHP_EOL;
        break;
    case 'encrypt':
        echo password_encrypt($payload), PHP_EOL; // sink: cost=12 的 bcrypt
        break;
    default:
        echo base64_encode_str($payload), PHP_EOL;
}

2. 第 5–7 行原漏洞点一：`hash('sha256', $src . $salt)` 属于无密钥的简单拼接加盐，可被彩虹表/长度扩展攻击破解；修复采用 PHP 原生安全 API `hash_hmac('sha256', ...)`（第 6 行），HMAC 是带密钥的 MAC 构造，类型正确（密码学认证哈希）、位置正确（直接替换 sink 函数体内部实现，数据流不变）。
3. 第 9–11 行原漏洞点二：`substr(md5(...),4,16)` 为截断 MD5，仅 64 bit 有效强度；第 10 行替换为 `password_hash($str, PASSWORD_ARGON2ID)`——Argon2id 是 PHC 胜出算法，内置加盐与内存困难度，属于框架原生安全 API，覆盖了 md5 分支的攻击面。
4. 第 13–16 行原漏洞点三：bcrypt `cost => 4` 等同最低成本，GPU 暴力破解极易；第 14 行提升至 `cost => 12`，符合 OWASP 对 bcrypt 工作因子的下限建议，位置在 sink 参数构造处，防御完整。
5. 第 17–20 行 base64 编解码仅为编码而非加密/哈希用途，且 default 分支不涉及凭证存储场景，按 minimal pair 纪律保持原样不动。
6. 第二入口检查：CLI 入口 `$argv[1]/$argv[2]` 与 HTTP 入口共用同一组函数与 switch 控制流（第 23–33 行），所有分支均落入已加固的三个哈希函数或无害的 base64 编码，替代通道无残留弱哈希路径。
