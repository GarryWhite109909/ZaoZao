```code
import json
from flask import Flask, request, render_template_string
from markupsafe import escape

app = Flask(__name__)

DEFAULT_OPTIONS = {
    'completeHTMLDocument': False,
    'metadata': False,
    'disallowRawHTML': False,
}

@app.route('/render', methods=['POST'])
def render_doc():
    # 用户提交的渲染配置（JSON 字符串）
    raw_opts = request.form.get('options', '{}')
    try:
        opts = {**DEFAULT_OPTIONS, **json.loads(raw_opts)}
    except (json.JSONDecodeError, TypeError):
        opts = dict(DEFAULT_OPTIONS)

    title = request.form.get('title', '')
    body = request.form.get('body', '')

    if opts.get('completeHTMLDocument'):
        # 拼接完整 HTML 文档，标题经 markupsafe.escape 转义后再进入 <title>
        safe_title = str(escape(title))
        html = '<!DOCTYPE html><html><head><title>' + safe_title + '</title></head><body>' + body + '</body></html>'
    else:
        html = body

    return render_template_string(html)
```

2. 第 20-21 行追踪主漏洞链：`title` 在 `completeHTMLDocument` 为真时被直接字符串拼接进 `<title>` 标签内，随后第 25 行 `render_template_string(html)` 将其作为模板渲染输出——这是 sink。由于 `render_template_string` 只对模板变量做自动转义，此处是手工拼接的原始 HTML 字符串，自动转义不生效，攻击者提交 `</title><script>alert(1)</script>` 即可注入脚本，构成 CWE-79。

4. 第 23 行的 `body` 保持原样未改动：按 minimal pair 要求只修复目标漏洞所在的 title 注入流，body 流与原代码完全一致，保证对照局部性。
