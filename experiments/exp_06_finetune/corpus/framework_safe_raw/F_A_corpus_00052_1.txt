```php
<?php

namespace App\Http\Controllers;

use Illuminate\Http\Request;
use Illuminate\Support\Facades\Storage;
use App\Services\DbBackupService;
use App\Jobs\ImportContentJob;

class DbController extends Controller
{
    // 白名单：仅允许下载这些精确的备份文件名
    private const ALLOWED_BACKUPS = [
        'content-backup.json',
        'users-backup.json',
        'orders-backup.json',
    ];

    public function exportContent(Request $request)
    {
        $filename = $request->input('filename');

        if ($filename) {
            // 白名单精确匹配，拒绝任何包含路径分隔符或不在允许集内的文件名
            if (!in_array($filename, self::ALLOWED_BACKUPS, true)) {
                abort(404);
            }

            $path = 'backups/' . $filename;

            if (!Storage::disk('local')->exists($path)) {
                abort(404);
            }

            return response()->download(
                storage_path('app/' . $path),
                basename($filename)
            );
        }

        return response()->streamDownload(function () {
            echo app(DbBackupService::class)->backup();
        }, config('app.name') . '-backup.json');
    }

    public function importContent(Request $request, ImportContentJob $importer)
    {
        $request->validate(['file' => 'required|file']);

        return $importer->importFromFile(
            $request->file('file')->getRealPath(),
            ['user_email' => $request->user()->email]
        );
    }
}
```

1. 第 20 行 `$request->input('filename')` 是用户可控输入点；第 47 行上传文件与第 48 行用户 email 是第二入口 `importContent` 的输入点。
2. 原漏洞链：第 20 行 filename → 第 23 行拼接 `'backups/' . $filename` → 第 32 行 `storage_path()` → 第 33 行 `response()->download()` sink。攻击者传 `../../.env` 可读取任意文件（CWE-22）。
3. 修复位置正确性：在第 26 行、sink 之前用严格白名单 `in_array(..., ALLOWED_BACKUPS, true)` 精确匹配整个文件名。类型正确性：全等比较字符串常量集合，任何含 `/`、`\`、`..` 的输入必然不在白名单内，无法绕过；这是框架无关的精确允许集防御，非黑名单/正则过滤。
4. 攻击面覆盖完整性：白名单匹配的是完整原始输入而非子串，覆盖了绝对路径、相对遍历、URL 编码变体等所有路径遍历形态；第 29-31 行的 exists/download 仅在白名单通过后执行，download 路径完全由服务端常量决定。
5. 第二入口检查：`importContent` 中第 46 行 validate 使用框架原生 file 规则，第 48 行 `getRealPath()` 来自 Laravel 上传临时目录而非用户可控路径字符串，email 为 ORM 参数化写入，无路径遍历数据流，保持原样以维持 minimal pair 局部对照性。
6. 结论：修复后无 CWE-22 数据流，其余业务逻辑、DI、队列用法不变。
