```python
from fastapi import FastAPI, Request
import redis
import json

app = FastAPI()
rds = redis.Redis(host="localhost", port=6379, db=0)

@app.get("/cache/{key}")
async def get_cached_aggregate(key: str):
    raw = rds.get(key)
    if raw is None:
        return {"error": "not found"}
    obj = json.loads(raw)
    return {"result": str(obj)}

@app.post("/cache/{key}")
async def put_cached_aggregate(key: str, request: Request):
    body = await request.body()
    json.loads(body)  # validate JSON before storing
    rds.set(key, body)
    return {"status": "stored"}
```

1. 第 9 行：用户可控输入点为路径参数 `key`；第 17 行：POST 请求体 `body` 完全由客户端控制，是反序列化数据的来源（source）。
2. 第 12 行原代码 `pickle.loads(raw)` 是 sink：raw 来自 Redis，而 Redis 中内容由第 18 行直接写入攻击者可控的请求体，构成完整污点链 source→sink。
3. 防御方式：将第 3 行的 `import pickle` 替换为 `import json`，第 12 行改为 `json.loads(raw)`。JSON 解析只产生纯数据结构（dict/list/str/num），不会执行任何对象构造或代码，类型上杜绝了任意代码执行；位置上精确替换了唯一 sink 调用。
