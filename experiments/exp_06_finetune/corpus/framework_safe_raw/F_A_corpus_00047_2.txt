```code
<?php
// rewrite_target.php — legacy front controller that rewrites request paths
// before dispatching to internal handlers, mimicking ingress rewrite-target.

$rewriteRules = [
    ['regex' => '#^/api/v1/(.*)$#i', 'replacement' => '/internal/$1'],
    ['regex' => '#^/legacy/redirect/(.*)$#i', 'replacement' => 'https://partner.example.com/$1'],
];

// Whitelist: the only external hosts a redirect may ever point to.
$allowedRedirectHosts = [
    'partner.example.com',
];

$requestUri = $_SERVER['REQUEST_URI'] ?? '/';
$path = parse_url($requestUri, PHP_URL_PATH);
$query = parse_url($requestUri, PHP_URL_QUERY);

foreach ($rewriteRules as $rule) {
    if (!preg_match($rule['regex'], $path)) {
        continue;
    }
    $newTarget = preg_replace($rule['regex'], $rule['replacement'], $path);

    // Absolute-URL replacement: issue a redirect, carrying over the query string.
    if (preg_match('#^https?://#i', $newTarget)) {
        // Defense 1 (Open Redirect): parse the URL and enforce an exact-match
        // host whitelist before emitting any Location header.
        $parts = parse_url($newTarget);
        if (!is_array($parts)
            || !isset($parts['host'])
            || !in_array(strtolower($parts['host']), $allowedRedirectHosts, true)) {
            http_response_code(403);
            echo 'Forbidden';
            exit;
        }
        $redirectUrl = $newTarget . ($query && strpos($newTarget, '?') === false ? '?' . $query : '');
        header('Location: ' . $redirectUrl, true, 302);
        exit;
    }

    // Internal rewrite: map the rewritten path onto the local file tree.
    $docRoot = rtrim($_SERVER['DOCUMENT_ROOT'], '/');

    // Defense 2 (Path Traversal): canonicalize first, then verify containment.
    // The candidate path is built from the raw (non-decoded) rewrite result,
    // so encoded sequences like %2e%2e%2f cannot smuggle traversal past the
    // realpath() canonicalization step.
    $candidate = $docRoot . '/' . ltrim($newTarget, '/');
    $targetFile = realpath($candidate);

    if ($targetFile === false || !is_file($targetFile)) {
        http_response_code(500);
        echo 'Internal Server Error';
        exit;
    }

    // Containment check: the resolved real path must remain inside DOCUMENT_ROOT.
    if (strpos($targetFile, rtrim(realpath($docRoot), DIRECTORY_SEPARATOR) . DIRECTORY_SEPARATOR) !== 0) {
        http_response_code(403);
        echo 'Forbidden';
        exit;
    }

    header('X-Forwarded-Prefix: ' . $path);
    readfile($targetFile);
    exit;
}

http_response_code(404);
echo 'Not Found';
```

1. 第 20 行：用户可控输入点为 `$_SERVER['REQUEST_URI']`，经 `parse_url` 拆出 `$path` 与 `$query`；这是唯一外部输入源，后续所有数据流均由它派生。
2. 第 30–31 行（内部重写流）：原代码用 `urldecode($newTarget)` 后拼接 `DOCUMENT_ROOT` 再 `realpath`，攻击者可用 `/api/v1/%2e%2e%2f%2e%2e/etc/passwd` 使解码后的 `..` 越出文档根。修复后第 33–35 行改为先对未解码路径做 `realpath` 规范化——realpath 会解析并消除任何形式的 `..` 序列，类型上返回绝对规范路径或 false。
3. 第 44–48 行：在 `readfile` sink 前增加包含性校验，要求规范化结果必须以 `realpath(DOCUMENT_ROOT)` 为前缀且位于其目录分隔符之后，位置正确（紧贴 sink），覆盖了符号链接、编码绕过、规则注入等全部到达该 sink 的路径变体。
4. 第 24–32 行（开放重定向流）：原代码只要替换结果形如 `https?://` 就直接写入 `Location` 头，若规则被污染或 replacement 含用户段可跳任意域。修复后用 `parse_url` 提取 host 并与精确白名单 `in_array(..., true)` 比对，属于白名单精确允许集防御，非黑名单/正则过滤。
5. 第 38–40 行：白名单不匹配时统一返回 403 并终止，保证两条数据流的每个 sink（`header('Location: ...')`、`readfile`）之前都有强制检查点，无旁路分支。
6. 第二入口检查：`$query` 仅拼接到已通过 host 白名单的 URL 之后，不参与文件路径构造；`X-Forwarded-Prefix` 头仅回显原始 path 且不再进入文件系统操作，无其他可控 sink，替代通道结论为安全。
