```code
package com.example.fetch;

import org.springframework.web.bind.annotation.*;
import java.net.*;
import java.io.*;

@RestController
@RequestMapping("/api/fetch")
public class UrlFetchController {

    // 修复：不再对字符串做黑名单式判断，改为解析后用 InetAddress 做权威判定
    private boolean isPrivateAddress(InetAddress addr) {
        if (addr == null) return true;
        // isAnyLocalAddress 覆盖 0.0.0.0/::，isLoopbackAddress 覆盖 127.0.0.0/8 与 ::1，
        // isSiteLocalAddress 覆盖 10/8、172.16/12、192.168/16 以及 IPv6 fc00::/7
        if (addr.isAnyLocalAddress() || addr.isLoopbackAddress()
                || addr.isSiteLocalAddress() || addr.isLinkLocalAddress()
                || addr.isMulticastAddress()) {
            return true;
        }
        // 关键修复点：InetAddress.getByName 会把 ::ffff:x.x.x.x 规范化为 Inet4Address，
        // 因此映射形式无法再伪装成公网地址绕过检查；同时覆盖 100.64/10 CGNAT 段
        byte[] b = addr.getAddress();
        if (b.length == 4) {
            int a = b[0] & 0xff, s = b[1] & 0xff;
            return a == 10 || a == 127 || a == 0 || a >= 240
                    || (a == 172 && s >= 16 && s <= 31)
                    || (a == 192 && s == 168)
                    || (a == 100 && s >= 64 && s <= 127);
        }
        return false;
    }

    @GetMapping
    public String fetch(@RequestParam("url") String urlStr) throws Exception {
        URL url = new URL(urlStr);
        String scheme = url.getProtocol();
        // 白名单精确允许集：仅允许 http/https 协议
        if (!scheme.equals("http") && !scheme.equals("https")) {
            throw new IllegalArgumentException("blocked scheme");
        }
        // 修复核心：先做 DNS 解析得到真实 InetAddress（含 IPv6 映射字面量的规范化结果），
        // 在连接发生之前对解析出的地址做判定，消除 TOCTOU/DNS rebinding 窗口内的字符串级绕过
        InetAddress resolved = InetAddress.getByName(url.getHost());
        if (isPrivateAddress(resolved)) {
            throw new IllegalArgumentException("blocked");
        }
        // sink：使用已验证的 IP 直连，避免二次 DNS 解析引入 rebinding
        URI safeUri = new URI(scheme, null, resolved.getHostAddress(), url.getPort(), url.getPath(), url.getQuery(), null);
        HttpURLConnection conn = (HttpURLConnection) safeUri.toURL().openConnection();
        conn.setConnectTimeout(5000);
        try (BufferedReader r = new BufferedReader(
                new InputStreamReader(conn.getInputStream()))) {
            StringBuilder sb = new StringBuilder();
            String line;
            while ((line = r.readLine()) != null) sb.append(line);
            return sb.toString();
        }
    }
}
```

1. 第 30 行 `@RequestParam("url") String urlStr` 是唯一用户可控输入点，由 Spring MVC 参数绑定注入，与原代码一致。
2. 第 36-38 行新增协议白名单（http/https），属于精确允许集而非黑名单，阻断 file/gopher 等替代协议通道。
3. 第 41 行在 sink 之前调用 `InetAddress.getByName` 完成真实 DNS 解析；第 42-44 行对解析出的 `InetAddress` 对象做判定。类型正确性：判定对象是规范化的地址字节而非攻击者可控的原始字符串，`::ffff:c0a8:1`、十进制整数、八进制等 IPv4 字面量变体均被 JVM 统一规范化为 `Inet4Address` 后落入第 20-27 行的私网段判断，攻击面覆盖完整。
4. 第 46-48 行用 `resolved.getHostAddress()` 构造直连 URI，保证检查的地址与实际连接的地址是同一个，消除 DNS rebinding 的 TOCTOU 窗口；位置正确性：防御位于 `openConnection()` 这个 sink 之前的同一数据流上。
5. 第 13-18 行改用框架/JDK 原生安全 API（`isSiteLocalAddress` 等）替代手写正则与字符串 split 黑名单，符合有效防御要求。
6. 第二入口检查：该控制器仅 `/api/fetch` 一个 GET 映射，无其他 handler 或中间件转发通道；除 `urlStr` 外无其他用户可控字段进入网络请求流，结论为不存在未防护的替代入口。
