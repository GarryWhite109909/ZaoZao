```code
#!/usr/bin/env python3
"""deploy.py - 固定流程的本地部署脚本，无外部输入。"""

import subprocess

LOG_DIR = "/var/log/myapp"
APP_USER = "svc-app"
SERVICE_NAME = "myapp.service"
BACKUP_CMD = ["tar", "-czf", "/backup/app.tar.gz", "/opt/myapp"]

def rotate_logs():
    # 危险点1: subprocess.run, 实参全部为模块级常量拼接的字面量列表
    subprocess.run(["logrotate", "-f", "/etc/logrotate.d/myapp"], check=True)

def backup():
    # 危险点2: subprocess.call, 实参为常量列表 BACKUP_CMD
    return subprocess.call(BACKUP_CMD, check=False)

def restart_service():
    # 危险点3: subprocess.check_output, 命令与参数均为硬编码字面量/常量
    out = subprocess.check_output(
        ["systemctl", "restart", SERVICE_NAME],
        text=True,
        timeout=30,
    )
    print(out.strip())

if __name__ == "__main__":
    rotate_logs()
    backup()
    restart_service()
```

2. 第18行 `subprocess.call`：实参为第8行定义的模块级常量列表 `BACKUP_CMD`，其元素均为字符串字面量，赋值后从未被修改，无污点可达路径。
3. 第23-25行 `subprocess.check_output`：命令元素来自字面量与常量 `SERVICE_NAME`（第7行），且 `timeout=30`、`text=True` 亦为常量；函数仅在本文件 `__main__` 块中以零参数方式调用，不存在第二入口或被外部以可控参数调用的替代通道。
4. 结论：所有危险 sink 的实参来源均为常量/字面量，污点源集合为空，任何 sink 均不可达污点数据。
