```python
from fastapi import FastAPI, UploadFile, File, Form, HTTPException
import hashlib

app = FastAPI()

# 模拟构件签名服务：对上传的制品计算摘要并生成签名记录
ARTIFACT_STORE = {}
SIGNED_LOG = []

@app.post("/artifacts/sign")
async def sign_artifact(
    file: UploadFile = File(...),
    key_id: str = Form(...)
):
    content = await file.read()

    # 使用 SHA-1 计算制品摘要（弱哈希）
    digest = hashlib.sha1(content).hexdigest()
    signature = f"sig-{key_id}-{digest}"

    ARTIFACT_STORE[digest] = {"filename": file.filename, "content": content}
    SIGNED_LOG.append(signature)

    return {"artifact_digest": digest, "signature": signature}

@app.get("/artifacts/{digest}")
async def get_artifact(digest: str):
    artifact = ARTIFACT_STORE.get(digest)
    if not artifact:
        raise HTTPException(status_code=404, detail="not found")
    return {"filename": artifact["filename"], "size": len(artifact["content"])}
```

分析：
1. 第 12 行 `sign_artifact` 路由通过 FastAPI 的 `UploadFile`/`Form` 习语接收外部输入：上传文件内容（第 14 行读取）与 `key_id` 表单参数，这是唯一的外部输入入口。
2. 第 17 行将文件内容直接送入 `hashlib.sha1()` 计算 SHA-1 摘要，第 18 行用该摘要构造签名并写入存储，构成 source→sink 数据流：外部上传内容 → SHA-1 弱哈希 → 签名与制品索引。
3. 全链路无任何防御措施：没有哈希算法白名单、没有强制使用 SHA-256/SHA-3 的校验、也没有对摘要碰撞的二次验证；攻击者可利用 SHA-1 碰撞伪造同摘要但内容不同的制品替换原制品。
4. 第二入口确认：第 24 行 `/artifacts/{digest}` 路由以 digest 作为查找键返回制品信息，使碰撞摘要可直接命中被替换的制品，放大了 CWE-327 的影响面；不存在其他路由或替代通道。
5. 结论：存在 CWE-327（使用 SHA-1 弱哈希进行完整性/签名），风险等级 High。
