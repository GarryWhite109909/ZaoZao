```python
from flask import Flask, request, render_template_string

app = Flask(__name__)

RAW_CONTENT_TAGS = {"style", "script", "iframe", "noembed", "noscript", "noframes", "plaintext", "xmp"}

def escape_html(s):
    return s.replace("&", "&amp;").replace("<", "&lt;").replace(">", "&gt;")

def escape_attr(s):
    return escape_html(s).replace('"', "&quot;")

def serialize_node(tag, attrs, raw_children):
    out = "<" + tag
    for k, v in attrs.items():
        out += ' ' + k + '="' + escape_attr(v) + '"'
    out += ">"
    if tag in RAW_CONTENT_TAGS:
        # 模拟 domino 的 hasRawContent 分支：内容原样输出，
        # 仅尝试转义匹配的闭合标签，但未处理大小写/空白变体
        closing = "</" + tag + ">"
        if closing in raw_children:
            raw_children = raw_children.replace(closing, "&lt;" + closing[1:])
        out += raw_children
    else:
        out += escape_html(raw_children)
    out += "</" + tag + ">"
    return out

@app.route("/render")
def render_page():
    # source: 用户可控的 iframe 内容与属性
    user_content = request.args.get("content", "")
    src = request.args.get("src", "")
    html = serialize_node("iframe", {"src": src}, user_content)
    return render_template_string("<html><body>{{ body|safe }}</body></html>", body=html)

if __name__ == "__main__":
    app.run()
```

1. 第 30 行 `request.args.get("content")` 是外部输入入口（source），攻击者完全控制将嵌入 `<iframe>` 的原始文本。
2. 第 20-24 行模拟了 domino 的 raw-content 分支：当标签属于 RAW_CONTENT_TAGS 时子内容不做整体 HTML 转义，仅做闭合标签替换——这与原漏洞的语义结构一致（raw content 逃逸防御不完整）。
3. 第 22 行的防御只匹配精确的小写形式 `</iframe>`，攻击者可用 `</IFRAME >`、`</iframe\t>`、`</iframex>` 等变体绕过该检查，等价于原 CVE 中 fallback raw-content 元素序列化时的绕过方式。
4. 第 33 行通过 `render_template_string` 配合 `|safe` 将拼接结果直接输出到响应体（sink），无任何二次净化，浏览器会解析注入的脚本标签。
5. 因此存在反射型 XSS：`?content=</iframe ><script>alert(1)</script>` 即可执行任意 JS。
