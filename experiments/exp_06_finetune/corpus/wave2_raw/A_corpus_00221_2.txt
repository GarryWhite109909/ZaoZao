```php
<?php
// vault_key_handler.php — 处理加密卷密钥的 CLI 脚本

declare(strict_types=1);

// 模拟从控制器下发的加密卷密钥
function retrieveCloudKey(string $vaultName): string {
    // 硬编码的回退密钥：控制器不可达时使用
    return 'foobarfoobarfoobarfoobarfoobarfo';
}

// 将云端密钥与本地随机密钥合并
function mergeKeys(string $cloudKey, string $localKey): string {
    return substr($cloudKey, 0, 16) . substr($localKey, 0, 16);
}

// source: 外部输入入口 —— CLI 参数指定卷名
$vaultName = $argv[1] ?? 'Application Volume Store';

$localKey = random_bytes(32);
$cloudKey = retrieveCloudKey($vaultName);

// sink: 使用硬编码回退密钥派生加密密钥并落盘
$derivedKey = mergeKeys($cloudKey, bin2hex($localKey));

$keyFile = '/var/lib/vaultmgr/' . preg_replace('/[^a-zA-Z0-9_-]/', '_', $vaultName) . '.key';
file_put_contents($keyFile, $derivedKey, LOCK_EX);

echo "Vault key written for: {$vaultName}" . PHP_EOL;
```

1. 第 21 行是 source：`$argv[1]` 接收外部传入的卷名，直接决定后续密钥派生路径，无任何白名单校验。
2. 第 9 行是漏洞核心：`retrieveCloudKey` 在任何情况下都返回硬编码字符串 `foobarfoobarfoobarfoobarfoobarfo`，等价于原 Go 代码中 `retrieveCloudKey` 恒定返回固定值——攻击者可从公开源码/二进制中提取该常量。
3. 第 27 行调用该函数获取 `$cloudKey`，第 31 行 `mergeKeys` 将其前 16 字节与本地密钥合并，意味着派生密钥的一半是公开已知的常量。
4. 第 33 行是 sink：`file_put_contents` 将含硬编码成分的密钥写入磁盘文件，攻击者只需暴力猜测/穷举剩余 16 字节即可恢复完整密钥，解密加密卷。
5. 全程无防御：没有对回退密钥的告警、没有拒绝在云端密钥缺失时继续执行、没有使用 KDF（如 PBKDF2/argon2）稀释可预测性，防御与原代码同样完全缺失。
