class LocalhostOnlyHTTPServer(tornado.httpserver.HTTPServer):
    """Reject any connection whose socket peer address is not loopback."""

    def handle_stream(self, stream, address):
        try:
            peer_ip = ipaddress.ip_address(address[0])
        except ValueError:
            stream.close()
            return
        if not (
            peer_ip.is_loopback
            or (peer_ip.is_link_local and str(peer_ip).startswith("fe80::1"))
        ):
            logger.warning(f"Rejected non-local connection from {address[0]}")
            stream.close()
            return
        super().handle_stream(stream, address)

## Vuln 版分析（CWE-441）

1. Web API 服务器默认绑定 `127.0.0.1:8081`，开发者隐式假设“能连上这个端口的就是本机可信用户”。
2. 但同一进程还运行着代理服务器，默认绑定 `*:8080`，接受任意远程客户端。
3. 远程攻击者通过代理发起对 `127.0.0.1:8081` 的请求时，代理将其转发到本机回环地址，源地址变为 localhost——服务器只看到“本地连接”，信任边界被代理流量穿越。
4. 于是恶意客户端可调用内部 API（读取/修改 flows、options、执行拦截等），实现未授权访问。

}

## Safe 版分析

1. 唯一语义修正：新增 `LocalhostOnlyHTTPServer`，在 `handle_stream` 中用 **socket 对端真实地址**（`address` 参数，来自内核 accept 信息）判断是否为 loopback，非回环直接关闭连接。该检查发生在任何 HTTP 解析之前，无法被 X-Forwarded-For、Host 头或任何应用层字段伪造。
2. 覆盖面：无论请求经代理转发、DNS rebinding 后的直连、还是其他任何路径到达该端口，只要 TCP 对端不是本机回环地址即被拒绝；而经代理转发的流量其对端地址恰是本机回环——这正是漏洞利用的必经通道，被此检查精确封堵。
3. 其余代码逐 token 保持一致，仅替换 HTTPServer 类并新增 import 与子类，不引入新的信任假设。
4. 因此“仅本机用户可访问内部 API”这一安全不变量重新成立，攻击面被完整消除。
