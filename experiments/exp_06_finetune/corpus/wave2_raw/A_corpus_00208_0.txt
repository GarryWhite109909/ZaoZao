```code
from flask import Flask, request, jsonify
import re

app = Flask(__name__)

# 依赖此净化函数的下游会直接渲染返回的 SVG（信任其已无脚本）
def sanitize_svg(svg_text):
    # 仅移除 <script>...</script> 标签块，黑名单式过滤
    cleaned = re.sub(r'<script\b[^>]*>.*?</script\s*>', '', svg_text, flags=re.IGNORECASE | re.DOTALL)
    return cleaned

@app.route('/api/svg/clean', methods=['POST'])
def clean_svg():
    svg_text = request.form.get('svg', '')
    if not svg_text:
        return jsonify({'error': 'missing svg field'}), 400
    result = sanitize_svg(svg_text)
    return result, 200, {'Content-Type': 'image/svg+xml'}

@app.route('/view/<doc_id>')
def view_doc(doc_id):
    # 第二入口：从存储读取并直接内联渲染用户上传的 SVG 片段
    snippet = load_user_snippet(doc_id)  # 假设来自数据库的用户内容
    return f'<div class="embed">{snippet}</div>'

def load_user_snippet(doc_id):
    import sqlite3
    conn = sqlite3.connect('docs.db')
    row = conn.execute('SELECT body FROM snippets WHERE id=?', (doc_id,)).fetchone()
    conn.close()
    return row[0] if row else ''
```

2. 第 15-16 行的防御是黑名单 + 正则字符串删除：仅匹配 `<script>` 标签对，无法覆盖 `<svg onload=alert(1)>`、`<foreignObject>` 内嵌 HTML、`<use href="data:...">`、大小写/空白变体如 `<scr<script>ipt>` 拼接绕过等，与原 SVGO 插件“只删 script 元素、其余可执行向量残留”的缺陷语义一致，属可绕过防御。
3. 第 23-26 行是第二入口 `/view/<doc_id>`：从数据库取出的用户片段在第 25 行未经任何净化直接拼入 HTML 模板，构成独立的存储型 XSS 通道，进一步证明净化缺失不是单点疏漏。
4. 综上两条数据流均无有效防御，结论为存在 CWE-79。
