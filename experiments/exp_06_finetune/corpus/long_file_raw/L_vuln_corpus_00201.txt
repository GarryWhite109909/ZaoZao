## 编号分析

1. **第 1–30 行（文件头/常量区）**：本文件是 league/commonmark 的纯工具类 `RegexHelper`，无 HTTP 入口、无路由、无文件读写，source 只能来自调用方传入的字符串参数。所有正则常量在此定义。

2. **第 33–56 行（PARTIAL_* 常量）**：用于 Markdown 解析的 HTML 标签识别正则，仅做“是否像 HTML”判定，不产生 sink。

3. **第 58–62 行**：
   - 第 59 行 `REGEX_UNSAFE_PROTOCOL = '/^(?:javascript|vbscript|file|data):/i'` —— **黑名单式协议过滤**，且锚定在字符串开头。
   - 第 60 行 `REGEX_SAFE_DATA_PROTOCOL = '/^data:image\/(?:png|gif|jpeg|webp)/i'` —— data 协议白名单，未含 svg（svg 已被排除），但同样锚定开头且不做字符归一化。

4. **第 64–110 行（isEscapable/isWhitespace/isLetter/matchAt/matchFirst）**：纯匹配工具，无安全决策，无 sink。

5. **第 112–122 行（unescape）**：反转义反斜杠并解码 HTML 实体，输出交回解析器，本身不直接进入 HTML 输出 sink。

6. **第 124–186 行（getHtmlBlockOpenRegex/getHtmlBlockCloseRegex）**：按枚举类型返回正则；非法 type 抛异常（第 158、185 行），无注入面。

7. **第 188–193 行（isLinkPotentiallyUnsafe）——核心安全决策点**：
   ```php
   return preg_match(self::REGEX_UNSAFE_PROTOCOL, $url) !== 0
       && preg_match(self::REGEX_SAFE_DATA_PROTOCOL, $url) === 0;
   ```
   数据流：source = 调用方传入的用户可控 `$url`（Markdown 链接目标）→ sink = 该函数返回值决定链接是否被保留为可点击 HTML `<a href>`。
   **防御有效性验证**：这是黑名单 + 锚定开头 + 未归一化输入，按分析要求视为可绕过：
   - 浏览器在 URL scheme 解析时会剥离制表符与换行符（WHATWG URL 规范），因此输入 `jav\tascript:alert(1)` 或 `java\nscript:alert(1)` 不匹配第 59 行的正则（`\t`/`\n` 打断了字面量 `javascript`），函数返回 false（判定“安全”），但浏览器实际执行 javascript 协议 → 存储型/反射型 XSS。
   - 同理前导控制字符或全角变体等归一化差异均可绕过锚定开头的黑名单。
   - 第二入口确认：该类无其他入口；替代通道方面，即使部分调用方做了额外转义，本函数作为公共 API（public static）也被下游直接用于安全判断，防御责任落在此处即失效。

8. **结论**：存在漏洞——不安全的协议黑名单校验（CWE-184 不完整的黑名单 / 导致 CWE-79 XSS）。风险等级：中高（需下游将返回 false 的 URL 直接渲染为 href 才触发，但该假设正是此 API 的设计用途）。
