## 编号分析（逐函数、行号锚定）

**入口点枚举**：本文件无网络路由/文件/环境变量入口，唯一 source 是 Markdown token 中的用户可控字符串（`token["raw"]`、`attrs`、`url`、`title`、`text`、`html`、`info`），sink 是各 render 方法拼接的 HTML 输出。

1. **第 41-54 行 `render_token`**：仅做分发，不直接拼接 HTML，数据流向下方各方法。
2. **第 56-70 行 `safe_url`**：核心防御。先经 `_unquote_url` 三轮解码再小写化（第 58 行），可拦截 `%6A%61vascript:` 等编码绕过；黑名单命中返回 `#harmful-link`（第 65 行）；未命中仍走 `escape_text(url)`（第 67 行）转义引号与特殊字符，防止属性逃逸。白名单 `GOOD_DATA_PROTOCOLS`（第 26-31 行）只放行四种图片 data URI，且 `data:` 前缀整体在黑名单中，逻辑为“黑名单命中但属图片白名单才放行”，无 `data:text/html` 泄漏路径。`allow_harmful_protocols=True` 是显式开发者选择（第 59 行），不构成默认漏洞。
3. **第 72-75 行 `text`**：默认 `_escape=True` 走 `escape_text`；`safe_entity` 仅在调用方显式关闭转义时使用，属配置项而非缺陷。

6. **第 98-100 行 `codespan`**：内容强制 `escape_text`，安全。
7. **第 107-110 行 `inline_html` / 第 126-129 行 `block_html`**：默认 `escape=True` 时转义；`escape=False` 输出原始 HTML 是库文档声明的信任模式（调用方自担风险），非默认路径漏洞。
8. **第 112-115 行 `heading`**：id 经 `escape_text` 转义，level 为解析器产生的整数，安全。
9. **第 122-131 行 `block_code`**：info 先 `safe_entity` 再取首词放入 class 属性，code 强制转义，安全。
10. **第 133-143 行 `list`**：start 经 `str()` 写入属性，来自有序列表起始数字解析，攻击者可控性极低且无引号逃逸面（值不含引号时 `str(int)` 安全）；即使异常输入也仅限属性内。
11. **第 145-147 行 `list_item`、第 77-80 行 emphasis/strong、第 118-120 行 block_quote/block_text**：透传子渲染结果，子节点已各自转义。
