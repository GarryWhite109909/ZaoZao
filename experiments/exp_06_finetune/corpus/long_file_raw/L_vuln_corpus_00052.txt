## 编号分析

**入口点枚举（全文）：**

1. **第 15–37 行 `backupContent`**：options 仅 `include/filename`，且第 26–29 行对 `include` 做白名单校验（`exporter.BACKUP_TABLES`）；`query` 只调用 `dbBackup.backup(frame.options)`，无用户可控文件路径 sink。安全。

2. **第 39–75 行 `exportContent`**：
   - 第 61 行 `if (frame.options.filename)` —— **source：HTTP 查询参数 `filename`，用户完全可控**；
   - 第 62 行 `dbBackup.readBackup(frame.options.filename)` —— **sink：文件读取操作**；
   - **防御验证**：本控制器内对 `filename` 无任何校验（validation 块只覆盖 `include`，见第 44–50 行）。在 Ghost 的 `data/db/backup.js` 中，`readBackup` 直接以 `path.join(backupDir, filename)` 拼接后读取（历史版本未做 resolved 路径前缀检查），传入 `filename=../../../../../etc/passwd` 或 Windows 下 `..\..\` 即可逃逸备份目录。黑名单/扩展名过滤不存在；即使存在也按规则视为可绕过。**source→sink 数据流成立，为路径遍历任意文件读取（对应真实漏洞 GHSA/CVE-2023-40028）**。
   - 第 70–74 行 `exporter.doExport` 分支不含用户路径。安全。

3. **第 77–103 行 `importContent`**：sink 为 `importFromFile(frame.file)`，受框架上传处理与 `permissions: true` 约束，导入器内部有内容校验；email 来自服务端数据。低风险，非本次结论。

4. **第 105–117 行 `inlineMedia`**：`frame.data.domains` 传给 media-inliner，用于 SSRF 面，但该端点要求 Admin 权限（复用 importContent 权限），且 domains 由已认证管理员提供，属预期功能；media-inliner 内部有域名/IP 校验。不构成主要漏洞。

5. **第 119–152 行 `deleteAllContent`**：无外部参数进入查询，操作固定删除 posts/tags，需管理员权限。安全。

**第二入口/替代通道核查**：`filename` 参数仅经 API 框架透传至第 62 行，无其他中间件清洗；`backupContent` 的 `filename` option 未被其 query 使用，不构成额外通道。
