## 编号分析（全文逐函数）

1. **第 20–40 行（构造函数）**：`is_cli()` 检查，非 CLI 直接 `exit`。这是唯一的访问控制防线——所有公开方法仅能通过命令行触发。Web 端无法直接路由到这些方法。

2. **第 47–54 行 `install()`**：无用户输入，固定调用 `migrate('fresh')` 与 `seed()`。无 source→sink 流。

4. **第 80–83 行 `seed()`**：无外部输入。

5. **第 93–96 行 `backup()`**：**关键点**。`$GLOBALS['argv'][3]`（第 95 行）未经任何校验/规范化直接传入 `$this->instance->backup()`。这是文件路径型 source→sink 数据流：
   - source：第 95 行 `$GLOBALS['argv'][3]`（命令行参数）；
   - sink：`instance->backup()` 内部大概率用于目录创建/文件写入（备份输出目录）；
   - 防御：**无任何过滤、realpath 校验或目录白名单**；
   - 影响：本地 CLI 用户可传入任意路径（如 `../../` 或敏感目录），导致备份 SQL 文件写入任意可写位置，或读取上下文异常。属于 CWE-22（路径遍历）/ CWE-73（外部可控文件名）。但因构造函数强制 CLI，攻击者需已具备本地执行权限，故风险等级为低。

6. **第 105–119 行 `sync()`**：数据来自数据库（providers），经 `filter_var(..., FILTER_VALIDATE_BOOLEAN)` 判断后调用 `Google::sync((string)$provider['id'])`。id 来自数据库自增主键，非直接用户输入；即便 DB 被污染也属二阶问题且此处为 CLI 上下文。无可利用流。

7. **第 128–150 行 `help()`**：纯静态输出，`config('version')` 为常量。无漏洞。

8. **第二入口核查**：全文件无其他 HTTP 可达入口；`require_once Google.php` 仅引入同步逻辑；`response()` 输出内容均为常量字符串，无反射型 XSS 面。
