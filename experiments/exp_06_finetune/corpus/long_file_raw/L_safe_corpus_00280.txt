## 编号分析

**入口点枚举（全文）**
1. 第 152–170 行：`gotOpts` 定义了全部钩子入口——`init`（仅测试环境，第 156 行）、`beforeRequest`（第 157 行）、`beforeRedirect`（第 158 行）。所有外部请求都经 `externalRequest = got.extend(gotOpts)`（第 165 行），source 为调用方传入的任意 URL。
2. 环境通道：第 71 行、第 84 行、第 116 行读取 `config.get('env')`；第 155 行读取 `process.env.NODE_ENV`。无其他文件/回调入口。

**数据流逐一验证**

3. **URL 校验**（第 83–96 行 `errorIfInvalidUrl`）：hostname 缺失或非 URL 即抛错。注意第 85 行 development 直接放行——属设计内豁免，生产环境不受影响。

4. **第一道 DNS 检查**（第 98–113 行 `errorIfHostnameResolvesToPrivateIp`）：对 `options.url.hostname` 做 `dnsPromises.lookup` 后交给 `isPrivateIp`。存在经典 TOCTOU/DNS rebinding 缺口，但见第 7 条被连接层兜底。

5. **IP 归一化与私网判定**：
   - 第 8–19 行 `normalizeIPv4` 用 WHATWG URL 解析器把十进制/八进制/十六进制/整数形式归一为点分十进制，覆盖了 `2130706433`、`0x7f.0.0.1`、`0177.0.0.1` 等混淆写法；非 IPv4 返回 null。
   - 第 21–33 行 `normalizeIPv6` 同理处理括号形式。
   - 第 35–86 行 `isPrivateIPv4` 覆盖 10/8、172.16/12、192.168/16、127/8、169.254/16、100.64/10、198.18/15、0/8、240/4 及广播地址。
   - 第 88–141 行 `isPrivateIp`：空值 fail-closed（第 91–93 行）；`::ffff:` 点分与十六进制映射均展开重检（第 95–110 行）；归一化后再次匹配映射形式（第 129–140 行）；无法识别的格式一律返回 true（第 141 行）。黑名单式检查的常见绕过（非标准进制表示、映射地址、尾随点等）均被归一化后拦截，未发现可绕过形态。未覆盖 192.0.0.0/24、198.51.100/24 等文档段，但这些不构成 SSRF 内网访问面。

6. **siteUrl 豁免**（第 103–107 行、第 121–124 行）：请求 host 与配置的 Ghost 站点 host 相同则放行。这是允许回调本实例的设计需要；host 含端口精确比较，攻击者无法借此扩大到同机其他端口（host 不同即进入检查流程）。前提是生产环境 `config.get('url')` 配置可信，属部署假设而非代码缺陷。

7. **连接层权威校验**（第 115–150 行 `installSafeDnsLookup`）：在 `beforeRequest` 与 `beforeRedirect` 中都安装自定义 `options.lookup`，在真正建立 TCP 连接时用同一份解析结果复检 `isPrivateIp`（第 133、145 行），并正确处理 `all:true` 数组结果（第 127–137 行）。这消除了第 4 条的 rebinding TOCTOU 窗口：Node http 模块实际连接的就是被校验的那个 IP。注释（第 143–144 行）也说明了这一点。

8. **重定向链**：`beforeRedirect` 钩子（第 158 行）对每个跳转目标重新执行私有 IP 检查并重新安装安全 lookup；got 本身限制重定向协议为 http(s)，无 file/gopher 等替代协议通道。got 的 `dnsLookup` 公共属性不透传到原生请求的问题已被第 146 行注释说明并用原生 `lookup` 规避。

9. **第二入口核查**：除上述三个钩子外，模块仅导出 `externalRequest` 及两个测试辅助（第 166–167 行）；`isPrivateIp` 导出只读，无独立可触发 sink。无环境变量注入路径（NODE_ENV 仅影响是否禁用重试，第 155–156 行）。

10. **残余风险**：development 环境全放行（第 71、85、117 行）依赖部署纪律；若攻击者能控制 `config.get('url')` 则第 103 行豁免可被滥用——但该值属服务端受信配置，不在本文件威胁模型内。综合判断：防御为归一化 + 双层（DNS 前置 + 连接时）校验 + 重定向逐跳复检，未发现有效绕过路径。
