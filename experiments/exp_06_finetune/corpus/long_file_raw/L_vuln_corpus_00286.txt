1. **入口点枚举（全文）**

   - `MakeRequests`（第41行）：入口为 openRTBRequest，其中 `Imp[0].Ext` 是外部输入 source。
   - `getHeaders`（第30行）：UA/IP 写入 header，属正常转发，无注入 sink。
   - `getImpressionExt`（第76行）：解析 `imp.Ext` → `bidderExt.Bidder` → `ExtAcuityAds`，包含 `Host`、`AccountID` 字段，完全由请求方控制，且无任何校验/白名单。
   - `buildEndpointURL`（第96行）：将攻击者控制的 `params.Host`、`params.AccountID` 直接填入 endpoint 模板。
   - `MakeBids`（第110行）：解析 bidder 响应，仅 JSON 反序列化，无危险 sink。

2. **source→sink 数据流验证**
   - source：第76–90行 `getImpressionExt` 返回的 `acuityAdsExt.Host / AccountID`（来自 HTTP 请求体）。
   - 中转：第94–100行 `buildEndpointURL` 无任何过滤、白名单或 URL 校验；黑名单/正则也不存在。
   - sink：第46–48行 `url` 被直接赋给 `RequestData.Uri`，prebid-server 将向该 URL 发起出站 POST 请求。
