## 编号分析

1. **第 22–27 行（环境变量入口）**：`OAUTH_CLIENT_ID/SECRET/SCOPES`、`OPENID_PROVIDER_URL`、`SPACE_HOST` 均来自环境变量，属部署者控制，非攻击者可控 source，无直接风险。

2. **第 60–66 行（SessionMiddleware）**：secret 由 `OAUTH_CLIENT_SECRET` 派生，`https_only=True`、`same_site="none"`。`same_site=none` 是 Space iframe 场景所需，配合 `https_only` 可接受。

3. **第 84–89 行 `/login/huggingface`**：调用 `_generate_redirect_uri(request)`（第 190–214 行）。在 Space 中 redirect_uri 强制为 `https://{SPACE_HOST}/login/callback`，host 来自环境变量而非用户输入，不可被注入；`_target_url` 仅作为 query 参数编码进 redirect_uri，不构成跳转目标。非 Space 时使用 `request.url_for(...)`，安全。OAuth state 由 authlib 处理，CSRF 防御有效。

4. **第 91–141 行 `/login/callback`**：`authorize_access_token(request)` 由 authlib 校验 state 与 code，防御有效。`MismatchingStateError` 分支中 `nb_redirects`/`_target_url` 来自 query params，仅用于构造 `/login/huggingface?...` 的相对 URI（第 118–124 行），且经 `urlencode` 编码，无注入面。超过重试上限后跳转到 `https://{SPACE_HOST}` + 相对路径，host 为环境变量，安全。

5. **第 143–148 行 `/logout`**：仅清除 session 并调用 `_redirect_to_target`，无其他 sink。

6. **第 151–176 行 mocked 路由**：本地调试用，session 写入固定 mock 信息，`_target_url` 同样进入 `_generate_redirect_uri` 仅作参数，无 sink 直达。

7. **第 178–194 行 `_generate_redirect_uri`**：`_target_url` 用户可控但只作为 query value 被 urlencode，不改变跳转主机。

8. **第 196–208 行 `_redirect_to_target`（核心 sink）**：source 为 `request.query_params['_target_url']`（完全攻击者可控），sink 为 `RedirectResponse(safe_target)`。防御方式是取 `urlparse(target).path` 拼回 query/fragment：
   - `https://evil.com/x` → path=`/x`，scheme/host 被剥离 ✅
   - `//evil.com` → netloc=`evil.com`，path 为空 → 返回 `/` ✅
   - **`/\evil.com` 或 `/\\evil.com`** → urlparse 将其归入 path（反斜杠不触发 netloc 解析），`safe_target = '/\evil.com'`。多数浏览器在解析 `Location` 头时会把 `\` 规范化为 `/`，得到 `//evil.com`，即协议相对的跨域跳转 —— **开放重定向绕过**。该“剥 scheme/host”防御属于黑名单式清洗，未拒绝包含反斜杠的 path，可被绕过。
   - 另外 fragment 中也可携带 `#/\evil.com`？fragment 不参与跳转目标主机解析，无影响。

9. **第 211–286 行 OAuthProfile/OAuthToken/_get_mocked_oauth_info**：数据类与本地 token 读取，无网络 sink，mock token 为固定占位值，无泄露。

**结论**：唯一 source→sink 数据流是 `_target_url`（query 参数）→ `_redirect_to_target` → `RedirectResponse`。现有防御对常规绝对 URL 和 `//` 形式有效，但对反斜杠变体（`/\evil.com`）存在浏览器规范化导致的开放重定向绕过。
