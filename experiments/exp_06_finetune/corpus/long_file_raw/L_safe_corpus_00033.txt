# 逐点分析

**入口点枚举**
1. `decode(data, size)`（第 44 行起）：source 为调用方传入的 `data`（来自 PSD 文件压缩通道数据）与 `size`。
2. `encode(data)`（第 76 行起）：source 为调用方原始数据，输出为字节流。

**decode 数据流验证（第 44–72 行）**
- 第 55 行：`i, bit = i + 1, data[i]`，循环条件 `i < length and j < size` 保证 `data[i]` 不越界；每次迭代 i 至少 +1，无死循环。
- 第 57–63 行：重复模式，`actual = min(1 + bit, size - j)` 裁剪到剩余输出空间，写入 `result[j:j+actual]` 不越界；`j += actual` 后 j ≤ size，循环终止。截断输入时第 59 行 `if i >= length: break` 防止读取越界。
- 第 65–69 行：字面量模式，`actual = min(copy_count, available, size - j)` 同时受输入长度与输出空间约束，切片不越界；`i += min(copy_count, available)` 推进不超过流末尾。
- 第 71 行：bit == 128 视为 no-op，仅消耗一个头字节，安全。
- 返回值恒为恰好 `size` 字节，无内存放大：`result` 预分配为 `size`，解码不会超出该缓冲区。size 本身由上层 PSD 行宽决定，属正常参数而非本模块可控的攻击面。

**encode 数据流验证（第 76–118 行）**
- 纯编码器，无外部输入解析；所有索引均在 `0 <= x < length` 内推进（第 84、88、96、101、113 行），最坏情况输出略大于输入（约 +0.4%），无溢出或无限循环风险。
