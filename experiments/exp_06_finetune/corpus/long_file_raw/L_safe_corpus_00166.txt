2. **第 92-121 行 `createGrayRelease`**：同样有 `@PreAuthorize`；注意第 97 行将 `clusterName` 设为 `branchName`，但权限仍按原 cluster 校验——灰度分支发布沿用父 namespace 权限，属设计行为，且分支本身由授权操作创建。无独立漏洞。

4. **第 137-152 行 `findAllReleases` 与 第 154-169 行 `findActiveReleases`**：均先做 `shouldHideConfigToCurrentUser` 检查，命中则返回空列表。防御有效。

5. **第 171-177 行 `compareRelease`**：GET `/envs/{env}/releases/compare?baseReleaseId=&toCompareReleaseId=`。**全文唯一没有任何权限校验的读接口**：既无 `@PreAuthorize`，也无 `shouldHideConfigToCurrentUser` 检查。任意已认证（甚至视 Portal 配置可能匿名）用户可通过枚举/猜测 releaseId，获取两个 release 的完整配置差异（`ReleaseCompareResult` 含键值内容），绕过第 3、4 条入口建立的“隐藏配置”防线，构成越权信息泄露（broken access control / sensitive data exposure）。这是 source（HTTP 参数 baseReleaseId/toCompareReleaseId）→ sink（releaseService.compare 返回配置明文给响应体）的无防御数据流。

6. **第 179-207 行 `rollback`**：PUT 回滚接口虽无注解式鉴权，但第 186-189 行在方法体内显式调用 `hasReleaseNamespacePermission` 并抛 `AccessDeniedException`，防御有效。
