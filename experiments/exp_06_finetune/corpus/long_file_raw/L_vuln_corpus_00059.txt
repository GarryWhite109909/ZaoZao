**逐条数据流验证**

- **put**：`sanitizePath(fs.UploadFolder, req.URL.Path)` 归一化路径，随后显式阻断 `.goshs` 覆盖（第 39 行），ACL 与大小限制在写前执行。防御看起来完整；唯一残留风险是符号链接竞争（TOCTOU），但代码未提供可证实的利用面。
- **upload**：目录经 `sanitizePath` 处理；文件名仅按 `/` 分割取最后一段（第 110-112 行）。在 Linux 上反斜杠不是分隔符，安全；但在 Windows 上 `..\..\x` 会通过过滤并被 `filepath.Join` 解析为遍历——这是条件性 CWE-22。`.goshs` 阻断存在（第 115 行）。
- **bulkDownload（关键漏洞）**：第 185-199 行，对每个 file 参数调用 `findEffectiveACL(governing)`，**只有当 `aclErr == nil` 时才执行 `applyCustomAuth` 认证和 Block 列表检查**；若读取 `.goshs` 出错（权限、IO、格式损坏），代码直接落到第 200 行 `filesCleaned = append(filesCleaned, absPath)`——**fail-open**：未认证的文件仍被打包进 zip 返回给客户端。walker 内部第 216-222 行同样只在 `aclErr == nil` 时检查，错误时静默包含文件。攻击者无需凭据即可请求受保护路径下的文件；若能诱发 `.goshs` 读取失败（如通过上传接口制造权限异常的目录结构），即稳定绕过。
