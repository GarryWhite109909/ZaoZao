# gorush router/http_server.go 全文安全分析

## 一、文件整体定位

本文件是 gorush（appleboy/gorush）的 HTTP/HTTPS 服务器启动层，构建标签为 `!lambda`（第 1-2 行），包名为 `router`（第 4 行）。文件共包含 5 个函数：

1. `RunHTTPServer`（第 14 行起）
2. `listenAndServe`（第 76 行起）
3. `listenAndServeTLS`（第 92 行起）
4. `startServer`（第 108 行起）
5. 以及被引用但定义在别处的 `routerEngine`、`autoTLSServer`

下面逐函数、逐行枚举入口点与数据流。

## 二、逐函数分析

### 1. RunHTTPServer（第 14-74 行）

**入口点枚举：**

- **配置入口（source #1）**：`cfg *config.ConfYaml`（第 15 行）。该结构体来源于启动时的 YAML 配置文件与命令行参数/环境变量覆盖（gorush 的 config 包逻辑），属于**管理员可控的本地配置**，不是外部 HTTP 请求输入。
- **服务器注入入口（source #2）**：可变参数 `s ...*http.Server`（第 15 行）。若调用方传入自定义 server，则直接采用（第 27-29 行）；否则新建。这是程序内部调用链，非网络可达。
- **路由入口（间接 sink）**：第 28 行 `Handler: routerEngine(cfg, q)` —— 真正处理 HTTP 请求的路由注册在 `routerEngine` 中（本文件未包含），本文件本身不解析任何请求参数。

**数据流验证：**

- **流 A：`cfg.Core.Address + ":" + cfg.Core.Port` → `http.Server.Addr`（第 26 行）**
  - source：配置文件中的 address/port 字符串。
  - sink：`ListenAndServe` 的监听地址。
  - 防御评估：无过滤，但监听地址由管理员配置，攻击者若能改配置即已等同控制进程，不构成提权路径。注意 `//nolint:gosec`（第 25 行）仅是抑制 gosec 对地址拼接的告警，非安全缺陷本身。
- **流 B：`cfg.Core.CertPath` / `KeyPath` → `tls.LoadX509KeyPair`（第 38-42 行）**
  - source：配置中的证书路径；sink：文件读取加载密钥对。
  - 若攻击者可控 CertPath 可读任意 PEM 文件并经 TLS 握手回显——但同样要求已能修改服务端配置文件，前提条件即意味着主机已被攻陷，不构成独立漏洞。
- **流 C：`CertBase64` / `KeyBase64` → `base64.StdEncoding.DecodeString` → `tls.X509KeyPair`（第 43-56 行）**
  - 解码错误均有检查并返回（第 45-47、49-51、52-55 行），无 panic 路径（X509KeyPair 返回 error 而非 panic）。无注入面。
- **流 D：TLS 配置本身（第 32-36 行）**
  - `MinVersion: tls.VersionTLS12`（第 33 行）强制 TLS 1.2+，禁用了 SSLv3/TLS1.0/1.1，属正确做法。`NextProtos` 设为 `http/1.1`（第 35-36 行），未启用 h2 但这不是漏洞。
- **流 E：AutoTLS 分支（第 30-31 行）**
  - 直接委托给 `autoTLSServer(cfg, q)`（定义于其他文件，通常基于 autocert/Let's Encrypt），本文件内无可验证的缺陷证据，按要求不作猜测。

**结论**：RunHTTPServer 的所有 source 均为本地管理配置，sink 均为服务器自身行为，不存在不可信输入到危险操作的通路。

### 2. listenAndServe（第 76-90 行）

- 第一个 goroutine（第 78-84 行）：等待 ctx 取消后按 `cfg.Core.ShutdownTimeout` 设置超时调用 `s.Shutdown(ctx)`。`ShutdownTimeout` 来自配置，若为负数会导致立即超时——仅为可用性问题，且仍是管理员自伤场景。
- 第二个 goroutine（第 85-89 行）：`s.ListenAndServe()`，错误过滤 `http.ErrServerClosed` 后正常返回。无请求级输入处理。

### 3. listenAndServeTLS（第 92-106 行）

- 结构与 listenAndServe 完全对称（第 94-100 行优雅关闭，第 101-105 行 `ListenAndServeTLS("", "")`）。
- 关键点：证书已在 RunHTTPServer 中装入 `server.TLSConfig`（第 57 行），此处传空字符串参数是正确的——不会意外从磁盘默认路径加载，也不存在证书回退到弱默认的问题。

### 4. startServer（第 108-115 行）

- 仅根据 `s.TLSConfig == nil`（第 109 行）分流明文/TLS 启动。纯调度逻辑，无输入。

## 三、第二入口与替代通道核查

- **HTTP 请求体/查询参数/header**：本文件零接触。所有 HTTP handler 在 `routerEngine`（另一文件），本文件无法引入注入/XSS/SSRF 类漏洞。
- **环境变量**：本文件未调用 `os.Getenv` 等任何环境读取函数（全文 import 仅 context/tls/base64/errors/http/time 及项目内包，见第 6-16 行）。
- **文件系统**：唯一的文件操作是第 39 行 `LoadX509KeyPair`，路径来自管理员配置，前述已论证不构成越权。
- **回调/信号**：ctx 取消来自上层优雅退出机制，非外部可控。
- **并发问题**：两个 errgroup goroutine 中 `server`/`s` 只读共享，无数据竞争；`config` 局部变量遮蔽包名（第 31 行）是风格问题非安全问题。

## 四、总体结论

全文 115 行均已通读。所有 source（ConfYaml 配置字段、注入的 *http.Server）均为部署者控制的本地信任输入；所有 sink（ListenAndServe、TLS 加载、Shutdown）均为标准库安全用法。TLS 强制 1.2+，错误路径完整。真实的外部输入处理位于本文件之外的 routerEngine/handler 中，本文件范围内不存在可达的安全漏洞。
