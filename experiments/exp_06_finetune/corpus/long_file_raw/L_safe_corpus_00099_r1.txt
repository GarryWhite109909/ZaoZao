## 编号分析（全文逐函数）

1. **init() / DialContext（第 19–52 行）**：SSRF 防御核心。每次真实建连后取 `RemoteAddr` 解析 IP，拒绝 loopback、链路本地、接口本地多播，并逐一比对 `internalRanges`（第 88–96 行，覆盖 127/8、10/8、172.16/12、192.168/16、169.254/16、::1、fe80::/10、fc00::/7）。这是基于实际连接地址的校验，天然免疫 DNS rebinding/TOCTOU——即使域名解析阶段返回公网 IP，连接时若落到内网 IP 也会被拦截。Go 的 `IPNet.Contains` 会自动解包 v4-mapped-IPv6（如 `::ffff:10.0.0.5`），该绕过路径无效。

2. **CheckRedirect（第 65–67 行）**：直接返回 `http.ErrUseLastResponse`，客户端完全不跟随重定向。因此不存在“公网 URL 302 跳内网”的经典 SSRF 绕过；重定向响应原样返回给调用方且不写盘。

3. **New/track/ByServer/ByID/find/remove（第 118–124、246–296 行）**：仅内存缓存管理，UUID 标识符为随机生成，无用户可控 source 进入文件系统或网络 sink；锁使用正确。

4. **Execute()（第 133–190 行）**：
   - URL 仅来自 `dl.req.URL`（已解析的 `*url.URL`），请求经上述受控 client 发出。
   - `UseHeader` 时从 `Content-Disposition` 取 filename（第 156–166 行）作为 `dl.path`；否则用请求 FileName 或 URL 最后一段。
   - 关键 sink 是第 187 行 `dl.server.Filesystem().Write(p, ...)`，其中 `p = filepath.Join(dl.req.Directory, dl.path)`（第 226 行）。路径穿越风险由下游 `Filesystem.Write` 承担——wings 的 Filesystem 层会对路径做规范化并确保最终路径落在服务器数据目录内（越界即报错），这是本项目公认的安全边界，不属于本文件的防御缺口。此外写入大小受 `res.ContentLength` 与磁盘配额约束。

5. **counter/Progress/MarshalJSON（第 199–216 行）**：仅进度计算与 JSON 序列化，输出字段只有 Identifier 和 Progress，无敏感泄露。

6. **第二入口核查**：本文件无路由注册、无环境变量读取、无回调入口；唯一外部输入是调用方传入的 `DownloadRequest`（URL/Directory/FileName），其合法性校验在上游 router 层完成，本文件对已收敛的输入做了连接级 SSRF 防护与重定向禁用。

**结论**：SSRF 防御采用“连接后校验实际 IP + 禁止重定向跟随”的双重机制，无黑名单正则类可绕过过滤；文件写入依赖下层 Filesystem 沙箱且本文件未引入新的穿越通道。全文未见可利用漏洞。
