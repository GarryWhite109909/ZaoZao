## 编号分析

1. **第 5–17 行（入口点）**：本文件是独立 HTTP 入口脚本，无路由框架；输入来源包括：`$argv[1]`（CLI 参数）、`$objClone` 插件配置（管理员设置）、以及远程克隆服务器返回的 JSON（`cloneServer.json.php` 响应）。后者是最重要的外部 source。

2. **第 60–66 行（鉴权）**：若 `$argv[1]` 与 `$objClone->myKey` 不匹配且非管理员则拒绝。但注意第 64 行：`echo "$objClone->myKey !== $argv[1]"` —— 在鉴权失败分支中把**真实密钥 myKey 直接回显给未授权用户**，属于敏感信息泄露漏洞。攻击者拿到密钥后可绕过该检查（在 CLI/register_argc_argv 场景下）。

3. **第 88–89 行（sqlFile 清洗）**：`preg_replace('/[^a-z0-9_.-]/i')` 移除了斜杠，路径穿越被阻断；随后又经 `escapeshellarg`，wget 命令（第 93 行）的 shell 注入已防护。

4. **第 128–155 行（任意 SQL 执行 sink）**：下载的 `$sqlFile` 内容被逐行直接送入 `$global['mysqli']->query($templine)` 执行。source 是远程服务器返回的 SQL dump，无任何内容校验。恶意/被劫持的克隆服务器可通过 dump 执行任意 SQL（如 `SELECT ... INTO OUTFILE '/var/www/html/videos/shell.php'`），实现 **RCE**。这是最严重的数据流：远程 JSON → 文件 → mysqli::query。

5. **第 160–190 行（文件写入 sink）**：非 rsync 分支中 `file_put_contents("{$videosDir}{$value->filename}", fopen("$value->url"))`。filename 虽经 `[^a-z0-9_.-]` 清洗（防穿越），但**未限制扩展名**——允许 `.php` 结尾，且此处没有 rsync 分支的 `--exclude '*.php'` 保护。远程服务器返回 `filename=shell.php` 即可在 Web 可达的存储目录写入 PHP 文件 → **RCE**。

6. **第 194–210 行（rsync 分支）**：sshUser/sshIP 经白名单正则清洗，port 经 intval，password 含单引号包裹问题但整体经 str_replace 后进入 exec——密码含 `'` 可破坏引号结构，但 sshUser/IP 已白名单化，注入面有限；`$json->videosDir` 允许 `/` 和 `..`，但因目标是远端路径且 rsync 目的地固定，本地风险低。

7. **第 233 行**：`chmod -R 777 {$videosDir}` —— 目录遍历权限过宽，属配置弱点而非注入。

8. **第二入口验证**：`deleteDump={$json->sqlFile}`（第 218 行）复用已清洗变量，安全；`url_get_contents` 的 URL 由配置拼接并 urlencode，SSRF 面受限于管理员配置的 cloneSiteURL。

**结论**：存在真实漏洞——(a) 未授权回显密钥；(b) 远端响应驱动的任意 SQL 执行与 `.php` 文件写入导致 RCE 链。
