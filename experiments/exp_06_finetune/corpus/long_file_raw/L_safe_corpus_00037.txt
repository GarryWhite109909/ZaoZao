## 编号分析

**入口点枚举（全文通读）**：本文件共 9 个视图函数，均为 `@login_required` + `@permission_required(Permissions.SCAN)` + POST 限制：`mobsfy`（第 64 行）、`execute_adb`（第 98 行）、`get_component`、`run_apk`、`take_screenshot`、`screen_cast`、`touch`、`mobsf_ca`、`global_proxy`。辅助函数 `get_package_name`（第 45 行）从 DB 或 `packages.json` 取包名。

**逐条数据流验证**：

1. **mobsfy（第 70→79 行）**：source 为 `request.POST['identifier']`，经 `cmd_injection_check`（第 71 行）过滤后传入 `Environment(identifier)`。按分析要求，黑名单类过滤视为可绕过，此防御不算有效；但 identifier 主要用于连接模拟器地址，实际命令拼接在 Environment 内部，风险有限。
2. **execute_adb（第 101→106 行）**：source `request.POST['cmd']` **无任何校验**，直接 `cmd.split(' ')` 拼入 `subprocess.Popen(args + cmd.split(' '))`（第 105–108 行）。这是明确的 source→sink 命令注入流。代码注释（第 106 行 lgtm 标注）表明这是“有意设计”——允许已认证用户在 VM/AVD 内执行 adb 命令。但 adb 本身可在设备上执行 shell（如 `shell rm -rf /data`）、端口转发、安装任意 APK 等，且若 MobSF 部署时 adb 指向宿主或其他可达设备，影响扩大。防御仅有登录 + SCAN 权限，属访问控制而非输入净化，持有低权限账号即可利用。
3. **touch（text 分支）**：`shlex.quote(x)` 正确转义，安全；数字分支经 `is_number` 校验，安全。
4. **get_component / run_apk / take_screenshot**：均经 `is_md5` 白名单校验（十六进制定长），hash 类注入不可行；`take_screenshot` 中路径由 md5 拼接，md5 校验阻断了路径穿越。
5. **mobsf_ca / global_proxy / screen_cast**：action 为固定枚举比较，无用户数据进入命令。

**第二入口/替代通道**：`execute_adb` 是主要 AJAX 入口；MobSF 的 REST API（api=True 路径）同样路由到这些函数，构成替代通道，但同样受 API key 认证保护。

**结论**：存在一处真实可利用的认证后命令执行/注入漏洞（execute_adb），其余入口防御有效。
