6. **第 236-248 行 `toInstallationRepresentation`**：JSON 序列化输出，Jackson 自动转义，安全。

7. **第 250-283 行 `toJBossSubsystemConfig`（关键）**：
   - **source**：`realmModel.getName()`、`clientModel.getClientId()`、`clientModel.getSecret()`、以及凭据 Map 的 key/value（第 252、259、262、267-275 行），这些值可被拥有 manage-clients 权限的主体通过 Admin REST API 设置（第二入口：Admin API 的 client update 端点）。
   - **sink**：第 253-280 行直接 `buffer.append(...)` 拼接进 XML 字符串，**全程无任何 XML 转义**（无 escapeHtml/escapeXml 调用）。
   - **数据流验证**：恶意 clientId 如 `</resource><script>...` 或凭据 value 含 `<`、引号，将原样进入生成的 subsystem XML。该输出在安装适配器页面展示给域管理员，管理员复制到 JBoss/WildFly 的 standalone.xml 时即发生 XML 注入，可破坏配置结构甚至注入额外 secure-deployment 条目。
   - **防御检查**：全文未发现任何编码/转义/白名单校验；`showClientCredentialsAdapterConfig` 仅控制是否输出凭据，不构成对内容的过滤。
   - 前提条件：攻击者需具备管理该客户端的权限（manage-clients），而查看者通常是更高权限的域管理员，存在权限边界跨越，故为低危。

8. **其余部分**：getter/setter 与内部类定义无可达 sink。
