## 编号分析

**入口点枚举（全文）**
- 第 79 行 `--host` 选项：CLI 参数，决定 `stream_socket_server` 绑定地址（第 105–109 行）。默认 `127.0.0.1:9911`，但可被设为 `0.0.0.0` 暴露到网络——这是第二入口的来源。
- 第 80 行 `--format`、第 81 行 `--date-format`：CLI 参数，进入 ConsoleFormatter（第 101–106 行），仅本地运维可控。
- 第 82 行 `--filter`：CLI 参数，交给 ExpressionLanguage（第 122 行）。
- 第 113 行 `getLogs()`：网络 socket 数据流，每行日志经 `yield` 返回——真正的远程 source。

**source→sink 数据流验证**

1. **网络数据 → `unserialize`（第 111–115 行）**：远程攻击者可向该端口发送任意 base64 字符串触发反序列化。防御：`allowed_classes => [Data::class, Stub::class]` 白名单。这是 Symfony 官方修复（对应历史 CVE 后加的补丁），将对象注入限制为 VarDumper 的 `Data`/`Stub`，二者无已知 POP 链；且第 116 行要求结果为数组否则丢弃。白名单类反序列化在此上下文视为有效防御（黑名单才视为可绕过）。
2. **`$record['datetime']` → `DateTimeImmutable::createFromFormat`（第 118–120 行）**：解析失败返回 false 回退原字符串，无危险 sink。
3. **`$record['log_id']` → `unpack('H*', ...)` → `$clientId % 8`（第 137–139 行）**：取模 8 保证索引在 `BG_COLOR` 数组范围内，无越界；unpack 对任意输入安全。
4. **`$record` → `$this->handler->handle($record)` / ConsoleFormatter（第 141 行）**：格式串来自 CLI 而非网络数据；记录内容经 formatter 输出到控制台，CLI 场景下无 HTML/XSS sink。
5. **`--filter` → `ExpressionLanguage::evaluate`（第 122 行）**：ExpressionLanguage 是沙箱化表达式引擎，不执行任意 PHP；且 source 是本机命令行参数，非远程可控。
6. **`getLogs()`（第 126–146 行）**：`stream_select` 循环、`fgets`，无缓冲区溢出类问题；连接数无上限属 DoS 可用性问题而非注入漏洞，且默认仅监听回环。

**第二入口检查**：除 socket 外无文件上传、回调注册、环境变量读取等其他通道；`isEnabled()`（第 43–53 行）仅在依赖缺失时禁用命令，无安全问题。

**结论依据**：唯一远程可达的危险 sink（unserialize）已有类白名单有效防护，其余数据流均落在安全 sink 或本地信任输入上。未发现可利用漏洞。
