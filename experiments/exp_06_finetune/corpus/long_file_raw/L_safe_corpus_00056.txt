## 编号分析

1. **入口点枚举（全文）**：MCP 工具共三个——`consult_gemini`（第 285 行附近）、`consult_gemini_with_files`、`web_search`。外部可控参数：`query`、`directory`、`files`、`model`、`timeout_seconds`、`mode`。环境变量：`GEMINI_BRIDGE_MAX_INLINE_*`、`GEMINI_BRIDGE_TIMEOUT` 等（第 22–27 行），仅由本机部署者设置，非远程 source。

2. **命令注入 sink 检查**：唯一 sink 是 `subprocess.run(cmd, ...)`（第 168 行、第 253 行），`cmd = ["gemini", "-m", selected_model]`，列表形式且无 `shell=True`，参数不经过 shell 解析；`query` 通过 `input=` 走 stdin（第 174 行），不会成为 argv。无注入。

3. **model 数据流**：`_normalize_model_name`（第 31 行起）先做白名单集合匹配，未命中时仅放行 `gemini-` 前缀值（第 68–69 行）。由于前缀限定为 `gemini-`，不可能以 `-` 开头构造额外 CLI 选项（如 `-yolo`/`--sandbox` 类 flag），作为单个 argv 元素传入也无需转义。防御有效。

4. **路径穿越数据流**：source 为 `files` 列表，sink 为 `_read_file_for_inline` 的文件读取及 `@{rel_path}` 拼接。`_resolve_path`（第 88 行）对 root 与候选路径均 `.resolve()`（跟随符号链接后判定），再用 `relative_to(root)` 做包含性检查，绝对路径、`..`、指向目录外的符号链接均返回 `None` 并被调用方跳过（第 205 行、第 232 行）。这是基于规范化真实路径的白名单式检查，非黑名单，防御有效。

5. **残余风险（低危/设计固有）**：
   - `_resolve_path` 返回后到实际打开文件之间存在符号链接竞态窗口（TOCTOU），本地攻击者可换链读取目录外文件；但 MCP server 与攻击面均为本机信任域，风险极低。
   - inline 模式将目录内文件内容拼入 prompt（第 219 行），存在间接提示注入可能，属此类工具的固有设计而非代码缺陷。
   - `directory` 参数允许任意目录是工具声明的功能语义。
   - 环境变量数值解析有 try/except 或 int() 直接调用（第 22–26 行），异常配置可致启动崩溃，非安全问题。

6. **第二入口/替代通道**：无网络监听、无回调、无临时文件写、无 eval/exec/pickle；`web_search` 仅拼接字符串进 stdin，同样安全。
