## 编号分析（全文通读）

**入口点枚举**
- 第 33 行：`$argv[1]` —— 认证密钥输入（CLI 参数；在部分 SAPI/register_argc_argv 配置下可受请求影响）。
- 第 20 行：`require_once $config` 加载全局配置；第 24–27 行引入 CloneSite 插件。
- 第 44 行：`$objClone->cloneSiteURL`、`myKey`、SSH 配置等来自插件数据库配置。
- 第 62 行：向远端服务器发起 HTTP 请求，响应 `$json` 是完全外部可控的第二入口（server-supplied data：`sqlFile`、`videosDir`、`videoFiles`、`photoFiles`）。

**逐条数据流验证**

1. **认证逻辑（第 48–56 行）—— 密钥泄露 + 认证绕过**：
   ```php
   if (empty($objClone) || empty($argv[1]) || $objClone->myKey !== $argv[1]) {
       if (!User::isAdmin()) {
           ...
           echo "$objClone->myKey !== $argv[1]";
   ```
   未认证用户访问该端点时，第 54 行直接把 `$objClone->myKey`（克隆认证密钥）回显到 HTTP 响应中。攻击者拿到 myKey 后即可通过 `$argv[1]` 通过校验，完整触发后续克隆流程。这是真实的 source（配置中的秘密）→ sink（echo 输出）泄露，且直接导致授权失效（CWE-200 → CWE-287）。注意该文件名是 `cloneClient.json.php`，是公开可达的插件端点。

2. **wget 命令注入（第 84–88 行）**：`$json->sqlFile` 先经 `preg_replace('/[^a-z0-9_.-]/i','')` 再 `escapeshellarg`，随后 `str_replace("'",'',...)` 把 escapeshellarg 添加的引号剥掉——但前置白名单正则已移除空格、分号、反引号等元字符，故此处实际不可注入（防御有效）。`cloneSiteURL` 仅做 escapeshellarg+去引号（第 96 行），未做字符白名单——若管理员配置的 URL 含空格/分号可造成命令注入，但来源为管理员自身配置，属低危二阶问题。

3. **rsync 命令（第 168–175 行）**：`sshUser/sshIP/videosDir/port` 均有白名单净化；但 `{password}` 在第 174 行以 `str_replace` 直接原样拼入 shell 命令后 `exec`（第 177 行），密码中任何 shell 元字符都会被执行——存储型命令注入（来源为插件加密配置，需管理员或已攻破 DB 才能设置，风险受限但真实存在，CWE-78）。另外 `-o StrictHostKeyChecking=no` 削弱传输安全。

4. **SQL dump 直接执行（第 118–140 行）**：远端返回的 dump 内容被逐行喂给 `$global['mysqli']->query`，等于无条件信任远端服务器执行任意 SQL——若 cloneSiteURL 被指向攻击者服务器（SSRF/配置篡改），即完全接管本地数据库（含写入 PHP 后台账户）。

5. **文件写入（第 152、161 行）**：filename 经白名单正则（无 `/`），路径穿越不可行；但 URL 来自远端，存在 SSRF 式内容拉取到本地存储。

6. **结尾（第 205 行）**：`chmod -R 777 {$videosDir}` 将整个视频目录设为全局可写，违反最小权限（CWE-732）。

**第二入口确认**：`$json->videosDir` 允许 `/` 和 `\`（第 66 行注释声称安全），作为 rsync 远端源路径虽不直接命中本机 shell，但配合第 4 点的任意 SQL 与第 1 点的密钥泄露，构成完整攻击链：泄露 myKey → 触发克隆 → 恶意“服务器”返回恶意 dump → 任意 SQL 执行 → 接管站点。
