## 编号分析（全文通读）

**1. 类结构与状态（第 1–37 行）**
- 第 36 行：`private static YamlParserProperties yamlParserProperties;` —— 静态可变字段，由实例构造器赋值。
- 第 38–41 行：`@Autowired` 构造器将 Spring 属性写入静态字段。若存在多个应用上下文或该 Bean 未被创建，静态字段可能为 null 或被覆盖——这是第二入口/替代通道问题：所有 `newYaml*()` 工厂方法的行为完全取决于这个隐式全局状态。

**2. `hasYamlSecurityPropertiesConfigured()`（第 43–48 行）**
- 只要 maxAliasesForCollections **或** codePointLimit 任一非空即视为“已配置安全属性”。注意：这两个限制只防 Billion Laughs / 超大输入（资源耗尽），**完全不限制标签反序列化**。

**3. `newYaml()`（第 55–72 行）—— 核心漏洞点**
- 第 61 行：`Constructor constructor = new Constructor(opts);` —— 使用 SnakeYAML 的 `Constructor`（非 `SafeConstructor`）。`Constructor` 允许解析 `!!javax.script.ScriptEngineManager [!!java.net.URLClassLoader ...]` 这类全局标签，实现任意类实例化 → RCE（CWE-502 反序列化不可信数据）。
- 第 62–68 行：即便配置了 LoaderOptions，传入的仅是别名数与码点上限，对任意类构造无任何约束；LoaderOptions 的 `tagInspector` 未设置。
- 第 71 行：未配置时的回退路径是 `return new Yaml();` —— 默认同样是 `Constructor`，同样不安全。即两条分支都暴露不安全解析器。

**4. `newYamlSafeConstructor()`（第 80–95 行）**
- 配置时用 `SafeConstructor(opts)`（第 84 行），未配置时 `new Yaml(new SafeConstructor())`（第 94 行）。此方法是安全的，但注意它没有显式 Resolver 参数的版本差异不影响安全性。

**5. `newYamlDumperOptions()`（第 104–119 行）**
- 两个分支均使用 `SafeConstructor`（第 109、117 行），加载侧安全。

**6. `newYamlLoaderOptions()`（第 128–135 行）**
- 第 130–131 行：配置了安全属性时反而**忽略调用方传入的 loaderOptions**，返回 `new Yaml(opts)`——默认内部仍是 `Constructor`（SnakeYAML `Yaml(LoaderOptions)` 构造器使用 `Constructor`），因此即使调用方本想传 SafeConstructor 相关配置也会丢失；且该路径同样允许任意标签反序列化。这是“防御被静默削弱”的第二通道。
- 第 134 行：未配置时直接采用调用方的 options，行为取决于调用者。

**7. `newYamlRepresenter()`（第 144–155 行）**
- 第 145–148 行：配置时使用**调用方传入的任意 `Constructor`** 并套上 LoaderOptions——若调用方传 `new Constructor(SomeBean.class)`，仍允许通过 YAML 触发对应类型树的构造，且 LoaderOptions 不含 tag 白名单；未配置时（第 153 行）完全无任何限制。

**8. 数据流验证**
- source：外部输入的 YAML 文本（由 Spinnaker 各服务经 HTTP/管道/pipeline 定义等入口传入并调用 `YamlHelper.newYaml().load(...)`）。
- sink：第 61 行 `new Constructor(opts)` + 第 66 行返回的 `Yaml` 实例的 `load()`；以及第 130–131 行、第 145–148 行的同类 sink。
- 防御有效性评估：maxAliasesForCollections/codePointLimit 仅缓解资源耗尽型攻击，黑名单式/容量式限制按规则不算有效防御；真正需要的是 SafeConstructor 或 tagInspector 白名单，代码中 `newYaml()` 主路径缺失。

**9. 结论方向**
`newYaml()` 是该工具类对外的主工厂方法（Javadoc 示例即用它解析用户内容），其默认与“加固”两条路径均使用可实例化任意类的 `Constructor`，构成不安全的反序列化漏洞；同时静态字段初始化竞态可作为替代触发通道使安全配置失效。
