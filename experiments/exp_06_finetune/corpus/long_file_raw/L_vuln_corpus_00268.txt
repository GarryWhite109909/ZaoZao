## 编号分析

1. **第 44-45 行 `authenticate_ldap_user(username, password)`**：入口点，username/password 来自调用方（Moonraker 登录 API 的请求参数），无任何校验直接传递。

2. **第 47-49 行**：`run_in_thread` 调用 `_perform_ldap_auth(username, password)`，数据流原样透传，无过滤。

3. **第 77 行 `ldfilt = f"(&(objectClass=Person)({attr_name}={username}))"`**：username 直接字符串插值进 LDAP 过滤器。`attr_name` 来自配置（安全），但 `username` 是用户输入，未做转义（如 `\28 \29 \5c`）。

4. **第 79-80 行 user_filter 分支**：`self.user_filter.replace("USERNAME", username)` 同样是纯替换，无转义；且第 71-73 行仅检查模板含 "USERNAME" 字面量，不构成对注入的防御。

5. **第 83-84 行 sink：`conn.search(self.base_dn, ldfilt, ...)`**：注入的过滤器被用于搜索，攻击者可通过注入 `*)(uid=*))(|(uid=*` 等改变过滤器逻辑（如绕过 objectClass/属性限制、枚举用户、匹配任意 DN 条目）。base_dn 来自配置文件，非用户可控。

6. **第 86-90 行 rebind / 第 92-96 行新连接验证**：password 作为绑定凭据使用，属正常认证用途，非 sink 注入点。

7. **第 100-105 行 `_validate_group`**：group_dn 与 memberOf 比较，均来自配置/LDAP 返回值，无注入。

8. **第二入口/替代通道**：本文件唯一入口为 `authenticate_ldap_user`；config 模板渲染的 base_dn/bind_dn 属管理员配置，不可由终端用户控制。错误信息第 85 行回显 username（`f"LDAP User '{username}' Not Found"`），存在轻微信息回显，但主要漏洞为 LDAP 注入。
