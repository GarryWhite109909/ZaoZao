# 编号分析

**1. findByUid（第 41–57 行）**
- Source：`$uid` 参数，类型声明为 `int`（第 43 行），PHP strict_types 下无法注入字符串。
- Sink：QueryBuilder `where eq` + `createNamedParameter($uid, ParameterType::INTEGER)`（第 49 行），参数化查询。
- 结论：无 SQL 注入。

**2. findAll / findAllForListing（第 64–101 行）**
- Source：`SearchCriteria $criteria` 对象（DTO）。
- Sink：`applySearchCriteria`（第 137–153 行）：searchTerm 经 `escapeLikeWildcards()` 转义 `%`/`_` 后通过 `createNamedParameter` 绑定；limit 走 `setMaxResults(int)`。无拼接 SQL。
- 注意：LIKE 通配符已转义，非黑名单式过滤，属有效防御。

**3. existsByFormIdentifier / findUidByFormIdentifier（第 110–133 行）**
- Source：`string $formIdentifier`。
- Sink：均为 `expr()->eq(..., createNamedParameter(...))` 参数化绑定（第 117、130 行）。安全。

**4. add（第 162–194 行）**
- Source：`$persistenceIdentifier`、`$pid`、`FormData` DTO。
- Sink：DataHandler `process_datamap`（第 176 行），字段为数组形式传入，DataHandler 内部做类型处理与权限校验；且调用前后有 `persistenceGuard->allowInvocation/consumeInvocation`（第 173、179 行）防止 DataHandler 调用被滥用（防二次入口绕过持久化守卫）。JSON 编码用 `JSON_THROW_ON_ERROR`。无直接 SQL 拼接。

**5. addRaw（第 205–222 行）**
- Sink：Doctrine `connection->insert(self::TABLE_NAME, [...])`（第 208 行），列名硬编码常量，值为绑定参数。`configuration` 直接传数组由 DBAL 处理。`crdate/tstamp` 来自 `$GLOBALS['EXEC_TIME'] ?? time()`，为整数时间戳。安全。
- 风险点评估：该方法绕过 DataHandler 与 persistenceGuard——但注释明确限定用于 Install Tool 升级向导（无可后端用户上下文），且写入内容来自内部 FormData 对象而非用户请求直接输入；在本文件范围内无外部 source 可达此 sink 的路径。

**6. remove / update（第 231–283 行）**
- Source：`int $uid`（强类型）、`FormData` DTO。
- Sink：cmdmap/datamap 均走 DataHandler，同样有 persistenceGuard 包裹（第 234/239、268/273 行）。update 有 `empty($uid)` 检查（第 265 行）。安全。

**7. 第二入口/替代通道检查**
- 全文无 `$_GET/$_POST/$_REQUEST/$_COOKIE/php://input` 等超全局读取；无 `include/require/eval/exec/system/shell_exec/unserialize` 等危险 sink；无文件读写操作。所有数据库访问均经 ConnectionPool QueryBuilder 或 Doctrine insert，全部参数化。
