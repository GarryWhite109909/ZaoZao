## 编号分析（全文通读，逐函数行级核查）

**文件概况**：本文件是 Pimcore CustomReportsBundle 的 SQL 报表适配器（`Tool/Adapter/Sql.php`），共约 200 行，包含入口方法：`getData`、`getColumns`、`buildQueryString`、`getBaseQuery`、`getAvailableOptions`、辅助方法 `stripSqlCommentsForValidation`。

### 1. `getData()`（第 26–60 行）
- **source**：`$filters`、`$sort`、`$dir`、`$offset`、`$limit`、`$drillDownFilters`（第 27–33 行参数）。
- `$dir`（第 42 行）：经 `strtoupper($dir) === 'ASC' ? 'ASC' : 'DESC'` 白名单化，安全。
- `$sort`（第 43 行）：进入 `ORDER BY` 前经过 `$db->quoteIdentifier($sort)`，DBAL 会转义反引号，标识符注入被阻断。
- `$offset/$limit`（第 46–48 行）：声明为 `?int`（strict_types=1），拼接进 LIMIT 前已是整型，无法注入。
- `$filters` / `$drillDownFilters`：流入 `getBaseQuery`，见下文第 3 节。
- 底层 SQL 来自 `$baseQuery['data']`，源头是 `$this->config`（报表配置），见第 4 节。

### 2. `getColumns()`（第 62–82 行）
- source 为 `$configuration`（stdClass 配置对象）。经 `buildQueryString` 拼接后先过 `stripSqlCommentsForValidation` 再做黑名单正则（第 69–71 行）拦截 ALTER/CREATE/DROP/RENAME/TRUNCATE/UPDATE/DELETE。
- 黑名单本身可绕过（如未覆盖 INSERT、不匹配无空白后缀的写法），但该方法的 sink 是只读连接执行查询，且输入源是**管理员在后台保存的报表配置**而非终端用户请求参数——黑名单在此是纵深防御而非唯一防线。作为独立漏洞证据不足。

### 3. `buildQueryString()`（第 84–137 行）
- `$config['sql']/'from'/'where'/'groupby'` 原样拼接——但这些字段全部来自 `$this->config`（构造时注入的报表配置对象），属于受信配置面（仅限有报表管理权限的管理员编辑），非 HTTP 用户直接可控。
- `$drillDownFilters`（第 120–130 行）：field 经 `quoteIdentifier`，value 经 `$db->quote` 参数化引用，防御有效。
- `$selectField`（第 92–94 行）经 `quoteIdentifier`，安全。

### 4. `getBaseQuery()`（第 139–194 行）
- `$filters` 循环（第 148–183 行）：所有分支中 `$filter['property']` 均过 `quoteIdentifier`，`$value` 均过 `$db->quote`；date 分支的 `strtotime` 返回值也被 quote。无裸拼接的用户值。
- 第 185–190 行对最终 SQL 再次跑黑名单正则，命中则返回 null（拒绝执行）——同样是纵深防御。
- 输出的 data/count 外层再包一层 `SELECT ... FROM (...) WHERE`，条件全部来自上述已引用的条件数组。

### 5. `getAvailableOptions()`（第 196–221 行）
- 复用 `getBaseQuery`，`$field` 在第 208 行经 `quoteIdentifier` 后拼入 GROUP BY，安全。

### 6. 第二入口与替代通道
- 文件内无路由、无请求对象、无文件/环境变量读取；唯一外部数据是调用方传入的 filters/sort 等，均已验证。真正的攻击面（谁能改 `$this->config`）在控制器层，不在本文件内，不能据此判定本文件存在漏洞。

### 结论
全文所有用户侧可控输入（filters、sort、dir、offset、limit、drillDownFilters、field）均经白名单化或 quoteIdentifier/quote 有效消毒；原样拼接的 SQL 片段仅来源于管理员维护的报表配置，属设计上的受信输入。黑名单正则虽弱，但不是唯一防线，构不成可利用漏洞。
