# 全文逐函数安全分析

## 一、入口点枚举（通读全文）

## 二、`decode` 函数逐行数据流验证

**结构**：`i` 是输入游标，`j` 是已产出字节数计数器，`result` 是输出缓冲。

### 数据流 D1：重复分支（`bit > 128`）

```python
i, bit = i + 1, data[i]
if bit > 128:
    bit = 256 - bit
    if j + 1 + bit > size:
        raise ValueError(...)
    result.extend((data[i : i + 1]) * (1 + bit))
```

- **防御有效性**：在执行 `result.extend(...)` 前有显式上界检查 `j + 1 + bit > size`，保证单次扩展后总产出不超过 `size`。这是白名单式精确边界检查（非黑名单/正则），**有效**。因此即使攻击者构造 `0xFF` 头字节（重复 128 次），内存放大也被硬性限制在 `size` 以内——解压炸弹（CWE-409）在此函数内部被约束。
- **缺陷 1（边界遗漏）**：该分支未检查 `i < length`。若输入以头字节结尾（如 `b'\x81'`），`data[i:i+1]` 为空切片，`extend` 产出 0 字节，但 `j += 1 + bit` 仍按预期累加。随后末尾 `if size and (len(result) != size)` 会因 `len(result) != j` 抛错——**前提是 `size` 非零**。
- **缺陷 2（size==0 绕过终检）**：终检条件写作 `if size and (...)`，当调用方传入 `size=0` 时终检被完全跳过。此时上述截断输入会静默返回空/短结果；更一般地，任何提前耗尽输入的情况都不会报错。这是正确性/健壮性问题而非内存安全问题（bytearray 无越界写），但在解析器场景下可能造成下游逻辑基于错误假设继续执行（完整性影响，低危）。

### 数据流 D2：字面量分支（`bit < 128`）

```python
elif bit < 128:
    if i + 1 + bit > length or (j + 1 + bit > size):
        raise ValueError(...)
    result.extend(data[i : i + 1 + bit])
```

- 同时校验了输入侧（`i + 1 + bit > length`）与输出侧（`j + 1 + bit > size`），防止读取越界切片与超限产出。**防御有效**，且此分支无 D1 的 `i` 越界问题。

### 数据流 D3：`bit == 128`（no-op）

两个分支条件都不命中，但由于第一行已执行 `i += 1`，游标必然前进，**不存在死循环**。这是 PackBits 规范中的 no-op 字节，处理正确。

### 数据流 D4：终止与终检

`while i < length` 保证循环终止（每轮 `i` 至少加 1）。终检 `len(result) != size` 在 `size` 非零时能捕获所有产出不足/不一致情况——但如 D1/D2 所述，`size=0` 时失效，且错误消息用 `%d % j` 而非 `len(result)`，仅是信息不准确。

### 内存消耗评估

`result` 最大增长到 `size` 字节。若上游把 PSD 文件中攻击者控制的通道长度直接作为 `size` 传入（常见做法），单个通道即可申请 GB 级缓冲——但这属于调用方的资源策略问题，本模块自身有界。综合判定：**本函数内无可利用的内存破坏或注入漏洞**，仅有上述两处健壮性缺陷。

## 三、`encode` 函数逐行数据流验证

- **MAX_LEN = 0xFF >> 1 = 127**，符合 PackBits 单字节长度上限。
- **重复分支**：内层 `while j < length` 有三个 break 条件（达到 MAX_LEN、到达末尾、run 断裂），每轮 `j += 1` 必然推进，`i = j = j + 1` 保证外层推进——**无死循环**。
- **字面量分支**：同样每轮 `j += 1` 推进；`elif` 链中第一个条件 `pass` 只是注释性占位，不影响控制流；后续两个 `elif` 仅决定是否提前 break。`result.append(j - i - 1)` 时必有 `j > i`（进入分支时 `data[j] != data[j+1]` 保证至少前进一次），不会写出负长度头。
- **退化输入**：`length == 0` 直接返回原对象；`length == 1` 写出 `(0, data[0])`。均正确。
- **sink 检查**：无任何危险 sink（无 eval/exec/os/subprocess/pickle）。输出仅为纯字节重组，最坏膨胀 ~0.4%，无放大风险。
