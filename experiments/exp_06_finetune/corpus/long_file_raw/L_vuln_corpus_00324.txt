# 编号分析

**1. 入口点枚举（全文通读）**
- `index()`（第 27-34 行）：渲染视图，无直接 sink。
- `getComments()`（第 36-56 行）：`$request->all()`（第 40 行）作为 `$filter` 传入 `Comment::filter()`（第 44 行）。这是 Laravel 集合/查询过滤，Microweber 的 filter 实现按白名单字段构建查询，且走 Eloquent 参数绑定，非原始拼接，SQL 注入风险低。
- `saveCommentEdit()`（第 58-152 行）：主入口，`$request->all()`（第 64 行）取全部用户输入。
- `__report_for_spam()`（第 154-197 行）：内部调用，数据来自数据库中已存评论，POST 到固定 URL `spamchecker.microweberapi.com`（第 157 行），URL 不可控，无 SSRF。

**2. saveCommentEdit 数据流分析**
- 第 64 行 `$data = $request->all()` → 第 145 行 `mw()->database_manager->save($table, $data)`。`$table` 固定为 `'comments'`（第 62 行），但 `$data` 的键与值完全由请求控制。Microweber 的 `database_manager->save` 是通用表写入器，会按传入字段动态构建 INSERT/UPDATE。攻击者可注入额外字段如 `created_by`、`user_ip`、`is_admin`、`rel_type` 等，造成**批量赋值 / 任意字段篡改**（CWE-915），可伪造任意 rel_id/rel_type 的评论、篡改他人评论。
- XSS 流：第 133-139 行先 `clean_html` 再 `clean_xss`（黑名单正则：`on\w*`、`xmlns`、`formaction` 等事件属性黑名单——题目要求视为可绕过；且未过滤 `<script>` 标签本身在部分配置下、未处理编码绕过）。随后若 `format == 'markdown'`（第 141-143 行）经 Markdown 转 HTML。输出端 `allow_html = '1'`（第 144 行）明确允许 HTML 渲染。存储型 XSS（CWE-79）：source 第 64 行 → sink 第 144/145 行持久化后在前台以 HTML 输出。黑名单式 clean_xss 属于可绕过防御（如 `<img src=x onerror=...>` 变体、SVG、大小写/编码混淆等历史绕过均存在）。
- 第 76-77 行 delete 分支使用 `intval($data['id'])`，参数化删除，安全。
- 第 69-83 行 reply_to_comment_id 继承旧评论 rel 信息，逻辑正常。

**3. 第二入口/替代通道**
- `getComments` 的 filter 走 ORM 白名单，未见直接 whereRaw。
- `__report_for_spam` 将评论内容外发第三方（信息泄露面小，URL 固定）。
- 主要风险集中在 saveCommentEdit 的全量 `$data` 直接入库 + 黑名单 XSS 清洗。

**结论**：存在漏洞——(a) 存储型 XSS：黑名单属性过滤可绕过且允许 HTML；(b) 大规模批量赋值：`$request->all()` 未做字段白名单即写库。以最直接的 CWE-79 为主要报告项。
