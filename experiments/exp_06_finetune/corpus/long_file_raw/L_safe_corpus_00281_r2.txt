## 编号分析

**1. 入口点枚举（全文通读）**
- 本文件不暴露 HTTP 路由；唯一对外入口是第 116 行 `module.exports = externalRequest`，即被其他模块（如 oembed、webhooks 等）调用发起出站请求。source 为调用方传入的 URL，sink 为 `got` 发起的网络请求。

**2. normalizeIPv4 / normalizeIPv6（第 10–40 行）**
- 用 WHATWG URL 解析器把十进制/八进制/十六进制/整数形式 IPv4 归一化（第 13–15 行），IPv6 同理（第 27–33 行），并用 `net.isIPv4/isIPv6` 校验，防止畸形地址绕过后续判断。

**3. isPrivateIPv4（第 44–86 行）**
- 覆盖 10/8、172.16/12、192.168/16、127/8、169.254/16、100.64/10、198.18/15、0/8、240/4 及广播地址，范围检查完整。

**4. isPrivateIp（第 88–146 行）**
- 第 91–93 行：空值 fail-closed。
- 第 95–113 行：处理 `::ffff:` 点分与十六进制两种 IPv4-mapped 形式。
- 第 115–120 行：先做 IPv4 多进制归一化再判私网，堵住 `2130706433`、`0x7f000001` 等绕过。
- 第 122–144 行：IPv6 检查含 ::1、::、fc00::/7、fe80::/10，并对归一化后的 mapped 地址二次检查。
- 第 145 行：无法识别的格式 fail-closed 返回 true。

**5. errorIfHostnameResolvesToPrivateIp（第 148–167 行）**
- 第 150–152 行：开发环境跳过（仅本地开发，非生产漏洞）。
- 第 154–157 行：允许请求自身站点 host（Ghost 自身回调场景）。
- 第 159 行：DNS 解析后用 `isPrivateIp(result.address)` 判定解析出的真实 IP，而非仅校验 hostname 字符串——有效防御了以域名伪装内网 IP 的 SSRF。

**6. errorIfInvalidUrl（第 169–179 行）**
- 校验 hostname 非空且通过 validator.isURL。

**7. disableRetries 与 hooks 配置（第 181–200 行）**
- 测试环境禁用重试防止重试绕过校验。
- 关键点：`beforeRequest`（第 197 行）在每次实际请求前执行 IP 检查；`beforeRedirect`（第 198 行）确保重定向链上每一跳都重新执行 `errorIfHostnameResolvesToPrivateIp`，即替代通道（30x 重定向到内网）也被覆盖。

**8. 数据流结论**
- source（调用方 URL）→ sink（got 请求）之间，每一跳均经过：URL 合法性校验 → DNS 解析 → 解析结果 IP 私网判定 → 不通过则 reject。黑名单式的多进制/映射形式绕过已被归一化 + fail-closed 堵死。
- 唯一理论残余是 DNS rebinding（lookup 与实际连接之间的 TOCTOU），但这属于网络层固有竞态，需要攻击者控制权威 DNS 且窗口极小，本文件代码层面无缺陷；且该设计已是 Node 生态中此类防护的标准实现。
