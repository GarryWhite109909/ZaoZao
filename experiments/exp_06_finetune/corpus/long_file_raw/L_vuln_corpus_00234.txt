## 编号分析（通读全文，逐函数枚举）

9. **第 305–339 行 `toJBossSubsystemConfig` —— 关键 sink**：
   - 第 307–308 行：`realmModel.getName()` 与 `baseUri.toString()` 拼入 XML；
   - **第 313 行：`buffer.append("    <resource>").append(clientModel.getClientId()).append("</resource>\n")`** —— `clientId` 是 source（创建客户端时由用户提供，见第 68 行 `createClient` 接收的 `rep`），全文对该值做任何 XML 转义或校验（黑名单/正则均无）；
   - 第 315–326 行：credential 的 `entry.getKey()`、`credEntry.getKey()`、`credEntry.getValue()` 同样未转义直接拼入 XML 标签名与文本（secret 通常为随机值不可控，但 key/value 在某些 authenticator 配置下部分可控）。
   - 该方法被安装适配器端点调用（如 `/admin/realms/{realm}/clients/{id}/installation/providers/keycloak-oidc-jboss-subsystem`），返回的 XML 被下载到应用服务器配置中使用。攻击者持有 manage-clients 权限即可通过恶意 clientId 注入任意 XML 元素/闭合标签，破坏下游解析（XML 注入 / 配置注入）。

10. **第二入口验证**：`toInstallationRepresentation` 走 Jackson 序列化有转义，安全；唯一未防御通道就是 `toJBossSubsystemConfig` 的手工字符串拼接，且与第 68 行 `createClient` 的用户输入构成完整 source→sink 链。
