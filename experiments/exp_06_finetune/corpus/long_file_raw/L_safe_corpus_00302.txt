**入口点枚举（全文通读）**

1. **构造/反序列化入口**：`DictPromptTemplate(template=..., template_format=...)`，第 14-16 行定义字段；第 18-21 行 `validate_template` 校验器在构造时调用 `_get_input_variables`。反序列化路径经 `is_lc_serializable`（第 63-65 行）允许 dump/load，但 load 走 pydantic 校验，同样触发该验证器。
2. **格式化入口**：`format(**kwargs)` 第 32-40 行 → `_insert_input_variables`；`aformat` 第 42-47 行只是同步包装。
3. **invoke 入口**：第 49-58 行，将 `input: dict` 展开为 kwargs 传入 format。

**数据流逐一验证**

- **source→sink 1**：用户输入 `inputs`（kwargs）→ 第 78 行 `formatter(v, **inputs)` / 第 90 行列表分支。f-string formatter 是 langchain 的安全实现（基于 string.Formatter，仅做占位符替换，不执行代码），mustache 同理。输入值只被插入为字符串值，不会被再次解析为模板，无二次注入。✅ 无注入 sink。
- **source→sink 2**：模板本身（template dict）在构造时仅被 `_get_input_variables` 解析提取变量名（第 100-117 行），不执行任何求值。✅
- **image_url/path 检查（第 80-86 行）**：仅在嵌套 dict 的 key 为 `image_url` 且含 `path` 时发 warning，但仍继续递归格式化并返回结果——这是一个“警告但不阻止”的弱防御。然而其目的本身是移除文件读取工具，实际文件读取逻辑不在本文件中；此处仅是提示性告警，且 path 值来自 template 而非直接执行 IO。本文件内不存在任何文件/网络 sink，故不构成本文件内的可利用漏洞（属于纵深防御层面的设计取舍）。
- **递归结构（第 100-117、74-97 行）**：深度嵌套可致 RecursionError（DoS），但需攻击者能控制 template 结构，且 Python 默认递归限制会抛异常而非崩溃进程，属低风险健壮性问题而非安全漏洞。
- **第二通道检查**：`_serialized`（第 61-62 行）用 `dumpd` 序列化，无敏感信息外泄面；`pretty_repr` 直接 raise NotImplementedError，无 HTML 注入面。
- **keys 不解析变量**：docstring 明确 key 不参与格式化，避免了对 dict key 的意外注入。

**结论**：全文无 eval/exec/文件 IO/网络请求等危险 sink；formatter 为安全实现；唯一弱点是 image_url/path 仅告警不阻断，但本文件内无可达的危害 sink，不构成实际漏洞。
