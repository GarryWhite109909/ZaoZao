## 编号分析

1. **第 60–200 行（属性定义）**：所有安全策略均为 public 属性，默认值宽松（`static_classes = []` 允许全部静态类、`allow_constants = true`、`allow_super_globals = true`、`streams = ['file']`）。这是 Smarty 的设计取舍：Security 类本身不接收外部输入，配置由应用开发者设定，故默认宽松不算本文件内的漏洞。

2. **isTrustedStaticClass / isTrustedStaticClassAccess（约 210–260 行）**：输入 `$class_name` 来自模板编译期，模板本身须已通过 `secure_dir` 校验才能加载；且 `$trusted_static_methods[$class_name]` 为空数组时回退到类级白名单，逻辑自洽。无攻击者可控 source 直达敏感 sink。

3. **isTrustedTag / isTrustedModifier / isTrustedSpecialSmartyVar / isTrustedConstant（约 270–370 行）**：纯黑/白名单比对，输入为编译器解析出的标签名，非 HTTP 输入。`in_array` 未用严格比较，但两侧均为字符串字面量场景，无类型混淆利用面。

4. **isTrustedStream（约 380 行）**：`in_array($stream_name, $this->streams)`，stream 名来自模板资源字符串；默认仅允许 `file`，开发者可收紧。松散比较在此无实际绕过（两边均为字符串）。

5. **isTrustedResourceDir / _checkDir（约 410–500 行，核心路径校验）**：
   - `_checkDir` 先用 `@realpath()` 解析符号链接（注释明确说明防 CWE-22 symlink 穿越），文件不存在时回退到 `_realpath()` 字符串归一化——回退分支针对尚未写入的 config/cache 路径，属于已知权衡；
   - 对可信目录同样做 realpath 归一化后再比对，防止 `/var -> /private/var` 类合法符号链接被误杀；
   - `preg_match('#[\\\\/][.][.][\\\\/]#', ...)` 仅作快速失败检查，真正的防护是逐级向上匹配 `$trusted` 集合，即使该正则被绕过也不会放行越界路径；
   - 结论：source（模板/配置文件路径）→ sink（文件读取）的数据流防御有效。

6. **isTrustedUri（约 505–525 行）**：用 `$trusted_uri` 中的 PCRE 匹配 `scheme://host`。正则由开发者提供而非用户输入；`parse_url` 解析后丢弃 userinfo/port/path，缩小了匹配面。若开发者写了过宽的正则（如 `#^http#`）会失效，但那是配置错误，非本代码缺陷。

7. **enableSecurity（约 545–570 行）**：`$security_class` 若为字符串会实例化任意类名，但有双重约束：必须已存在且必须是 `Security` 的子类，构造函数签名固定为 `(Smarty $smarty)`，无法注入任意类实现 RCE。

8. **startTemplate/endTemplate/registerCallBacks（约 580–615 行）**：嵌套计数防 DoS，`_current_template_nesting` 为 private 且仅在渲染回调中增减，无并发/溢出问题（PHP int 范围内）。

9. **第二入口核查**：全文无直接读取 `$_GET/$_POST/$_COOKIE/$_FILES/php://input` 或环境变量的代码；所有参数均来自 Smarty 编译器内部或应用层显式配置。缓存属性 `_resource_dir/_template_dir/_config_dir` 的失效逻辑（`_updateResourceDir`）在目录变更时正确清理旧前缀。
