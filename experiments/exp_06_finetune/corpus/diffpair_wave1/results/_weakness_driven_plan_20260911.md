## 三、判断：16 块冲突**不能剔除**——要把 (b) 改成 (c)

**我上一轮建议的 (b) 整块剔除，在这个角度下是错的。** 理由：这 16 块承载的**正是模型不会的题**；剔除等于把最难的题从卷子里拿掉，与补弱点背道而驰。逐条对弱点族后更明显：

| 缺陷 | 块 | 命中哪个弱点族 |
|---|---|---|
| **★漏报 5** | 00018(CWE-1336 SSTI) | W4 sink 词表缺口（模板引擎） |
| | 00132(**CWE-601**) | **W6 工具层全盲 601(0/10)** + W1 长尾 |
| | 00155(CWE-400) | W1 长尾 |
| | 00160 / 00162(**CWE-863 授权**) | **W3 逻辑类盲区**（与 00013/00036/00100 同族） |
| **误报 7** | 00007×2、00037、00097、00098、00117、00177 | **W2 防御有效性判断**（真值无洞而模型报洞） |
| **编号错 4** | 00008(352→**346**)、00019(98→1336)、00094(295→**441**)、00145(400→**409**) | **W1 类型归因塌缩**的微观实例 |

**所以正确处置是 (c)：带真值重跑，拿到"结论对 + 推理也自洽"的 16 块。**
不是 (a) 只改结论行 —— 那会得到"结论对、防御/载荷/锚句仍在论证旧结论"的自相矛盾样本，等于教模型用错误推理蒙对答案。

已产出任务包：`results/_redistill_pack_20260911.jsonl`（16 条，15 个 id），每条含
`truth_has_vulnerability / truth_cwe / truth_note / model_answer / code_A / code_B / patch_adds`。
按弱点优先级排序：**P1 漏报 5 条 → P2 误报 7 条 → P3 编号错 4 条**。

## 四、判断：20 条"判无洞"不是垃圾，是 **FP 抑制燃料**——但必须带防御证据

模型把 20 个包的 A 版判成无洞。它们从"正样本"变成负样本。从补弱点看这**恰好补 W2**：

- 其中 **15 条模型已经判对**（一致：都是无洞）→ 直接可用，教"这是安全的"。
- **5 条模型判错**（00037、00097、00098、00117、00177）→ 必须修正后才可用，否则教模型误报。

但有一处必须补：**负样本若只说"无洞"，学不到"为什么安全"**。他的 FP 第一根因就是"防御未识别"（loopback-only XFF 设计、ObjectInputFilter 白名单、prepare+pexecute 参数化、ldap.EscapeFilter、ORM 参数化…被系统性无视）。
→ **这 20 条的目标输出必须要求"点名防御所在行号 + 为什么该防御有效"**，否则等于白给。
